# 「我的字幕流」启动器重构规划

制定日期：2026-09-14  
代码基线：`my-feature` / `49375c6`  
状态：仅规划，尚未实施启动器改动。

此前编辑器 ASR／素材库 D–G 已提交并推送至用户仓库。本文件规划启动器的后续改造，不表示其中的新功能已实现，也不修改 `main` 或上游仓库。

## 1. 重构目标与范围

把启动器做成「进入编辑器、准备工程、管理运行环境」的横向桌面工作台。默认进入「启动编辑器」，让用户第一次打开就能进入空白工程；需要提前批处理时再使用「预制工程」。

启动器与编辑器职责：

| 位置 | 负责的工作 |
| --- | --- |
| 启动器 | 最近工程、明确的空白启动、离线文件处理计划、批量预制、运行环境、纯文件工具、使用指南 |
| 编辑器 | 波形／时间线交互、整段／选区／贴片 ASR、字幕翻译、TTS、素材编辑与插入、音频贴片、保存恢复和成品导出 |
| 共用后端 | 服务配置、处理配方、素材契约、媒体解析、波形缓存、工程读写与来源校验 |

保留现有 Python + pywebview 启动链路与本机编辑器服务，前端继续使用 `web/launcher/`。本轮不要求迁入 React、Electron 或另一个桌面壳，避免同时改动布局、处理逻辑和打包体系。

### 已明确的需求

- 横向窗口；左侧导航固定为「启动编辑器／预制工程／实用工具／使用指南／更多设置」。
- 中文名「我的字幕流」，英文名 **Moyor's Subtitle Workflow**；MSW 继续作为简称。
- 暗色使用中性黑色层次与低调紫色，移除现有蓝灰主调。
- 最近工程使用卡片；可选择工程、浏览工程文件或空白启动。
- 预制页右侧选择模块，左侧显示按顺序编号的可折叠配置区。
- 默认勾选「选择媒体」「波形生成」。
- 原工具箱中改变工程的后处理迁入预制页。
- 用户已确认：**OCR 保留现有字幕去重功能，不新增画面硬字幕擦除。**
- 用户已确认：**TTS、音频素材导入列入后续扩展阶段，先完成新布局与现有处理模块整合。**
- 用户已确认：**LOGO 沿用水母轮廓，暗色反白、亮色黑色，不加外框。**

下文新增的交互细节、默认值和分期均为实施建议；用户明确确认的方向与其他建议分开记录。

| 编辑器已有恢复记录，但启动器没有最近工程卡片接口 | 复用应用数据根目录和工程身份；新增轻量最近工程索引，不把恢复快照直接当最近工程 |

| `website/` 有旧 MAW 说明残留；部署工作流配置了本仓库 Pages 地址 | 指南入口集中配置为 MSW 地址，文档同步时检查残留品牌与上游链接 |

## 3. 视觉与布局方案

### 3.1 整体气质

采用横向桌面应用的稳定布局：窄侧栏、清楚的页面标题、宽松但不浪费空间的卡片、固定主操作区。借鉴绘世类启动器的导航与工作台观感，具体排版和图形沿用 MSW 的水母品牌，不复制其素材或功能结构。

- 去掉主模块标题中的彩色数字 emoji，改用小型 `01 / 02 / 03` 序号标记。
- 图标统一为本地 SVG 线条风格，常规 18–20px、线宽约 1.6px；不混用 emoji、实心彩色图标和不同粗细的线图标。
- 不使用大幅宣传 Banner、强渐变发光、通篇紫色背景或持续动画。
- 主要按钮有明确填充，次要按钮使用低对比底色，危险操作仅在对应情境显示。
- 每张卡片只保留一个主标题、一段必要信息和一组操作，不在首页堆叠引擎说明。

### 3.2 尺寸与响应式

建议初始窗口 **1200×780**，启动时按当前屏幕工作区收敛；普通桌面目标最小可用内容约 **960×640**。高 DPI、任务栏和小屏导致可用区域更小时，必须允许紧凑布局，不能让最小窗口尺寸把按钮顶到屏幕外。

| 区域 | 建议尺寸／行为 |
| --- | --- |
| 顶部品牌栏 | 约 76–84px，高度稳定，显示双语品牌和独立版本号 |
| 左导航 | 默认 184–196px；紧凑状态 64px 图标栏并有悬浮名称 |
| 内容页边距 | 默认 24px；紧凑时 16px |
| 预制模块选择栏 | 默认 240–260px；窄宽度改为“处理模块”按钮打开抽屉 |
| 底部操作栏 | 约 60–68px，固定于内容页底部，不覆盖最后一项表单 |
| 卡片 | 圆角 10–12px，细边框；间距以 8/12/16/24px 为主 |
| 表单 | 控件高 34–36px；常规字段两列，长路径、提示词与替换规则整行 |

每个导航页记忆自身滚动位置。预制配置区主滚动，右栏可独立滚动；模块卡片内部默认不再套长滚动区。日志展开后可滚动，但不改变底部主按钮的位置。

### 3.3 品牌排版

- 原生窗口标题：`我的字幕流 · Moyor's Subtitle Workflow`。
- 应用页头：水母标志 36–40px，无额外方框；右侧中文名 22–24px、字重 600，英文名 12–13px、次级颜色，独立一行。
- 版本号放页头右侧或侧栏底部，以 `v…` 小标签显示，避免混入英文品牌长句。
- 中英界面都保留两种正式名称；页面标题和操作文字跟随界面语言。
- 当前 LOGO 轮廓不重绘。已确认暗色反白、亮色黑色、无外框，并跟随应用有效主题；不只跟随操作系统主题。
- 更换显示名称不重命名 `.mosp`、工程 schema、旧环境变量或存储目录，避免品牌修改触发数据迁移。

### 3.4 主题令牌初稿

## 4. 五个导航页的详细设计

### 4.1 启动编辑器

默认首页，上方只放页面标题、简短说明与“打开工程文件”；主体为最近工程卡片，下方为固定启动区。

**卡片与选择**

- 卡片展示工程名、父文件夹简称、最近打开时间、主／副字幕与音频素材数量；未知信息显示“读取中”，不伪造统计。
- 可选封面只使用已有本机缓存，不为了展示首页解码整段视频。无封面时使用简洁的水母／工程图形占位。
- 单击选择，选区细框与小勾提示；再次点击或“取消选择”可回到无选择。双击直接打开，键盘 Enter 执行当前主按钮。
- 首次进入首页默认无选择，不能因为自动选中最近工程改变“启动空白编辑器”的含义。
- 顶部提供搜索；最近列表默认展示 12 项，可加载更多。索引建议最多 50 项，支持固定常用工程。
- 菜单提供固定／取消固定、打开所在文件夹、从最近记录移除。移除只删记录，不删工程文件。
- 重名工程通过目录区分；失效路径显示“文件已移动或不存在”，提供重新定位，不默默打开其他同名工程。

**底部操作**

- 无选择：主按钮“启动空白编辑器”。
- 有选择：主按钮“打开所选工程”，旁边保留“空白启动”。
- “打开工程文件”调用系统选择器，优先 `.mosp`，兼容旧 `.json`；SRT 导入属于编辑器／预制输入，不伪装成已有完整工程。
- “恢复未保存内容”是独立入口，跳转编辑器恢复记录，不把恢复副本当作磁盘工程。
- 服务已运行时显示真实状态；同一工程可“返回编辑器”。不同工程或明确空白启动时走会话切换流程。

**会话与最近记录**

建议默认复用一个受管理的编辑器会话，但必须经过编辑器的保存／放弃／取消与运行中任务提示。旧服务没有必要的状态协议时，不能直接结束它；提供返回现有会话，并在必要时显式启动独立会话。

最近记录由后端维护：启动器打开、编辑器实际打开／保存／另存为成功均更新同一索引。记录 `project_id`、规范化路径、显示名、最近打开时间和可选统计缓存。保存事件更新信息，不把每次自动保存当一次“最近打开”。恢复记录仅用于首次迁移辅助，不替代该索引。

### 4.2 预制工程

目标是由可理解的处理方案生成一个可直接进入当前编辑器的工程。

**输入方式**

1. **媒体预制**：输入视频／音频，支持单文件与批量；默认只启用选择媒体、波形生成。因此默认结果可以是合法的零字幕工程。
2. **已有字幕／工程再处理**：输入 `.mosp/.json/.srt`，直接使用现有字幕，不要求先重新 ASR。媒体可从工程解析，也可补充指定；不需要音视频的文字处理不强制要求媒体。

界面主称呼保留“选择媒体”；进入已有工程模式时首张卡片改为“输入工程／字幕”，避免要求用户把工程文件放进媒体选择器。输入卡片属于必需结构：媒体预制时默认勾选并固定启用，不能取消成无法定义输入的处理计划。

**模块选择与折叠**

- 勾选模块：左侧按依赖顺序插入配置区，首次启用展开并滚动到可见位置。
- 取消模块：从本次计划移除，但保留草稿设置。取消勾选不清空路径、提示词和替换规则。
- 折叠只改变显示，不改变启用状态。标题下保留一行摘要，例如“Qwen · 中文 · 说话人颜色”。
- 序号按当前可见顺序连续排列，模块身份用稳定 ID，不以序号持久化。
- 状态区分“未配置／就绪／条件不满足／运行中／完成／失败／已取消”。不能只用一种灰色表达未勾选和不可用。
- 点击不可用模块时显示具体缺少的条件；可以先编辑模块，开始执行前集中校验。
- 首版不提供任意拖拽处理顺序。运行顺序由契约决定，并显示在“本次处理顺序”摘要中。
- 切页、折叠、主题／语言切换保留表单草稿；保存方案是显式操作，不等于发起任务。

**运行与输出**

- 主产物为 `.mosp`；SRT 是可选附加导出，不再让首页围绕“SRT 输出路径”组织。
- “输出设置”固定保留：输出目录、文件名预览、同名处理、可选 SRT、保留中间结果、媒体收集方式、完成后操作。
- 新输出默认创建派生文件，命名预览沿用现有规则并避免覆盖。明确选择覆盖旧文件才进入既有覆盖确认与备份流程。
- “开始预制”和“预制并打开编辑器”共用计划；后者仅在最终工程成功发布后打开。批量完成默认展示结果卡片，不连续弹开多个浏览器窗口。
- 整批开始前显示文件数、选中模块、将调用的服务、预计处理量（时长／字符数）；没有可信价格数据时不编造费用。
- 处理中的表单以提交快照为准；当前任务不被后续改表单影响。停止按钮取消本次任务，切换导航不会取消。
- 输出区分别列出成功、失败和部分完成，不把中间字幕标成最终工程；成功项目可逐一打开。

### 4.3 实用工具

采用小工具卡片网格，点击后在当前页展开详情或进入工具子页。每项展示“输入类型 → 输出类型”，没有后台行为的宣传说明不常驻。

| 原功能 | 新位置 | 理由 |
| --- | --- | --- |
| 提取音频 | 实用工具，默认保留 | 输出独立音频，不修改工程 |
| 压制字幕 | 实用工具，保留“将现有 SRT 压入视频”的文件级入口 | 生成独立视频副本；包含当前配音轨／贴片的完整合成仍由编辑器导出 |
| 媒体重组／FFconcat | 实用工具的高级项 | 仅按已有清单生成独立媒体，不自动回写工程或重映射时间线 |
| 生成波形 | 预制工程 → 波形生成 | 当前功能会生成空字幕工程，不属于纯工具 |
| 文稿匹配／固定处理／LLM／OCR／翻译 | 预制工程对应模块 | 都改变字幕产物或工程内容 |
| 口播对齐 | 预制工程的“高级：交互式口播对齐”入口 | 它涉及时间线与工程；现有交互页面不能伪装成无人值守的一步 |
| FFmpeg 检测与路径设置、OCR／本地模型环境 | 更多设置 → 环境配置 | 属于运行环境，不是生产文件工具 |

口播对齐首版保留现有交互链路，从预制输入显式打开，完成后由用户选择生成工程接回流程。无人值守批次暂不把交互步骤当可自动执行模块；后续如需自动化另行完善输入输出契约。

可增加“媒体信息”轻量工具，复用现有探测显示时长、音轨、编码、帧率和尺寸；无写入副作用，优先级低于现有工具迁移。不增加与当前需求无关的下载站、插件市场或训练平台。

### 4.4 使用指南

- 三张简短入门卡：“直接进编辑器”“提前预制工程”“纯配音与素材”。每张 3–4 步，提供对应页的导航按钮。
- 明确说明启动器是可选的预处理入口，编辑器已能直接导入媒体、生成波形、ASR、翻译和 TTS。
- 区分本机编辑器与静态／便携 HTML 的处理能力；在线网页不冒充本机后台服务。
- 常见问题采用折叠条目：缺少 FFmpeg、API 配置、媒体丢失、工程与 `.assets` 搬移、波形缓存、任务取消和未知提交状态。
- 外部链接集中为“项目仓库／在线文档／版本记录／反馈问题”；离线时仍可读内置短指南。
- 当前部署配置地址见第 12 节。实施时检查入口和文档同步结果，不沿用旧 MAW 品牌说明。

| --- | --- | --- | --- | --- |

### 依赖处理规则

1. 不勾选 ASR 仍可由媒体生成零字幕工程；不能因为后处理需要字幕而偷偷开启收费 ASR。
2. 已有工程模式可关闭波形，直接做文字处理。纯字幕素材／纯 TTS 工程缺少媒体不算非法。
3. 不满足依赖时在模块和开始按钮附近列出原因，例如“翻译需要字幕，请启用识别或导入已有字幕”。不要静默跳过用户选中的步骤。
4. 无音轨视频不能生成真实波形或执行 ASR；用户可明确取消这些模块后制作工程。装饰波浪线只是编辑器显示回退，不能标记成“波形生成成功”。
5. 首版文字主链顺序沿用现有固定顺序；波形是依赖源媒体的分析分支，不应在 ASR 子命令和预制器里各生成一遍。
6. 相互依赖的设置变动只发出错误提示，不自动取消用户勾选、清空参数或调用服务。

```mermaid
flowchart LR
    A[媒体或已有工程] --> B[输入校验]
    B --> W[可选波形与频谱]
    B --> C[已有字幕或可选 ASR]
    C --> D[文稿匹配]
    D --> E[固定处理]
    E --> F[LLM 校对]
    F --> G[重新断句]
    G --> H[OCR 字幕去重]
    H --> I[翻译与目标轨]
    I --> J[工程发布与素材收集]
    W --> J
    J --> K[结果卡片 / 打开编辑器]
```

图中未勾选步骤直接通过；日志记录贯穿所有步骤。首版允许顺序执行波形分支，性能优化另行验证，不为了并行引入重复提取或取消竞态。

## 6. 与当前编辑器的兼容要求

这是核心验收项，不能把旧启动器表单搬成卡片后就视为完成。

### 6.1 工程与素材契约

- 正确保留 `msw.assets`、`audio_clips`、`subtitle_assets`、`asset_batches`；字幕素材和音频素材不能相互混用。
- 保留主副轨、完整绑定、颜色／组引用、ASR 应用记录与复核信息、导出／混音相关设置，以及支持的其他工程扩展字段。
- 后处理改变主字幕时，根据操作修复或解除失效绑定；保留副字幕与音频，标记需要复核。不得因旧后处理只理解 `segments` 就抹掉整个 MSW 命名空间。
- 字幕重新断句、删改或翻译后，音频贴片不自动改位置、不自动重新合成；对应来源变化给出复核信息。
- 正常派生工程复制必要素材并分配独立工程身份；素材 ID 与引用保持一致，运行中任务不迁入新工程。
- 使用既有素材校验和 `write_derived_project`／持久化逻辑；迁移后必须验证原路径、相对路径、多 `.assets` 目录和缺失引用。
- 波形缓存仍为可重建数据，遵循现有 `.quapeaks/.mopeaks` 与兼容读取规则，不新增与编辑器冲突的缓存目录或格式。

### 6.2 翻译目标

建议默认“保留主字幕，翻译为副字幕”，与编辑器当前双列／双排和独立编辑能力一致。有副轨时明确选择目标轨或新建，不隐式覆盖用户已有副字幕。

旧“原文与译文合为同一字幕块”保留为高级导出兼容选项，明确说明会得到单轨双语内容；不能把旧 `mergeBilingual` 路径直接当成新的多重字幕工程默认行为。对既有多轨工程的处理需显式限定目标轨。

### 6.3 环境和调用设置

启动器和编辑器使用相同服务连接配置与能力查询入口。首轮按已有服务能力迁移，不随布局重构扩充 ASR 供应商；本地实验性引擎保留能力提示。

区分三层：全局连接 → 新建方案默认值 → 本次处理快照。加载或保存方案不会修改 API Key；修改全局模型默认值不重写当前已提交任务。

### 6.4 并发与文件保护

- 预制读取的是磁盘工程快照，不是浏览器里尚未保存的文字；如果该工程已在编辑器打开，运行前指出使用的版本。
- 默认写派生文件。覆盖前校验文件指纹／版本，防止后台预制覆盖编辑器刚保存的内容。
- 打开预制结果是独立的显式动作，不自动替换当前编辑器时间线。
- 关闭启动器时不误杀仍在使用的编辑器服务。仅在明确停止且确认无未保存编辑／运行任务时结束受管理服务；不关闭其他进程启动的服务。

## 7. 计划、任务与批量处理的技术设计

### 7.1 模块注册表

建议新增小型模块注册表而不是继续在 `launcher.js` 中按 DOM ID 堆条件。每项包含：稳定 ID、分组、标题、依赖、默认启用、配置 schema、摘要生成、前端校验、后端处理适配器、输出类型、能力条件。

UI 根据同一注册表生成右侧选项和左侧配置壳；具体表单仍由各模块维护。后端重复做必要校验，不能把前端“就绪”当作可信输入。

建议新增文件名（实施时可合并小模块）：

- `web/launcher/navigation.js`：页面切换和滚动位置。
- `web/launcher/project-home.js`：最近工程和启动意图。
- `web/launcher/workflow.js`：选择、顺序、草稿、摘要与提交。
- `web/launcher/modules.js`：模块目录及能力约束。
- `maw/launcher_projects.py`：最近索引与编辑器会话桥接。
- `maw/launcher_workflow.py`：版本化方案和执行适配。

这些是拟新增边界，不要求机械地生成所有文件。通过现有桥接保持原 API 兼容，再逐项迁移调用方。

### 7.2 可保存处理方案

建议引入版本化方案，逻辑结构包含 `version / inputMode / modules / moduleOptions / outputOptions / completionAction`。保存稳定 ID，不保存模块标题或左侧序号。

- 初始内置方案：仅准备媒体、识别工程、识别并翻译、已有字幕整理。
- 用户选择“识别工程”才明确启用 ASR，不将模板选择变成即时运行。
- 通用方案不默认保存具体输入文件列表；保存路径为本机便捷选项，导出方案时默认剔除个人输入路径和凭据。
- 未识别的新版字段／模块提示不兼容，不自动降级并丢弃配置。
- 迁移旧配置时保留旧 ASR 和后处理启用状态，用户第一次创建全新方案才使用“媒体＋波形”的新默认；不能让升级自动新增服务调用。

### 7.3 执行状态与恢复

每次提交冻结输入文件版本、音轨、模块参数和输出决定。状态建议覆盖准备、运行、取消中、完成、部分完成、失败、已取消、状态待确认。

- 每个文件有模块级状态，保留已完成中间结果及最终产物路径。
- 失败重试从失败步骤继续，前置输入或方案改变后必须重新校验，不复用不相容的旧结果。
- 复用已有取消事件、日志和请求标识；云端响应未知时显示确认／检查入口，不自动重新付费执行。
- 重开启动器可以读取任务结果与中断状态；不承诺本来不支持的断点续传能力，不能把重启后重新运行叫“继续原任务”。
- 原 LLM 流式输出保留在日志详情，默认先展示可读状态；大段模型 JSON 和思考输出不常驻主配置区。

### 7.4 批量模式边界

- 每个文件独立产出、独立失败状态；批量共用方案，队列可增删和排序，运行时冻结。
- 首版保留现有串行处理，避免供应商限流和任务管理同时重写。
- 多音轨文件分别记录选择；不存在的音轨不默认替换为另一个音轨。
- 文稿匹配需要逐文件映射。首轮沿用能力限制并在勾选／预检时明确提示；后续可加“同名匹配＋人工核对”映射界面，未匹配项列出原因，不静默跳过。
- 文件名冲突、同名不同目录、部分媒体不可用和输出目录权限在预检中单独报告。

## 10. 风险与控制

| 风险 | 控制办法 |
| --- | --- |
| 只换皮、入口仍然割裂 | 先列旧功能归属和启动行为，再逐阶段替换；E 阶段单独验证统一执行 |
| 旧后处理损坏新编辑器工程 | 使用含主副字幕、贴片与两类素材的公共夹具，逐模块验证保留与失效处理 |
| 空白启动实际恢复旧工程 | 显式启动模式及服务目标身份验收 |
| 打开新工程杀掉正在编辑的服务 | 会话握手与保存／取消流程；不根据端口可访问就直接停止进程 |
| 模块很多又变成长表单 | 右侧分类、左侧仅显示启用项、折叠摘要、高级参数逐层展开 |
| 紫色过多或黑色界面层级不清 | 中性灰作结构、紫色仅作交互提示；暗亮原型与真实屏幕检查 |
| “生成波形”仍重复执行 | 由计划统一决定分析任务，子命令禁用重复分析并复用有效缓存 |
| 方案／设置相互覆盖 | 全局连接、本次配方、默认值分层；字段级保存与版本校验 |
| 批处理重复付费 | 不可变请求身份、未知状态确认、失败步骤显式重试 |
| 双语合一移除副轨 | 独立副轨为默认，单轨双语为明确兼容输出 |
| 首轮范围过大 | TTS／音频导入后置 H；不把目录双向同步、视频擦字、插件平台顺带加入 |
