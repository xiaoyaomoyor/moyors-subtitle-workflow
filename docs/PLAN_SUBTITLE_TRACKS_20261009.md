# MSWE 字幕轨道与重叠编辑重设计

日期：2026-10-09。核查基线：`my-feature / 4fb9d9d`。

状态：阶段 1–4 已实施；阶段 5 的处理与输出闭环尚未实施。阶段 3–4 仅通过 `?subtitle-tracks=1` 开发入口启用，默认流程仍为 v2。验证见[拖动修复账本](TEST_FEEDBACK_SUBTITLE_DRAG_20261009.md)、[固定轨道迁移](TEST_FEEDBACK_SUBTITLE_TRACKS_20261009.md)、[固定轨道编辑](TEST_FEEDBACK_SUBTITLE_TRACK_EDIT_20261009.md)及[注释定位与稳定排布](TEST_FEEDBACK_SUBTITLE_TRACK_PRESENTATION_20261009.md)。用户已明确：需要同时处理多人重叠对白和画面文字／注释。本文作为后续实施依据，取代上一版方案中“编辑层完全由重叠自动计算”的设计方向；既有实现仍以当前代码为准。

## 1. 核查结果和设计目标

当前开发版已将旧 V叠内容迁入统一字幕模型，普通字幕可以重叠，并参与翻译、配音、样式与导出。问题不只是名称或面板布局：编辑中的轨道位置、重叠判定和视频中的摆放仍缺少足够明确、稳定的规则。

已在独立 Chromium 工程复现的三个问题：

| 现象 | 代码原因 | 重设计必须满足的条件 |
| --- | --- | --- |
| 2–5 秒字幕从右侧缩短后，整体变为约 0.91–1.01 秒 | `applyLayerDrag` 对单侧调整同时夹逼起点和终点 | 调整一侧时固定另一侧；达到最短时长即停止 |
| 想贴齐 4 秒的相邻字幕，最后停在 3.62 秒 | 新布局未使用原有磁吸；禁止重叠时直接拒绝最后一次移动 | 吸附和碰撞边界统一求解，允许准确贴齐 |
| 跨行拖动经过行间空白，结束时间从约 17 秒变成 7 秒 | 未命中波形行时回退到最初按下那一行 | 拖动持续使用明确的当前时间行，经过行间空白不会退回起始行 |

相关实现：`web/waveform.js` 的 `applyLayerDrag`、`moveCueDrag`、`timeMsAtPoint`；`web/msw-subtitle-layers.js` 的自动分层；`web/msw-subtitle-presentation.js` 的画面排布。当前画面排布还会为未绑定、时间相交的主副字幕推导共同显示组，应在新机制中取消这种无明确对应关系的推导。

新的核心：**固定字幕轨道、统一字幕块、明确主副绑定、工程样式统一渲染。** 编辑时字幕属于哪条轨道是稳定信息；视频中的位置由工程样式决定。两者不能通过拖动或自动重排相互猜测。

## 2. 用户面对的内容结构

每条字幕轨道包含主字幕，以及按需显示的副字幕。主／副继续表示原文与译文关系，不表示第几个说话人。轨道不是说话人身份，也不是视频画面的绝对纵坐标。

默认只显示“对白 1”。“添加轨道”提供两个起始模板：

- **对白**：添加“对白 2”等轨道，用于同时说话、插话或需要独立处理的另一组台词。默认继承工程对白样式，主副作为绑定对排布。
- **画面文字**：添加“画面文字”等轨道，用于招牌翻译、说明和注释。默认上方居中，可在播放器中调整位置，也能有自己的译文。

二者使用相同的字幕模型、选择、编辑和处理能力。模板只决定默认名称、样式和批量处理范围，不恢复一个操作能力受限的特殊 V叠类型。

示意：

```text
波形与时间刻度
对白 1       主   [第一句────────] [第二句────]
             副   [对应译文──────] [对应译文──]
对白 2       主          [插话────────]
             副          [插话译文────]
画面文字     主      [招牌翻译────────────────]
```

- 首版不做通用剪辑轨道总线或任意语言管理；保留当前主副语言选择体系。
- 没有副字幕内容时，副行默认不占空间；需要创建译文时可以显式展开。
- 轨道名称可修改。轨道顺序和折叠状态稳定，拖动时不自动增删轨道或改变行高。
- 折叠只压缩编辑界面，不禁用内容。轨道启用状态作用于预览和导出；锁定只限制编辑，仍参与预览和导出。两种状态使用不同图标和说明。
- 轨道数不沿用音频贴片的三层限制；空轨道由明确操作清理，不能在一次拖动后消失。

## 3. 波形和拖动操作

### 3.1 固定轨道的时间规则

- 同一轨道的同一主／副行不放重叠块；不同轨道可以同时出现。主副之间的时间相交是双语的正常情况。
- 普通移动和调整长度始终留在当前轨道，不通过轻微纵向移动换轨。多行波形中向上一行／下一行拖动仍表示前后时间，而不是更换字幕归属。
- 需要换轨时使用右键“移到轨道…”，直接列出已有目标，并提供“新建对白轨道”“新建画面文字轨道”。移动到目标轨道默认保留时间和文字；目标空间冲突时就地说明，并提供新建轨道，不静默挤压或修改他人内容。
- 首版不同时引入额外拖动手柄和新修饰键。后续如果增加专门换轨拖动，应使用独立命中区，并与跨时间行拖动严格区分。
- 取消全局“允许字幕重叠”开关的常用入口。重叠由多轨自然表达，同轨保持清楚的编辑规则。

### 3.2 边界、碰撞和吸附

| 操作 | 规则 |
| --- | --- |
| 移动整块 | 保持时长；仅改变所选块及应联动的绑定对象；遇到同轨障碍准确停在边界 |
| 拖左边界 | 固定终点，修改起点；不能越过最短时长或同轨前一条的边界 |
| 拖右边界 | 固定起点，修改终点；不能越过最短时长或同轨后一条的边界 |
| 拖共享边界 | 仅当同轨同一主／副行两端精确相接且共同高亮时，联动改变两侧；保留独立调整入口 |
| 多选移动 | 先求整个操作集合可接受的位移，再一次应用；不让不同块各自被夹逼而散开 |
| 进入行间空白 | 延续最近有效时间行；切换时间行必须有明确进入事件；不回退到起始行 |
| 超出波形区域 | 保持最后有效位置或按明确的边缘滚动继续；不会因浮窗、轨道头或空白区域而跳位 |
| 取消／撤销 | Esc 撤回本次手势，完成一次操作只产生一条撤销记录 |

波形工具栏增加一个主题色磁铁图标，默认启用吸附；关闭即可微调到任意合法位置。吸附目标是播放头、当前显示字幕的边缘和音频贴片边缘，排除整个拖动集合及其绑定跟随对象，不能吸到自己的旧位置。使用一致的屏幕距离阈值，并只对真正移动的边缘计算。

主副绑定或多选集合任一成员达到合法范围边界时，整个联动操作停在共同合法位置，使用局部提示说明限制来自哪条字幕；不靠反复气泡反馈，也不在先修改后失败时遗留半组数据。

现有 V／R、B／Ctrl+B／Shift+B、C／Ctrl+Shift+C、Ctrl+C、Shift 多选、Ctrl+Shift 时间选区等手势保持。Alt 的独立调整／禁用语义不被挪作吸附开关。键盘调整与鼠标使用同一套约束求解；时间按工程毫秒／帧基准统一量化，避免两条实现路径结果不同。

## 4. 主副绑定、切分和合并

- 绑定继续依靠明确 ID；时间相近、视觉靠近、处于同轨都不意味着绑定。
- 绑定对归属同一字幕轨道；显式换轨时默认两者一起迁移，保留各自时间偏移、状态和来源。只移动其中一侧到其他轨道属于明确的解绑操作，不能作为普通换轨的隐含副作用。
- 保留已确认的时间联动习惯：调整主字幕带动绑定副字幕；调整副字幕可独立改变时间偏移并保留绑定。新的轨道归属规则不把副字幕时间重新强制拉回主字幕。
- 普通切分仍进入字幕编辑器内嵌确认；快速切分与单切并解绑保留现有行为。切分产生的前后两组继承原轨道和样式。
- C 累加状态合并、Ctrl+Shift+C 共有状态合并保持。合并在同一轨道同一角色内执行，并联动明确绑定的另一半；跨轨多选不隐式合并成一条。
- 锁定成员参与联动操作时整次操作不提交，并说明目标；后台结果不能绕过锁定覆盖内容。

## 5. 字幕列表和字幕编辑器

- 列表默认保留时间顺序；添加紧凑范围选择“全部轨道／对白 1／对白 2／画面文字”。使用名称，不用颜色暗示归属。
- 主副继续在同一张绑定卡片中呈现；不同说话内容即使同一时刻也保持独立卡片。
- 字幕编辑器顶部显示当前轨道与主／副角色；轨道变化通过明确入口执行，不随播放命中变化。
- 播放头命中的多条内容可以同时高亮；正在编辑的对象和列表滚动锚点保持稳定，不在重叠内容之间抢焦点。
- 禁用块仍可见且淡化，沿用现有波形显示偏好；选区色、播放头色、标记色分别表达对应状态，不新增“叠加专用颜色”。
- 轨道管理放在波形轨道头及其菜单，文字、绑定、切分与合并在既有编辑器和菜单处理。普通操作不再打开专门的叠加字幕弹窗。

## 6. 画面位置和工程样式

唯一的样式入口仍是媒体播放器设置中的“字幕样式”。沿用已有主／副切换和通用／进阶／动画折叠分类，增加紧凑的编辑对象选择“工程默认／对白 1／对白 2／画面文字”。

- 默认对白轨继承工程样式；另一条对白轨可继续继承或选预设，无需复制整套参数。
- 主副顺序、主副间距及交换主副样式保持现有含义；画面中的主副上下顺序不改变时间线内容角色。
- 同时显示的对白按轨道顺序成组排布，默认轨道靠下，附加对白依次向上。轨道顺序是稳定优先次序，不依赖当前选中对象。
- 自动排布只在对白的画面区域中工作，按真实字体、换行和描边测量占位。每条显示中的字幕组保持位置稳定；不能因另一条开始／结束或无关长句改变整个工程的间距。
- 为保持稳定，按本条显示区间实际会相交的内容预计算排布，不能用全工程某一条最长字幕的高度作为所有时间的间距。对长时间连续重叠和密集对话单独验证，防止保留空位无限向上累积。
- 画面文字默认上方居中，可在播放器选中并拖动定位。对当前块的定位属于当前块覆盖；修改轨道位置属于轨道样式，操作对象必须明确。主副已绑定时以整对为定位单元。
- 画面文字不参与对白的底部自动堆叠；默认固定位置。注释之间或注释与对白发生碰撞时，在编辑状态提供局部提示，用户决定调整位置；不自动漂移注释或缩小字体。
- 固定画面位置保存在工程中，以视频内容区域为坐标基准，不受播放器黑边、窗口大小影响。
- 样式解析顺序明确：工程默认 → 轨道覆盖 → 当前字幕的明确位置覆盖。首版不扩展任意逐字样式或动画关键帧。

预览继续默认跟随工程，也保留校对预设“仅影响预览”的独立选择；改变工程轨道或样式不能重置这个选择。精确预览、ASS 和烧录共用同一份时间、绑定、换行、位置与排布结果。

## 7. 识别、翻译、配音和导出

### 7.1 处理流程

- ASR 默认写入当前指定对白轨；在应用识别结果时明确目标轨道和替换对象。不能因时间相同覆盖其他对白或画面文字。
- 翻译根据实际所选字幕及明确绑定回填，支持画面文字轨。不会按最近时间猜译文应该属于哪一条。
- TTS 支持所有普通字幕块，但“对白批量配音”默认只统计对白轨；画面文字需显式选择后处理，不能因为新增注释就自动读出注释。
- 轨道创建、折叠或换轨本身不会复制或重新生成音频贴片；已有贴片和素材保留稳定来源引用。时间／文字改变后的素材复核沿用现有规则。
- 所选字幕数、目标轨道和将覆盖的对象在任务内明确显示；迟到结果继续遵循原有快照、取消和切换工程保护。

### 7.2 导出保持简洁

- 视频导出继续只有“烧录字幕”和“字幕样式：跟随工程／其他预设”等既有选择，不添加临时编辑区。轨道启用状态、画面位置在工程里决定。
- 烧录仍遵循主／副／双语范围，画面文字同样有明确主副角色；已启用且属于导出角色的内容全部参与。导出前在播放器查看工程样式。
- 导出时改用其他样式预设只覆盖样式，保留轨道用途与显式位置。新的预设格式需要包含对白及画面文字的基础样式；旧预设不包含注释配置时，注释继承该工程原配置，不能被送回底部。
- ASS 保存可表达的多轨事件、样式、位置和显示优先级；烧录使用相同生成结果。
- SRT 可导出指定轨道或合并显示文本；不承诺保留自由位置、字体或外部播放器的叠放效果。已有“合并主副字幕（SRT）”名称和菜单位置保持，导出范围另明确是否包含画面文字，避免把该动作悄悄扩成合并所有内容。
- 去空隙、时间范围导出对所有字幕和贴片使用同一时间映射；固定空隙语义保持。OTIO 等外部时间线只承诺其实际支持的字幕和来源信息。

## 8. 数据与旧工程迁移

固定轨道归属必须保存到工程，不能继续只靠一次渲染产生的层号。推荐先保留现有主副字幕真源，通过统一访问接口添加轨道元数据和归属，不创建第二份字幕正文。主要元数据包括轨道 ID、名称、用途、顺序、启用／锁定状态、样式覆盖及字幕归属。

字幕的稳定身份与可变轨道归属分离。移动到另一条显示轨道不能使绑定、颜色、素材来源和后台任务把它当作新字幕；数组排序不得替代稳定 ID。

实施前定稿新的能力／格式版本门槛。旧编辑器如果不能理解多条固定轨道和自由位置，必须明确拒绝或提供有损导出说明；不能静默忽略新字段后覆盖保存。现有 `.mosp` 后缀及 `.assets` 资源组织保持。

迁移原则：

1. 原主副字幕优先进入“对白 1”；相交且无法同轨放置的内容分配到额外固定轨道。明确绑定作为整体分配，保留时间偏移；不按时间接近重建绑定。
2. 原叠加来源不能自动等同于注释。可识别的旧组保留“原叠加字幕”等来源名称、启用状态和原有显示信息，用户再确定用途。
3. 内容时间、字词时间码、颜色、禁用、表情包、绑定和配音素材引用不因迁移丢失；隐藏旧组保持未启用。
4. 已有手动位置优先原样保留；旧自动避让布局需要实际帧对照。不能仅凭轨道迁移测试就声称画面完全一致。无法保真时保留原工程并明确显示差异，不自动切换输出策略。
5. 打开只在内存迁移；首次写回保存旧版本备份；迁移失败或备份取消不覆盖原文件。布局与状态需经过保存重开验证。

## 9. 实施顺序和验收门槛

| 阶段 | 交付 | 必须通过的验收 |

| 1. 拖动基础修复 | 统一单边约束、合法位移、吸附和跨行坐标；可先修复当前用户遇到的问题 | 已复现三例全部消失；毫秒／帧、单行／多行、主／副、共享边界、取消和一次撤销通过 |
| 2. 固定轨道与迁移 | 已建立 v3 元数据、统一查询、稳定归属及专用迁移读写；尚不进入默认编辑流程 | 无时间／引用损失；绑定整体迁移；碰撞内容无丢失；旧隐藏状态保留；旧版不误读；验证详见[第二阶段记录](TEST_FEEDBACK_SUBTITLE_TRACKS_20261009.md) |
| 3. 编辑体验 | 已在开发入口接入紧凑轨道头、添加／换轨、折叠／锁定、列表范围和编辑器归属 | 普通拖动不跳轨、不重排行高；多选／切分／合并／撤销操作一致；单行／多行支持，详见[第三阶段记录](TEST_FEEDBACK_SUBTITLE_TRACK_EDIT_20261009.md) |
| 4. 注释与画面排布 | 已接入轨道继承／独立样式、注释定位、稳定对白避让、明确主副成组；旧工程显式切换 | 浏览器测量预览验证播放稳定性、长短句、连续重叠、双语偏移、换行、负间距、注释定位及保存；精确 libass 与烧录帧对照留到阶段 5 |
| 5. 处理与输出闭环 | ASR／翻译／TTS、预设、ASS、烧录、SRT 和去空隙适配 | 不串轨回填；素材身份保留；预览与真实 FFmpeg 烧录帧对照；保存重开一致 |

固定轨道模型进入默认使用前必须完成阶段 2–5，不能只上线一个能拖动、但保存或导出仍按旧轨处理的半成品。阶段 1 独立交付，不改变工程格式或轨道归属；鼠标碰撞约束已包含绑定跟随集合，离散键盘微调保留原有的冲突拒绝规则。

第二阶段定稿格式为 `msw.project.v3` / `msw.subtitle_tracks.v1`，迁移工具默认只读，显式写回才生成原字节备份。第三阶段开发页面在内存迁移，支持轨道编辑及便携工程保存，首次覆盖旧文件必须保留原字节备份。第四阶段在媒体播放器的字幕样式中提供“保留旧排布／固定轨道排布”选择；新排布使用浏览器字体测量，注释按视频内容坐标定位。默认编辑器与普通输出仍拒绝 v3，旧文件句柄不能覆盖新版本文件。开发页面不绑定服务端保存／处理任务，不开放尚未适配的输出；阶段 5 负责精确预览和实际输出的一致性。契约与开发者检查命令见 [JSON_SCHEMA](../JSON_SCHEMA.md#固定字幕轨道-v3第二阶段数据接口)。

重点交互夹具：两人同说＋各自译文、对白＋长注释、连续三组交叠、同起点不同终点、跨波形行的长字幕、多组共享边界、主副不同时间偏移、锁定跟随对象、快速越过多个短块、拖出可视区、拖动中滚动／缩放、隐藏轨与禁用块、后台任务期间换轨、旧 v1／v2 保存重开。
