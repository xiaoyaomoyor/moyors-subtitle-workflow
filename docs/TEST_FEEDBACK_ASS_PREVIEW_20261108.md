## 实施与首轮验证

- `previewIds` 只通过自动排布的有效字幕传播重叠依赖。固定注释仍进入所在时段的预览；单条锚点没有固定组基准时继续保留原自动排布依赖。绑定伙伴、远端标记来源物化和原文内容均保留。
- 主编辑器采用编辑版本与小规模设置签名，兼容宿主仍保留内容轮询。请求执行期间只记录后续变更，完成时校验版本；未变化的空闲轮询不复制工程。精确几何校验不再序列化全部字词时间。
- 字体清单返回所有限额内文件；超过单文件 64 MiB／合计 256 MiB 或文件不可读时，按字体族明确报告。前端清单缓存最多 32 组，字节缓存最多 128 MiB；正在读取的字节也复用，失败可重新请求。字体族顺序规范化，字体文件标识包含大小和修改时间。
- 浏览器专项使用固定长注释的 10,000 条合成工程。空闲 2.4 秒（覆盖旧版三个轮询周期）投影读取为 0；人为延迟请求后连续三次改样式，只投影和请求两次，旧结果被丢弃；文字编辑、撤销、跨窗口跳转通过。
- `project-subtitle-style.spec.mjs` 包含真实 libass 与 FFmpeg 画面对照、主副绑定／独立轨道、换行、负间距、便携模式及旧后端检测；14 项全部通过。更新失败测试原先要求立即切到近似预览，与现有“保留最后有效画面”的行为不符，已拆成保留画面和媒体重置后失败两个断言。
- 初轮新增夹具误用了 `fontFamily`（契约为 `fontName`）、字体统计混入 GET 请求、计数尝试修改冻结宿主，均属于测试搭建错误，修正后重新运行通过。Python 首轮未包含 tests 导入目录，5 个模块未载入；补齐导入路径后重新运行，结果如表。没有放宽性能和内容断言。

## 最终性能结果

命令：`node scripts/benchmark_preview.mjs --baseline d40d9ff8 --out output/perf-ass-20261108-v3`。原始报告保留在本地，去除无关逐帧数据后的可提交记录见 [ASS_PREVIEW_20261108.json](performance/ASS_PREVIEW_20261108.json)。

同一机器、浏览器及当前后端，分别加载旧／新前端；两小时 640×360、2 fps 合成媒体，每个工程 10,000 条。每项预热一次、正式三次，共 24 个正式样本全部成功；四次场景运行均无页面错误，原工程文件摘要未变，测量前后前端源码摘要一致。这里只对比前端，未伪装成历史后端的端到端对照。

下列单位为毫秒，统计为三次正式样本的中位数，包含编辑提交和最终 ASS 更新等待：

| 万条场景 | 文字修改：旧 → 新 | 样式调整：旧 → 新 |
| --- | ---: | ---: |
| 普通主副绑定 | 1,401 → 962 | 1,074 → 659 |
| 固定长注释 | 9,535 → 813 | 18,869 → 618 |

- 固定长注释在当前 0–60 秒窗口的渲染输入从 10,000 条降至 85 条；普通绑定保持 84 条。其他窗口与自动重叠链由模型及完整布局对照覆盖，不能简单按固定条数截断。
- 每个场景空闲观察 2.4 秒，旧版均投影 3 次，新版均为 0。几何检查独立五次采样中位数从约 208／226 ms 降至计时分辨率附近的 0／0.1 ms；0 不表示绝对没有执行成本。
- 文字输入仍有约半秒的编辑快照／校验同步开销。普通工程的完整预览耗时仍受后台校验和恢复任务影响；不宣称所有编辑已达 100 ms，不用三次样本推算操作 P95。保存及后台任务继续由第五阶段处理。

边界：本轮没有跑完整 27 类操作矩阵、数小时连续编辑、所有字体／系统、真实高分辨率媒体或整部电影烧录。既有保存失败及历史波形测试问题没有被本轮结果抹去。前端产物已重新生成，离线比较工具重建后无变化；没有修改工程格式或个人工程。
