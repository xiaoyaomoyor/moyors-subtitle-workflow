## 1. 核心结论

这次不能只调整图标和间距。最优先的问题是测试没有完整隔离新增的持久数据，导致测试工程进入真实用户的“全部工程”。此外，首页双分组、独立模块卡、右侧设置栏虽然已经出现，但部分行为仍只接了一半：封面只由全部工程驱动、序号没有决定 DOM 排列、设置抽屉按钮没有绑定、隐藏输出参数仍进入方案。

已保留的改善包括：五页基础结构不再出现上一轮整体错位，左导航图标居中已经改善，工具页能直接配置，右键菜单连续打开及 Esc 关闭本轮通过。因此，本文件不把上一轮所有问题重新列成当前故障。

优先级：P0 为真实用户数据污染与测试隔离；P1 为执行参数、功能不可达、错误顺序及主要信息缺失；P2 为视觉一致性和效率。除明确注明已验证的旧问题外，下文修正均为待处理。

## 2. “547 项、全部在 C 盘”的真实原因

### 2.1 本轮读到的数据

只读取了正式用户目录中的 `launcher-project-registry.json` 并做汇总，没有读取 `.env` 或输出完整个人工程路径。

| 指标 | 结果 |
| --- | --- |
| 登记总数 | 547 |
| 路径位于系统临时目录 | 547 |
| 工程文件已经不存在 | 547 |
| 路径所在盘符 | 全部 C 盘 |
| 登记来源 | `opened` 306、`created` 157、`editor` 84 |
| 登记日期 | 2026-09-16：4；2026-09-17：43；2026-09-19：500 |

名称高度集中在测试夹具，例如 `project.json` 212 条、`clip.waveform.mosp` 59 条、`clip.waveform-1.mosp` 53 条、`second.json` 53 条、`project.mosp` 42 条；不同临时目录会形成不同登记身份，因此同名不会自动合并。

结论：这些不应被当成用户真实制作的 547 个工程。它们是已删除临时工程留下的登记污染，与仓库测试中的夹具和调用路径吻合，不是工程被启动器搬到了 C 盘。

应用在 C 盘用户数据目录保存索引和封面缓存本身是正常行为；异常的是索引里的**工程路径**全来自测试临时目录。不能用“应用数据默认在 C 盘”解释掉这次污染。

### 2.2 代码中的污染路径

- `maw/gui_web.py:LauncherPaths.project_registry` 默认是 `None`。
- `_register_project_safe()` 将该值传给 `register_project()`；为 `None` 时使用正式应用数据目录。
- `tests/test_gui_web.py`、`test_launcher_r0.py`、`test_launcher_r4.py`、`test_launcher_r6_real.py` 中仍有只注入临时 `root/env_path/recent_metadata`、没有注入 `project_registry` 的 API 构造。
- 编辑器的 `_register_launcher_project()` 调用 `register_project(..., source="editor")` 使用默认位置；部分编辑器服务器测试没有统一隔离应用数据根。
- 测试结束删除临时工程，却不会回滚正式索引。重复运行测试继续增加记录。

这也说明此前“使用了临时工程”并不等于“没有污染用户数据”。本轮不运行未隔离的完整测试套件，避免再次增加记录。

### 2.3 修正与恢复方案

先阻断新增污染，再处理现有记录：

1. 为单元、集成、真实媒体、原生验收和子进程建立统一隔离夹具；应用数据根、工程索引、最近记录、缓存、日志、任务及测试配置都落在本次临时根目录。
2. 将索引依赖贯穿启动器和编辑器服务；补齐所有测试构造器，检查导入时缓存的默认路径，确保环境变量在相关模块初始化前生效。
3. 测试子进程显式继承隔离位置；增加越界写入断言，不能靠执行后删除污染来维持“干净”。
4. 对真实索引建立备份及清理预览，候选条件同时考虑临时目录、文件不存在、测试夹具/运行来源；清理仅处理索引记录，不操作磁盘媒体或工程文件。
5. 展示拟移除数量、判断依据和保留项后再执行；未知或无法判断的路径保留，支持从备份恢复。当前这 547 条可列为重点核对候选，不把这个数量硬编码。
6. 修正登记的来源与成功条件：只有真实制作、打开、保存成功的最终工程进入目录；临时包装工程和中间产物不进入。

不要粗暴禁止所有临时目录工程：用户也可能主动打开临时文件。真正的边界是测试/任务数据域隔离和明确登记意图，不是单纯匹配 `C:` 或 `Temp`。

### 4.2 数据层需要补齐的可靠性检查

- **首次登记与历史迁移的先后顺序**：迁移只在索引不存在时发生；如果制作/编辑器打开先创建索引，后续“全部工程”可能跳过旧最近记录迁移。应使用独立迁移版本标记，并作幂等合并。
- **坏索引不能当成空索引覆盖**：当前解析失败返回空字典，下一次登记可能写入仅含新条目的文件。区分首次不存在、格式损坏和读取失败；保留坏文件、备份及恢复入口。
- **锁不能只按时间猜持有者死亡**：当前锁文件达到 10 秒可被删掉重抢。需验证慢磁盘/进程暂停下的并发更新，优先可靠的跨进程锁或所有权校验；尚未复现丢记录，不报告为已经发生。
- **移除记录与删除文件的保护**：当前文件删除入口主要检查受管编辑器会话。运行中的制作任务、独立编辑器和操作前后的文件变化需补验收；本轮不调用删除接口。
- **登记失败反馈**：写入失败目前主要记录后端日志。已成功制作但登记失败时应仍可打开产物，并显示“未加入工程目录/重试”，不能只让首页没有卡片。

这些是代码路径与回归边界，不等于本轮已发现工程内容丢失。

## 5. 首页与分页的具体方案

### 5.1 分页控件

全部工程取消“加载更多”，默认每页 12 条；提供上一页、紧凑页码、下一页和“第 X/Y 页 · 共 N 项”。页数多时用省略号，不铺满所有页码；第一页/最后一页按钮禁用。0 条时显示空态，不出现“第 1/0 页”。

- 控件使用现有小按钮、圆角和选区色；当前页使用明确的活动状态及 `aria-current=page`。
- 分页条放在全部工程区域底部；卡片行数变化不造成按钮大幅漂移。窄屏保留上一页、X/Y、下一页。
- 每页条数可作为后续设置，首轮固定 12 即可；响应式改变列数不悄悄改变当前页范围。
- 翻页只替换本页，不累积 DOM；将全部工程区域滚动到可读位置，不把用户突然带回整个窗口顶部。
- 最近工程保持短列表与可折叠；不为了全部分页把最近工程也做成复杂双分页。

### 5.2 搜索、选择和更新规则

- 搜索覆盖全部登记工程名、媒体名、路径，输入后回第一页；计数展示命中数和总数。
- 翻页保留选中工程身份，底部明确显示“将打开：工程名”；本页之外的目标不能只剩一个无解释的打开按钮。
- 搜索彻底排除已选对象时清除选择；单纯折叠分组或翻页不自动切换打开目标。
- 删除最后一页最后一项后退到最近有效页；删除/移除失败留在原页并显示原因。
- 新工程制作成功排到前部；用户从结果进入首页时可定位第一页新卡片，普通后台刷新不强制打断用户正在看的页。
- 切页、搜索、刷新使用请求序号或取消标记，慢响应不能将页面回退。
- 图钉/选中状态按工程身份跨最近与全部同步；固定不强制打乱全部目录的最新排序。

### 5.3 后端分页与摘要

新增明确的分页查询参数和响应：`query/page/pageSize/sort`，返回 `items/total/matched/page/pageSize`。总数来自登记索引，媒体摘要使用轻量缓存；只对当前页做必要路径状态检查和封面请求，避免每次翻页重新解析所有工程。

媒体名搜索可以先渐进建立摘要索引，但建立过程中要显示范围/进度，不能无提示地漏掉未看过的卡片。离线盘或网络盘探测需有时间边界，不让整个首页因一个慢路径无响应。

计数建议显示“已登记 N 项”，可附“失效 M 项/待检查”；尚未完整检查时不伪造精确可用数量。缺失记录保留重新定位入口，清理索引由明确操作触发。

## 6. 封面、图钉和缓存修正

### 6.1 观察和请求

- 收集最近可见卡片及全部当前页卡片的并集，一次性更新观察；或每个分组各有观察器，共用按工程/媒体版本去重的请求层。
- 全部区域折叠、空目录、全部页内没有该最近工程时，最近封面仍会加载。
- 折叠区域不主动解码新媒体；同工程在两处出现只提取一次，并更新两处。
- 翻页后停止等待或取消无用的前端请求；后端提取保留并发上限与超时，不无限排队。
- 重新定位、替换媒体、工程保存、源文件版本变化后验证缓存，不只检查“之前有图片”。
- 每个异步响应关联请求代次和工程/媒体身份；旧图片、旧图钉状态不能回写覆盖新状态。

### 6.2 图片状态

明确展示加载中、有效图片、纯音频、无媒体、媒体缺失、工程失效、提取失败。桥接失败或图片解码失败必须进入可重试状态；“刷新封面”失败给出简短原因，不能继续空白。

保留现有基于真实 `media` 引用、FFmpeg 取帧及本机缓存的架构，不为修复前端加载改成同名猜视频。真实视频测试包含横屏、竖屏、短片、黑场、相对路径、中文路径、多音轨和已移动媒体。

### 6.3 图钉

将整枚图标的描边定义在 SVG 根，统一路径继承；检查针杆、帽沿在 100%/125%/150% 缩放下不裁边。保持当前角落位置，给足图标和点击/提示空间；底色在明暗视频画面中均可辨识。

封面目前 `aria-hidden=true`，图钉的读屏信息不应只藏在其内部。固定状态也写入卡片可访问名称或独立语义节点，与选中状态分别表达。

## 7. 模块、设置和输出一致性

### 7.1 模块顺序

以单一模块注册表定义：媒体、波形、ASR、字幕整理各步骤、翻译、人工对齐、输出、日志。口播对齐的具体结果回流关系在执行计划中明确，输出在处理配置之后，日志始终最后。

注册表同时驱动 DOM 排列、序号、右栏选项和配置摘要。不得仅用 CSS `order` 修饰视觉而保留错误的键盘顺序；不得仅改编号让错误顺序看起来连续。勾选、取消、重新开启、重启恢复后顺序保持。

“处理顺序”摘要需要来自实际执行计划；配置卡的固定展示顺序不一定等于内部缓存生成的时间顺序。修复 DOM 时不随意改处理器依赖；若摘要只是勾选模块列表，应改成“启用模块”避免误导。

### 7.2 设置栅格和抽屉

正文采用与标题一致的 24px 左右外边距，并统一设置分组、工具卡、预制模块的内部 14～16px 间距。当前 1200×780 下设置标题 x=88，而正文从导航边界 x≈64 起，需修正的是正文容器，不要把标题也向左挤。

- 设置页各组都校验，而非只修外观组；长路径、模型下拉、底部保存和错误提示不得贴边或遮挡。
- 标题、正文、右栏和底部操作区有明确滚动归属，不再通过叠加 padding 临时补洞。
- 预制、工具、设置三种右栏共用抽屉行为：打开、关闭、遮罩、Esc、焦点返回、切页、宽窄切换。
- 响应式规则置于正确优先级；打开后头部/关闭按钮/遮罩都可见，关闭时隐藏栏不能被键盘继续访问。
- 动效维持短而轻的过渡；自动化截图等待动画结束。本轮初次窄窗截图捕捉到过渡中间态，后续稳定态已复查，不把中间态当作常驻遮挡。

### 7.3 输出配置和路由

保留自定义草稿，但建立明确的“有效输出配置”解析：输出模块开启时使用自定义值，关闭时使用全局默认；预览、单文件/批量载荷、后处理及最终文件都消费同一解析结果。

增加回归：输入自定义路径 → 关闭模块 → 制作；重新开启后草稿恢复，但关闭期间不生效。原文/译文导出开关、默认值与当前方案也需同样处理。

用设置分组 ID 的统一映射替代到处硬编码 DOM ID，修复 `filesPanel` 旧深链，并批量检查运行环境、模型路径、连接配置、输出等入口。

## 8. 建议一并完善的相关能力

这些内容紧贴当前使用问题，按修复后优先级排列，不扩大成新平台：

1. **工程目录检查**：显示已登记、已确认失效、待检查数量；提供清理失效记录预览及重新定位。不能默认删除用户真实文件。
2. **封面诊断**：在失败占位的详情中说明媒体缺失、FFmpeg 不可用或提帧失败，并提供重试。普通成功卡片不常驻技术注释。
3. **可恢复的索引操作**：移除记录、批量清理提供恢复路径；数据损坏给出备份恢复，而不是默默重置空目录。
4. **工程筛选**：登记来源、可用/失效、固定项筛选；放入紧凑筛选菜单，不增加多排工具栏。
5. **产物登记失败补偿**：制作已成功但目录更新失败时保留打开按钮，允许重试登记。

不加入全盘自动扫描、自动删除素材、远程工程同步、新 ASR/TTS 引擎或与当前问题无关的功能。
