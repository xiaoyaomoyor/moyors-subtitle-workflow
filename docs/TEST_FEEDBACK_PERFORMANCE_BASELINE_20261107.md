## 后续施工依据

- **第二阶段，事务与索引**：10,000 条剪切一组的同步中位数约 2,815 ms，`fixedContentKey` 中位调用 5 次、累计约 532 ms；`renderAll` 一次约 1,625 ms。这些函数可能嵌套，不能简单相加。半数字幕轨道锁定的无改动模型校验中位数约 782 ms，需优化校验范围并保持锁定正确性。
- **第三阶段，界面增量刷新**：加载后的 DOM 节点从 1,000 条约 3.1 万增长到 10,000 条约 15.3 万、15,000 条约 22.1 万。10,000 条整组拖动松手提交中位数约 451 ms；100 组端点调整的松手提交约 582 ms，移动过程另有逐事件耗时记录。
- **第四阶段，预览与字体**：90 秒普通预览模型返回 126 条；固定长注释参与重叠关联后返回整个 10,000 条。混合场景的样式预览、文字预览也明显较慢，需分别核对范围投影、生成与前端刷新；字体文件静默截断及字号偶发跳变继续专项处理，本阶段未宣称解决。
- **第五阶段，保存与后台**：10,000 条无变化保存仍约 1,384 ms，混合场景约 4,317 ms。保留修改后、仅播放头、无变化三个独立工作量，避免遗漏快路径。
- **第六阶段，稳定性**：10,000 条的回收后 JS 堆约 174 → 204 → 174 MiB（加载／操作后／重开）。这只是三个测量点，不能证明长时间无泄漏；持续播放、多小时编辑、真实高分辨率媒体和完整视频导出仍需专项验收。

10,000 条已保存状态的三次空闲观察（每次 6 秒）分别记录到 3 / 1 / 1 个长任务，最长 163 ms；被计数的关键编辑函数未调用。仅凭这些数据不能判断是后台扫描、回收还是其他来源，留待第五阶段定位，不能标记为空闲无负载。
