- 耗时分开记录浏览器操作至结果可用，以及主线程超过 50 ms 的任务；不把包含查询防抖的等待时间当成阻塞时间。

## 实测与处理

- 原媒体（约 1.59 GB）及有效波形缓存已复制到测试目录，保持时长和真实峰值；原 `.mosp` 前后以 SHA-256 核对。未使用简化文字替代长工程。
- 首次基线：常规搜索 300–516 ms（包含防抖与浏览器操作）；单条修改 1064 ms、最长主线程任务 702 ms；6339 条整体替换 6562 ms、最长任务 4683 ms；批量撤销 4862 ms、最长任务 2967 ms。
- CPU 采样定位：纯文字事务仍重建双列卡片，重复查找绑定，并触发大批界面翻译遍历。改为保留卡片身份、只更新正文／字数／过滤状态及可见波形；正文显式跳过 UI 翻译，并剪枝已标记跳过的子树。
- 首次优化复测：整体替换 3230 ms、最长任务 1473 ms；撤销 1157 ms、最长任务 938 ms；单条修改 563 ms。仍有恢复草稿完整快照开销，不能宣称所有长任务均已消除。
- 前两轮性能操作和数据断言通过，末尾关闭步骤失败：右键菜单可能已因鼠标移出自动关闭，此时 Esc 合理关闭查找窗，测试又点击隐藏按钮。测试改为明确结束菜单，另加“菜单可见时 Esc 不关闭查找窗”的交互回归；查找窗优先级也补齐右键菜单保护。
- 上述新增回归又揭示共用浮窗的冒泡监听仍会关闭底层面板：浮窗忽略已处理事件与打开的菜单，菜单处理 Esc 后消费事件。最后专项通过。
- 长工程的锁定校验发现文字工具成功提示会掩盖撤销／锁定后的最新方案；索引确实改变时清除旧提示。新用例验证撤销后显示待修改数量，锁定后显示跳过数量并禁止应用。
- 中间复验输入已是 6341 条、3167 组绑定（每轮各自验证输入哈希不变）。完整 SRT 正文和 ASS 去样式／换行后的正文覆盖通过，保存重开字幕模型完全相等；绑定拖动两侧同移 60 ms，撤销恢复。实际两秒 H.264／AAC 成品时长 2.002 秒，抽帧可见编辑后的正文及原工程其他轨道。最终性能对照固定使用首次保存的 6339 条快照，不混用更新后的工程。
- 中间完整 ASS 生成约 33 秒、磁盘保存约 4 秒；ASS 包含动画等展开结果，约 21 MB。此处测量不能理解为整部视频已完成烧录，也不宣称全轨 ASS 生成无耗时。
