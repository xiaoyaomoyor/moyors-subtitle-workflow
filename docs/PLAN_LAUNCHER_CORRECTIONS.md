# 启动器初版审查与修正案

日期：2026-09-15。审查基线：`718afe8` / `my-feature`；开始检查时工作区干净。

本轮仅审查和制定方案，没有修改启动器、编辑器或后端业务代码，没有提交或推送。以下所有修复阶段均为待处理。

## 1. 审查结论与边界

当前版本的主要问题是：新页面的 HTML 层级已经错位，旧弹窗和工具箱样式仍参与布局，新模块开关尚未完整驱动执行流程。因此，不能只换一套颜色；应依次修复会话与执行问题、页面结构、视觉组件、最近工程封面，再完成预制流程和设置迁移。

本方案延续 [原重构规划](PLAN_LAUNCHER_REDESIGN.md)，并核对了 [初版实施记录](REDESIGN_LAUNCHER_LEDGER.md)。记录中的阶段交付描述不等于全部功能已经完成，尤其已有工程处理、模块配置面板、批量执行和原生窗口验收仍有缺口。

| 审查项 | 状态 | 本轮产出 |
| --- | --- | --- |
| 原要求、实施记录、当前代码核对 | 仅说明 | 已记录偏差及对应文件 |
| 页面布局和关键操作检查 | 仅说明 | Chromium 实际点击、截图、DOM 层级和接口路由证据 |
| 独立端口服务隔离检查 | 仅说明 | 临时目录、模拟进程复现，不操作真实会话 |
| 视频封面和统一视觉方案 | 仅说明 | 见第 4～6 节 |
| 生产代码修复 | 待处理 | 按第 9 节分阶段实施 |
| 原生窗口、真实媒体和云端完整链路 | 待处理 | 本轮未验证，列入最终验收 |

证据区分：**浏览器复现**指当前前端在内置演示后端中的真实点击；**隔离后端复现**指调用真实 Python 方法但替换进程和网络探测；**代码确认**指控制流或结构可直接定位；**待实测风险**不等于已经发生故障。

本轮没有读取实际 `.env`、上传媒体、发起付费识别或停止真实编辑器。演示数据不能证明原生文件选择、真实云端调用或大型工程处理正确。

## 2. 必须保留的设计方向

- 中文名“我的字幕流”，英文名“Moyor's Subtitle Workflow”；中文主标题，英文次标题。
- 横向工作台、左侧五项导航：启动编辑器、预制工程、实用工具、使用指南、更多设置。
- 暗色采用中性黑层次和低调紫色；与编辑器统一控件、图标、卡片及反馈语言。无需把编辑器默认蓝色主题直接复制到启动器。
- 保留当前水母轮廓；暗色反白、亮色黑色、不加外框。
- 编辑器本身已能导入媒体、ASR、翻译、TTS 和管理素材；启动器提供快速打开及提前批量预制。
- 新建方案默认只启用“选择媒体”和“波形生成”。ASR 需要用户主动启用；老用户配置单独迁移，不用“兼容旧行为”覆盖新方案默认值。
- OCR 保留“字幕去重”，不新增视频硬字幕擦除。
- 启动器 TTS 和音频素材导入仍是后续扩展，不作为本轮修正案的首发依赖。

- 普通页面切换时没有出现未捕获的 JavaScript 异常；这不代表页面布局正确。

## 4. 视觉修正规范

### 4.1 统一方式

从编辑器提取或对齐有限的通用规范：字体、圆角、间距、线性图标、表单、菜单、对话框、焦点和选中反馈。启动器保留独立的黑紫配色映射，不直接整份导入 `editor.css`，避免把波形、时间线等选择器带入。

优先清理旧规则再建立组件样式；不继续在 CSS 文件末尾逐条增加覆盖。建议按应用框架、通用控件、页面组件、对话框、主题、响应式组织，选择器限制在启动器作用域。

### 4.3 横向布局与滚动

五个页面必须共享同一内容起点；只有预制页具有右侧模块栏。页头和当前页操作栏固定，中央内容滚动；不让整个窗口、卡片、弹窗形成多层竞争滚动。

1200×780 是主要设计尺寸；同时检查 1440×900 和 960×640。窄窗口先压缩导航并调整表单列数；预制模块栏可通过“处理模块”按钮打开抽屉，不应直接堆在底部持续占用半屏。系统缩放 125%/150% 时仍要能看到主操作。

## 5. 各页面目标布局

### 5.1 启动编辑器

页面顺序：标题和简短说明 → 搜索/浏览工程 → 最近工程卡片 → 当前目标与操作栏。

- 卡片以媒体画面为主体，16:9 封面在上，工程名、媒体名和简要信息在下；主设计尺寸下两列，宽屏可三列，窄屏一列。
- 卡片展示工程名、视频文件名、最近打开时间；字幕/贴片数量作为次级信息。完整路径通过悬浮或更多菜单显示，不挤占封面。
- 单击选中，双击或 Enter 打开；固定、定位、移除通过卡片更多菜单操作，不触发误选/误开。
- 底栏主按钮明确写“打开所选工程”；未选中时禁用。旁边保留“空白启动”，文件浏览可位于标题工具栏。
- 文件浏览选定的工程立即成为当前目标；无论来源于卡片还是文件选择，只有一份目标状态。
- 显式“空白启动”不暗中恢复旧工程。已有运行会话用紧凑状态区显示工程名和“返回编辑器”，不展示常驻大端口表单。
- 移除卡片只移除最近记录，不删除工程或媒体。

### 5.2 预制工程

页面上部提供输入模式、方案选择、保存方案、运行摘要；中央左侧配置卡，右侧处理模块；底部固定“开始预制”和状态。日志作为可折叠任务详情，不作为可勾选的处理模块。

每个启用模块对应一个配置区域：`序号 · 模块名 · 参数摘要 · 折叠箭头`。关闭模块保留本地草稿；再次启用恢复。缺参数显示“待配置”，不自动取消用户勾选。

| 分类 | 模块 | 主要配置与约束 |
| --- | --- | --- |
| 输入 | 选择媒体 / 选择工程或字幕 | 随模式改变文件过滤、校验和处理对象；媒体源轨选择与编辑器同义 |
| 媒体准备 | 波形生成 | 普通波形、可选频谱、缓存复用/重建；关闭后不生成波形。无可解码音轨时说明原因 |
| 字幕获取 | ASR | 服务、模型、语言及本次识别参数；API Key、地域等连接信息来自更多设置 |
| 字幕整理 | 文稿匹配、固定处理、LLM 校对、重新断句 | 各自独立卡片；摘要说明输入输出及执行顺序 |
| 字幕整理 | OCR 字幕去重 | 明确只去重；校验视频及 OCR 环境，纯音频/SRT 无视频时给出原因 |
| 语言处理 | 翻译 | 目标语言、服务/模型、目标字幕轨；默认保留主字幕并生成独立副字幕 |
| 交互处理 | 口播对齐 | 作为独立人工步骤入口，不伪装成勾选后可全自动执行的步骤 |

顺序沿用现有处理器依赖进行明确编排；不因卡片摆放随意改变执行语义。OCR 与文稿匹配等会影响后续输入的处理应说明影响；首轮不加入任意拖拽重排。

输出区以工程文件为主，SRT 为可选附加产物。只有明确选中时才输出便携 HTML；已有工程处理默认另存新工程，不能静默覆盖原工程。

完成后显示结果卡：工程名、成功/失败模块、字幕及素材摘要、打开编辑器、打开所在目录。部分失败时区分已完成结果和未执行步骤，并明确重试范围。

### 5.3 实用工具、使用指南、更多设置

实用工具保留提取音频、压制外部字幕、媒体重组等独立文件操作。波形、文稿处理等回归预制模块；旧入口先迁移引用，再移除重复 UI。口播对齐保留明确的人工处理入口。工具弹窗显示输入、输出、执行及取消，继承统一对话框样式。

使用指南用三条简短路径：直接进入编辑器、提前预制工程、纯配音与素材。按钮名称与实际 UI 一致，去掉“Server 版”等实现术语；文档和仓库链接保留，失效提示可读。

更多设置改为真正的页面，建议分组：

1. 外观与语言：主题、缩放、中英文；顶栏语言切换只保存语言，不顺带保存未确认的处理草稿。
2. 服务与连接：ASR、LLM 等已有服务的地域、Workspace ID、API Key、Base URL。尽可能复用编辑器现有配置契约，先核对来源和优先级，避免再建一套冲突配置。
3. 默认处理参数：仅作为新建方案默认值，和当前方案参数区分。
4. 文件与输出：默认目录、命名和碰撞策略。
5. 工具与运行环境：FFmpeg、OCR、本地 ASR 现有路径和环境状态。
6. 编辑器启动：默认端口、会话管理等高级选项。
7. 缓存与诊断：封面缓存、日志目录、必要诊断信息。

默认值修改不悄悄覆盖打开的方案。环境配置缺失时导航到对应组并聚焦字段；取消后能返回原模块，保留草稿和滚动位置。

## 6. 真实视频封面的实现方案

### 6.1 工程与媒体解析

1. 以最近工程路径为入口，复用工程读取和 `resolve_project_media` 的路径规则；支持 `.mosp`、兼容工程 JSON、相对媒体路径及随工程收集的媒体。
2. 从工程实际 `media` 引用解析视频，不猜测同名 MP4，不使用最后一次在启动器输入的媒体路径。
3. 只读取必要元数据，不为封面启动完整编辑器、不生成波形、不修改工程。
4. 封面绑定解析后的源媒体版本；播放代理存在时也不能混淆不同源视频。优先直接从源视频提取，代理仅作为明确可验证的可用来源。

### 6.2 首帧策略与状态

- 默认静态画面，不自动播放和发声。
- 第一候选取视频时长约 10% 处，并限制在约 1～5 秒；短视频限制在有效时长内。时长未知时安全退回较早帧。
- 若首候选几乎全黑/全白，可再尝试少量候选帧；最多约三次，不进行全片分析。仍无合适画面则使用可用帧或占位。
- 封面容器 16:9，居中裁切；文字放在封面下方以保证可读性。竖屏视频仍使用同一尺寸卡片。
- 纯音频使用音频图标和文件名；有缓存波形可作轻量展示，但不为封面启动重型波形分析。
- 分别处理“加载中、已生成、纯音频、无媒体、媒体缺失、工程损坏、提取失败”。封面失败不阻止打开工程。
- 工程文件缺失和视频文件缺失使用不同状态；后者仍可进入编辑器重新关联素材。

### 6.3 缓存、性能和接口

- 建议新增小型 Python 封面服务，例如 `maw/launcher_thumbnails.py`，通过现有 pywebview 桥接接入，不引入远程图床。
- 缓存存于本机应用缓存目录，不写入 `.mosp`，不污染工程 `.assets`，移动工程不要求携带封面缓存。
- 缓存键至少包含媒体规范路径、文件大小、修改时间、提取尺寸、取帧策略版本；工程重新关联视频时重新解析并失效旧映射。
- 同一视频可复用图片缓存；路径/文件版本变化后不展示旧封面冒充新视频。统计缓存和工程摘要另外按工程文件版本管理。
- 图片建议约 480×270 的 JPEG/WebP；页面用缩略图尺寸，不传输整张视频原始帧。
- 先加载卡片文本，封面按可见区域异步加载；最多约两个并行提取任务，同一媒体请求去重，支持超时和切页取消等待。
- 缓存命中直接返回；失败短期缓存，避免每次窗口获得焦点都重复启动 FFmpeg。提供“刷新封面”和“清理封面缓存”。
- 桥接只返回受控缓存标识及小量状态；具体传图采用与原生 WebView 相容的受控本地资源方式，不增加任意本机文件读取接口。
- 异步响应必须核对卡片的工程和媒体版本；搜索、切页、重新定位后，旧请求不能回写到新卡片。

首轮不加入悬浮视频播放、联网封面、AI 选帧或手动时间轴选封面；以后需要时独立扩展。

## 7. 执行与数据修正原则

### 7.1 一份方案驱动 UI 和执行

建立带版本号的预制方案对象，包含输入模式、输入引用、启用模块、模块参数和输出选项；密钥只保存在连接配置中，方案使用服务引用，不复制密钥。

渲染配置卡、生成步骤摘要、预检、单文件执行和批量执行都从同一个方案生成，取消“右侧状态、旧复选框、工具箱草稿、实际请求”各自做主的情况。旧控件只作为迁移期适配，完成后清理双向同步代码。

| 输入与选择 | 必须执行的行为 |
| --- | --- |
| 媒体；只保留输入模块 | 生成合法零字幕媒体工程，无波形、无 ASR、无 API Key 要求 |
| 媒体＋波形 | 生成零字幕波形工程，不调用 ASR |
| 媒体＋ASR，可选波形 | 只执行选定步骤；选择的源音轨贯穿识别、缓存和工程元数据 |
| 已有工程＋字幕处理 | 读取原工程，处理指定字幕轨，保留其他数据；不自动调用 ASR |
| SRT＋字幕处理 | 处理字幕并按输出选项生成结果；需要视频的模块明确要求补充媒体 |
| 需要字幕但没有字幕或字幕生成步骤 | 开始前定位到问题模块，说明原因；不静默成功或跳过 |
| 批量 | 每个输入运行相同的已冻结方案；分别报告结果，失败不会冒充整批成功 |

预检应覆盖输入类型、路径、源音轨、模块依赖、环境、连接配置、输出目录和文件名冲突。耗时探测异步进行，不在界面线程读完整媒体。

### 7.2 会话与任务

- 后端以会话 ID 管理进程、端口、工程身份、启动状态和实际 URL；前端显示并使用同一份会话状态。
- 独立打开新会话必须保留原会话；关闭单个会话只影响该会话；启动失败不覆盖原来的受管句柄。
- 无文件路径不等于没有未保存内容；通过编辑器状态区分空白、已加载未保存和有修改的会话。
- 冲突处理使用一个对话框提供“返回现有会话”“独立打开”“替换当前会话”等适用操作；替换涉及未保存内容时走编辑器保存/放弃确认。
- 波形、ASR、后处理和批量具备统一任务状态：等待、运行、取消中、已取消、失败、完成；停止后只有确认后端退出才标为已取消。
- 切换页面不能中断任务或抹掉输入；修改下一次方案不能影响正在执行的任务快照。

### 7.3 编辑器工程保真

已有工程处理必须经过生产工程格式的读取、迁移和写入，不重建一个只有 `media + segments` 的简化对象。至少覆盖：

- `msw.assets`、`msw.subtitle_assets`、`msw.asset_batches`、已移除素材记录。
- `msw.audio_tracks`、`msw.audio_clips`、增益、静音、TTS 配方及关联的音频字节。
- 多重字幕轨、主副绑定、颜色标记、字级时间及稳定 ID。
- 时间选区、媒体元数据、源音轨、工作区和其他不属于当前步骤的合法扩展。
- `.assets` 相对引用及另存目录变化后的可打开性；媒体丢失不自动删除字幕或素材。

重新断句等需要改变字幕 ID 或时间的操作必须显式维护或标记失效的绑定关系；翻译默认添加独立副轨，不将所有双语塞进主字幕。传统双语合并仅作明确的兼容选项。
