# MSWE 统一多层字幕实施计划

日期：2026-10-05。核查基线：`my-feature` / `e33549b` 及本轮界面整理。**本文件是规划，不表示多层字幕已经实施，也不授权本轮修改工程结构。** 以下 A–G 专指本功能，不沿用早期 ASR／TTS 的阶段编号。

## 1. 要解决的问题与产品边界

MSWE 已是可直接导入视频、识别、翻译、配音、整理素材和导出的编辑器。重叠字幕应参与这条完整流程，而不是要求用户先把普通字幕转换成一个操作能力较少的特殊类型。

典型任务：

1. 两人同时说话：A 为 10–12 秒、B 为 11–13 秒，两条都可编辑、翻译、配音。
2. 台词与画面注释同时出现：注释独立存在，不占用译文的“副字幕”位置。
3. 双语重叠对话：A／A 的译文、B／B 的译文保持各自绑定，不因时间相交串配。
4. 从 ASR 批次或素材库加入字幕：保持原时间／相对时间，有重叠时自动排布，不为放入第二层而损失颜色、来源或配音关联。

保持轻量：首版不做完整视频剪辑轨道系统，不增加轨道总线、关键帧动画、模型训练、任意数量语言管理等低相关扩展。多层字幕不会自动生成或静音配音；音频贴片仍遵循现有三层重叠限制。

## 2. 当前实现核查

| 现状 | 对新功能的影响 |
| --- | --- |
| 主字幕在 `segments`，副字幕在 `multi_subtitle.tracks[*].segments`，叠加字幕在 `overlay_track.segments` | 不能只把“V叠”改个名字，必须统一查询和操作身份 |
| `convertMainCuesToOverlay` 迁移字幕并解除相应主副绑定 | 换显示行不应再改变绑定或字幕角色 |
| 叠加轨内部仍检查时间冲突；SRT 导入只有主轨＋叠加轨两层容量 | 导入与编辑都需要支持多条同时有效字幕 |
| TTS、翻译的常用选择入口围绕主／副字幕 | 新机制必须纳入原配方、字幕快照、批次记录与素材库 |
| `findActive` 等路径返回单个命中；部分查询按相邻条目的时间判断 | 要分清“所有播放命中”与“当前编辑对象”，补齐区间查询 |
| `maw/project.py` 的时间修复会以此前字幕结尾夹逼后一条 | 不能把合法重叠误判成异常后自动改时间 |
| `color_ref`／`sticker_ref` 的部分引用使用 `headIdx` | 排序／旧轨迁移前需先保存实际颜色、说话人和表情包引用语义 |
| 视频文本烧录已有按时间事件合并文本的路径；ASS／样式库另有路径 | 预览、ASS 与视频必须采用同一排布规则，避免结果各不相同 |
| 旧工程使用 `moy.asr.project.v1`，显式未知版本被拒绝 | 新语义需明确版本升级与兼容出口，不能假装旧版本仍可无损读取 |

主要依据：`JSON_SCHEMA.md`，`web/editor.js`、`web/waveform.js`、`web/editor-utils.js`、`web/msw-project.js`、`web/msw-asr-core.js`、`web/msw-translation-core.js`，以及 `maw/project.py`、`maw/msw/subtitle_export.py`。

## 3. 建议确定的交互规则

### 3.1 字幕角色和显示层分开

- **主／副是内容角色**：副字幕仍表示翻译／替代语言，并通过稳定 ID 与主字幕绑定。
- **层是排布结果**：同一角色中的字幕时间相交时自动上下分层；不创造“叠加字幕”这一编辑类型。
- 每条字幕保留自己的稳定 ID、起止时间、文字、字词时间码、禁用状态、颜色／说话人、样式和来源。
- 配对字幕仍在一个列表卡片内呈现；两组重叠对话是两张卡片，不把同时出现的全部字幕挤进一个卡片。
- 不把显示层当成说话人。说话人着色、音色选择与层号互不替代。

### 3.2 波形中的操作

- 保留“允许字幕重叠”作为**是否允许新编辑产生交叠**的偏好；导入已有重叠字幕始终保留。关闭开关不隐藏、不删除、不压平已有内容。
- 新工程建议默认允许重叠；旧工程按原偏好迁移。旧 `overlay_track.enabled=false` 的隐藏语义需单独保存，不能直接套用新开关。
- 创建、拖动、改变边界、粘贴、素材插入后自动分层；拖动中预览落位，提交后一次撤销。
- 不要求拖到特定轨道才能重叠，垂直移动不改变主副角色。删除“转为叠加字幕／转回主字幕”的常规操作入口和 V叠 专用标签。
- 保留现有 V 选择、R 分割、Shift 多选、Ctrl/Cmd+Shift 时间选区、选区编辑工具及右键优先级。不新增与现有手势冲突的快捷键。
- 排布使用整条字幕的稳定分层结果，跨波形行时不跳层；拖动时优先保持原层，不随着细小时间变化反复闪动。
- 相邻边界联动仅在同一角色、同一显示层、两端共同高亮时生效。跨层边缘不能误联动。
- 字幕层数不套用音频的“三层”硬限制。首版采用自动增加所需行高、复用波形主滚动与虚拟渲染，不为每层再套小滚动条，不悄悄隐藏第四条字幕。

### 3.3 字幕列表、编辑器和播放反馈

- 列表按开始时间稳定排序，同起点用稳定次序；当前列表的主／副／多重显示、双排／双列卡片保持。
- 多条同时命中时，所有对应未选中卡片／块显示播放头描边；选择描边仍优先，另一半主副卡片保留现有虚线反馈。
- 字幕编辑器始终编辑明确选中的一条（或当前卡片的主／副一侧），不因播放头同时命中多条来回切换。
- 跟随播放每个时间点只选一个滚动锚点：优先当前命中的编辑对象，再按稳定排序取首条；其余条目只显示命中状态，不轮流抢滚动。
- 普通用户无需常驻层号；定位歧义时可在悬浮详情显示“主字幕 · 第 2 层”。层号是辅助信息，不进入字幕原文。

### 3.4 播放器与输出

- 默认“同时出现的字幕自动避让”，主副绑定作为排布单元，译文紧随对应原文；独立字幕另占一组位置。
- 复用已有字幕样式、主副预览框、字体、颜色和 ASS 样式库。时间线上下层不直接等于画面像素坐标。
- 在字幕显示设置中收纳排布顺序／组间距等少量选项；已有手动位置的工程保留位置，检测到碰撞再提供明确的自动排布选择，不能打开就改变旧片样式。
- ASS 和视频烧录落实一致的位置、层次、双语顺序与安全区；CSS 预览和 ASS 预览两种模式都要验证。
- SRT 可保留重叠时间，但不能承诺所有外部播放器按相同位置显示。保留普通时间版 SRT，并提供明确标注的“按同时显示合并文本”兼容导出；合并仅影响导出，不改工程。
- 禁用、旧叠加隐藏、导出主／副／双语范围与去空隙时间映射必须一致生效。OTIO 支持情况按实际可表达范围给出提示，不能声称任意层次无损往返。

## 4. 数据方案和兼容原则

建议保留现有主／副数组作为字幕真源，在统一访问层中使用 `{role, track_id, cue_id}` 身份；允许主、副各自的合法时间交叠。**不再另外复制一份“多层字幕正文”，避免保存和后台任务读到两份不一致的数据。**

- 视觉层是可重建派生数据，采用稳定区间分配；必要的固定次序／旧显示组设置放在独立呈现元数据，不能以层号替代 ID。
- 区间统一采用整数毫秒、半开区间 `[start,end)`；12 秒结束与12 秒开始不算重叠。帧吸附只是时间输入／显示方式，不另建一套时间真源。
- 所有合法条目均保持 `start < end`。只修复本条异常时间，不再通过上一条结尾“修复”合法重叠；字词时间码仍限制在所属条目内。
- 引入新工程版本（暂拟 `msw.project.v2`，阶段 A 完成前定稿），同步 Python、浏览器和生成器边界。现有 `.mosp` 后缀及关联 `.assets` 目录规则保持。
- 旧 v1／无版本工程只读入并在内存迁移，不因打开就写盘。首次保存升级必须保留旧版本副本；自动保存、恢复记录与另存为使用同一版本规则。
- 原 `overlay_track` 条目迁入主角色，保留 ID、时间、颜色、禁用状态、表情包、来源与原显示组。旧隐藏叠加组仍隐藏且可重新显示，不能直接启用或删除。
- 主／旧叠加 ID 碰撞时确定性重映射，批量更新配音素材 `source_ref`、贴片来源、绑定、待复核和候选记录。已在过去转换时丢失的绑定不猜测恢复。
- `headIdx` 分组引用迁移前物化／转为稳定引用，排序后不得变色或换表情包。
- 旧版兼容导出只对可表达内容开放；有三层以上等无法表达内容时列出具体限制，可选 SRT／ASS 或不改工程的文本合并。禁止静默截断成两层。
- 顶层版本、`msw.schema`、`multi_subtitle.schema` 分别管理；只有对应字段语义变化时才升级各自版本，不用一个版本标记代替全部校验。

## 5. ASR、翻译、TTS 与素材库契合

| 场景 | 新规则与保护 |
| --- | --- |
| ASR 整段／时间选区／所选贴片 | 继续先生成识别批次，不因允许重叠就直接写时间线；存入素材库始终可用 |
| ASR 覆盖范围内多条重叠字幕 | 采用具体字幕 ID 的目标快照；范围命中多个独立内容组且目标不明确时，在应用步骤展示将替换的条目并选择目标，不能只按时间删除所有层 |
| ASR 截断保留区外部分 | 对明确选中的目标集合执行；没有可靠字词时间码的区外片段保留原文并标记待校对，延续用户此前决定；其他层保留 |
| 翻译 | 按明确选择的字幕和角色生成批次，无选择不翻译全部；回填优先绑定 ID，不能用“时间最接近”把 A 的译文写到 B。存入素材库与候选编辑保持 |
| TTS | 所选主／副字幕不受视觉层限制；逐条冻结文字、原生参数、来源 ID。Mossland 跟随时长使用该条自己的长度，其他引擎保留原生语速参数 |
| 插入／重新生成音频贴片 | 字幕可以多层，音频仍受三层限制；超限结果留素材库并说明原因，不替换原贴片。保留原起点＋新完整时长规则 |
| 补齐字幕／外部音频对齐 | 首版继续默认跳过有字幕冲突的贴片并列原因，不因新层可用而偷偷重复补齐；是否“允许新增一层”作为后续可选扩展，不与本轮同时扩大行为 |
| 素材库字幕插入 | 从播放头开始保留相对时间；保留主副配对、颜色、来源，有交叠则正常分层；一批一次撤销 |
| 配音来源复核 | 仅视觉换层不算字幕发生改变；文字、时间或真实绑定变化按现有规则提示，避免素材库铺满无意义变动圆点 |
| 异步任务期间编辑／切工程 | 保留任务快照、目标修订检查、取消和迟到结果保护；视觉重排不应让任务误认为原字幕已删除 |

## 6. 分阶段实施与退出条件

### A：契约、查询与迁移设计

- 盘点“字幕不重叠”“只有一个命中”“数组下标可作身份”的假设，形成逐文件迁移清单。
- 定稿 v2、稳定身份、统一字幕访问器、区间索引和旧 V叠 迁移；呈现元数据与内容真源分离。
- 建立夹具：空字幕、单主、双语绑定、旧叠加开／关、同 ID 冲突、颜色／表情包组、配音来源、同时存在候选批次。
- 先实现纯函数和读取器／迁移测试；未完成写出和旧版保护前不启用新重叠编辑。
- 验收：迁移确定、可重复、无重复字幕，合法重叠不被修复，打开旧工程不改写原文件。

主要文件：`JSON_SCHEMA.md`、`maw/project.py`、`maw/project_io.py`、`maw/msw/project_codec.py`、`web/editor-utils.js`、`web/msw-project.js`，新增小型字幕查询／分层核心模块。

### B：统一编辑命令与波形分层

- 创建／拖动／缩放／拆分／合并／删除／粘贴统一通过字幕身份操作，替换跨轨移动的特殊逻辑。
- 实现稳定分层、跨波形行拖动、正确命中、多选、撤销及共享边界规则；移除日常 V叠 转换流程。
- 主／副互相绑定与“同时选中主副”的显式开关保留，换显示层不会改它们。
- 合并默认只处理同角色明确选中的条目；文字顺序、保留时间、绑定和来源变化先预览，不能把另一层字幕误吸收。
- 验收：双人重叠、三条以上重叠、跨行字幕都能独立选中，动作一次撤销，无无关条目时间变化。

主要文件：`web/editor.js`、`web/waveform.js`、`web/waveform.css`、统一查询／布局核心、`tests/e2e/overlay-track.spec.mjs` 和波形历史测试。

### C：字幕列表、编辑器与播放命中

- 列表／波形／编辑器共享选择身份，双语配对继续单卡片展示。
- 所有命中条目反馈播放头状态；只保留一个明确编辑目标和稳定跟随锚点。
- 保留本轮的跟随偏好、手动暂停、点击不居中和拆分过滤保护。
- 右键层级优先字幕块，再时间选区，再空白；支持各层翻译、TTS、复制到素材库。
- 验收：两组同时出现的双语字幕不串选、不闪烁、不抢滚动，主副实线／虚线与颜色规则一致。

主要文件：`web/editor.js`、`web/editor-template.html`、`web/editor.css`、`web/editor-i18n.js`；字幕卡片／滚动／键盘操作浏览器测试。

### D：处理面板与素材／配音关联

- 改造 ASR 的命中快照、部分截断、目标冲突选择；原识别／翻译批次布局保持紧凑。
- 翻译回填和 TTS 来源按 ID／角色匹配，支持来自所有显示层的正常选择。
- 素材复制与回插、原配方重新生成、配音对齐、变动标记接入统一查询。
- 验收：只处理明确选中的条目；异步编辑冲突能解释；音频三层限制仍有效，换字幕显示层不使素材失联。

主要文件：`web/msw-asr-core.js`、`web/msw-asr.js`、`web/msw-translation-core.js`、`web/msw-tts-core.js`、`web/msw-tts.js`、`web/msw-asset-core.js`、`web/msw-asset-library.js`、`web/msw-audio-actions-core.js` 及对应处理宿主；需核对服务端请求校验和来源快照。

### E：预览与导出一致性

- 同步 CSS／ASS 预览、多条主副自动排布、样式继承与旧工程位置保留。
- 更新 ASS／SRT／视频烧录以及去空隙导出映射；音频混音策略保持独立。
- 核对表情包、说话人名称着色、禁用字幕和导出尾部范围；纯音频／空媒体项目仍可编辑字幕和配音。
- 验收：用同一夹具比对编辑器预览、ASS 和烧录帧；端点相接不多出一帧，双语不串组，不静默丢层。

主要文件：`web/msw-subtitle-style.js`、`web/msw-audio-export.js`、`maw/msw/subtitle_style.py`、`maw/msw/subtitle_export.py`、`maw/msw/timeline_export.py`，现有 ASS／样式／导出测试。

### F：保存、启动器、恢复与性能整合

- 全面贯通打开、导入、另存为、自动保存、恢复、便携 HTML、Launcher 打开与预制工程处理。
- 原 `.assets` 路径与音频哈希保持，处理失败不得留下半迁移的正式工程。
- 启动器对于尚未适配多层的模块明确拒绝或按明确内容组处理，不能经后处理自动抹平重叠。
- 更新帮助、快捷键说明与版本变更，验证旧版兼容导出和失败回退。
- 性能用 1,000／10,000 条字幕以及 2／4／8 层场景评测：播放只查询当前区间，拖动局部重排，不每帧全项目排序；预算以现有项目实测作基准，不凭空宣称零开销。
- 验收：保存重载、撤销重做、复制项目和后台任务并行时数据不丢；滚动与拖动达到当前单层体验可接受水平。

主要文件：`edit.py`、`server-editor/serve.py`、`maw/project_io.py`、`maw/msw/project_codec.py`，以及具体 Launcher 后处理入口；不重新设计启动器布局。

### G：生产回归与启用

- 回归完整路径：导入视频 → 局部 ASR → 叠加另一段字幕 → 翻译 → 多引擎 TTS → 插入贴片 → 补齐／修改 → 保存恢复 → 导出。
- 必测：批次运行时删字幕／移时间／切工程，取消与重试，旧 V叠 隐藏工程，中文／英文／混合文本，无字词时间码、同起点、跨行、空字幕与禁用条目。
- 预览截图和烧录抽帧均使用合成夹具；外部服务与真实音质测试单列，不能用模拟服务结果冒充供应商验证。
- 新版结构正式开放前，A–F 的功能闭环必须完成；不发布“时间线上能重叠，但翻译／保存会丢层”的半成品。
- 按维护者要求提交、推送；本计划不包含自动发布 Release。

## 7. 建议执行批次与决策点

建议按 **A → B+C → D → E → F+G** 执行。A 可以单独完成并评审迁移夹具；B+C 之后可以体验交互，但在保存和处理链路闭环前仍作为开发状态。

本计划采用的推荐默认值：新工程允许重叠、自动分层、不限制字幕为三层、主副绑定作为预览排布单元、补齐字幕继续跳过冲突。若要修改这些产品方向，应在 A 阶段确定；它们本轮都未落入实际产品。

A 阶段必须明确的技术决策：新版本标识、旧工程第一次保存的备份命名和恢复策略、旧隐藏叠加组的呈现元数据，以及对不能表达多层的旧格式如何明确拒绝。B 阶段用实测确定高密度多层的最小可读高度；D 阶段用多说话人夹具审查 ASR 目标选择界面。

完成标准是 MSWE 的编辑、处理、素材、保存和导出使用同一套字幕身份与时间规则。上游实现只作为需要逐项审查的参考，不直接搬入其轨道结构、手势或限制。
