# 启动器混合输入与模块配置修缮计划

日期：2026-09-21。MSW 基线：`my-feature` / `de20723`。初稿仅核实与规划；2026-09-21 已按授权完成 A+B，详见 [实施记录](IMPLEMENT_LAUNCHER_AB_20260921.md)。

上游对照：本地 `upstream/main` 的 `42656d8`（2026-09-20，v1.6.0-beta.6），重点对照旧工具箱的 LLM、文稿匹配和波形配置。已浏览上游仓库；网页源码读取失败的部分采用上述本地快照，不将其声称为实时远端最新版。

本计划承接此前启动器改造，保留五页导航、项目卡片与分页、右侧工具/设置选择、黑色与低饱和紫色主题。此前已修复的工程登记污染、封面、图钉等问题不作为本轮新发现重复列入。

## 1. 已确认的方向与需要修正的理解

用户诉求整体合理。当前主要问题是：界面已拆成模块，但部分配置、状态和执行入口仍依赖旧的单文件/批量、媒体/工程分支。本轮应统一任务与配置数据，再调整界面，避免继续把旧控件搬进新卡片。

| 事项 | 结论与实施口径 |
| --- | --- |
| 输入模块改名 | 左侧使用“输入媒体/工程/字幕”；右侧使用“选择文件”。输入模块保持必选。 |
| 虚线框与队列 | 采用。虚线框同时支持拖入和点击多选；移除输入模块原有的路径输入框、选择按钮、添加文件按钮和模式切换。文件路径、多音轨、关联等放入队列条目详情。 |
| 自动切换单文件/批量 | 不再让用户选择模式。显示结构随任务数自然变化，使用同一执行入口。 |
| 同名视频和字幕 | **已由用户确认：先识别为关联候选，确认后作为一个工程任务处理。** 不自动合并，也不根据文件名覆盖现有字幕。 |
| 文件数与任务数 | 两个已关联文件可以组成一个任务，因此显示“2 个文件 · 1 个任务”；批量进度按任务计数。界面自动变化仍符合用户意图，不能简单按文件数调用旧批量入口。 |
| 默认折叠 | 输入展开；其他模块首次显示时折叠。折叠与是否启用完全独立，不能折叠后停止执行。 |
| SRT 下方输入框 | 是 `srtPath`，用于 SRT 输出路径/识别产物命名锚点，有实际用途。应删除当前无标签的表现形式，保留明确的自定义输出能力。 |
| 频谱开关 | “生成频谱颜色数据”对应原来的“生成 reapeaks 频谱数据”。建议名称统一为“生成频谱颜色数据（ReaPeaks）”。 |
| 独立波形工具 | 恢复并增强，加入已有工程缓存补全能力。它属于工程辅助工具；与预制工程模块共享处理能力，使用独立输入。 |
| 长说明收纳 | 使用选项名称后的 ⓘ；错误、缺少配置、当前执行进度不藏入提示。实际处理日志继续放在日志模块。 |

## 2. 本轮核实结果

“代码确认”表示从当前实现可确定；“浏览器确认”表示在临时 Chromium 的启动器演示页核实，未调用真实服务。下表的功能调整均为待处理。

| 编号 | 优先级 | 发现 | 证据与影响 |
| --- | --- | --- | --- |
| F01 | P1 | 输入与执行仍分裂 | `workflow.js` 保存媒体/工程模式；`batch.js` 保存单文件/批量模式且只接受媒体。混合文件不能仅靠扩大文件选择过滤器实现。 |
| F02 | P1 | 批量不支持工程/字幕，文稿匹配被跳过 | `batch.js:startBatch()` 拒绝工程输入；`launcher_batch.py:_batch_postprocess_plan()` 禁用 match 步骤。新增文件不应导致原本配置的文稿匹配悄悄失效。 |
| F03 | P2 | Markdown 文案丢失 | 浏览器实际显示 `toolbox_clean_markdown_symbols` 和对应 hint 键名。HTML 有中文兜底，但语言渲染用缺失翻译键覆盖了它。 |
| F04 | P1 | 翻译配置分布不合理 | 浏览器可见双语、回填与目标选项；供应商选择不在翻译卡片，只有服务摘要。不能笼统判定回填功能已被删除，应重排现有能力并恢复本模块调用选择。 |
| F05 | P2 | 缺少明确的预设提示词区域 | 上游有只读预设提示词展示；当前卡片主要展示追加提示词，预设摘要挤在旧启用行，易被理解为用户必须自己写提示词。 |
| F06 | P2 | 重复开关与重复状态 | 六个后处理卡片仍含 `autoStep*` 启用行、状态和长摘要；右侧已有开关，卡头已有摘要。 |
| F07 | P2 | 折叠默认值不一致 | 浏览器中输入、波形、文稿匹配、翻译、输出均默认展开；日志才有专门的默认折叠逻辑。 |
| F08 | P1 | 输出隐藏值仍可能生效 | `plan.js:build()` 在输出模块关闭时仍读取 `srtPath`；其他输出草稿则被排除。输入框既然已放入输出模块，生效规则也应一起迁移。 |
| F09 | P1 | “原文 SRT”名称与发布逻辑存在冲突 | `postprocess_pipeline.py` 将处理链的 `current_srt` 传入 `_publish_final()`；双语合并/回填会改变该文件内容。因此当前“导出原文 SRT”不能在所有模式下保证导出翻译前原文。需用隔离夹具验证各分支并修正。 |
| F10 | P1 | 单独对已有工程补波形的路径缺失 | 当前 `_generate_media_project_sync()` 从媒体建立 `segments: []` 的新工程；不能直接拿来更新用户已有工程，否则会丢字幕和扩展数据。 |
| F11 | P1 | 输入适用性判断过粗 | `plan.js` 与 `gui_web.py:run_prefab_plan()` 拒绝“字幕输入 + OCR”，即使 OCR 卡片说明允许另选视频；工程输入无后处理步骤也直接被拒绝，无法用于只补缓存。 |
| F12 | P2 | 全流程设置放错卡片 | `autoPostprocessRetain`“保留中间产物”在翻译卡片内，却影响整个后处理流程；关闭翻译时难以理解或配置。 |
| F13 | P2 | 服务选择与环境配置耦合 | 当前前端给校对、断句、翻译写入同一个 `providerId`；后端步骤结构本已支持逐步骤 provider。设置页还有同步的供应商选择器，应分清“编辑哪家环境配置”和“本次调用哪家”。 |

补充核实：

- 基础波形与频谱是不同能力。`media_cache.py:embed_media_caches()` 关闭 `generate_spectral` 后，仍生成 ReaPeaks 波形层，跳过 FFT 与工程内 `spectral` 数据；不是关闭所有波形。
- 当前“未配置的模块保留勾选、开始前校验”已有实现和用例。保留这项行为，不照搬源码中遗留的“强制取消勾选”旧注释。
- 当前语言设置分组中的“显示相对小众的语言”控制 ASR 语种列表，不是启动器界面语言，迁移时必须分别命名。

## 3. 混合文件输入与任务组织

### 3.1 输入卡片

卡片内只保留拖入区和文件队列。无文件时拖入区较高；添加文件后收紧高度，保持可继续点击/拖入。提示文案简洁，例如“拖入媒体、工程或字幕，或点击选择文件”。

队列内容：

- 文件类型图标、名称、简短来源、状态、移除按钮；文件图标沿用现有 SVG 体系。
- 下层详情按需展开：完整路径、音轨、已关联媒体/字幕、文稿、问题定位。单音轨文件不额外展开选择器。
- 队列内显示文件数、任务数及清空入口；“移除”仅移出待处理队列，不删除源文件。
- 状态至少覆盖：读取中、待确认关联、待配置、可处理、处理中、完成、失败、已取消。
- 文件增加或删除时不清空其他模块参数，不重新挂载所有表单，不重置滚动位置。

优先支持当前已有类型：音频/视频、`.mosp`、兼容的工程 `.json`、`.srt`、`.ass`。扩展名只是初筛，工程 JSON 需验证结构，不能把任意 JSON 当作工程。ASS 导入的样式保留能力沿用实际解析器，并在不保留样式时明确提示。文稿 `.txt/.md` 继续由文稿匹配模块选择，不误判为带时间字幕。

文件选择器与原生拖入共用同一校验管线；不支持、重复、损坏或不可读的条目显示具体原因。规范化路径后去重，同名但不同目录不直接视为同一个文件。不新增全盘或递归目录扫描。

### 3.2 关联候选

1. 同目录且主文件名相同的媒体与字幕优先提出候选，如 `lesson.mp4 + lesson.srt`。
2. 展示候选中的完整文件身份及“关联为一个任务 / 分别处理”，由用户确认。
3. 确认后以一组展示，可展开看两个源文件，并可解除关联；进度按一个任务计算。
4. 多份同名字幕、多段视频、已有工程再附字幕等情况不猜测覆盖关系，提示选择来源或分别处理。
5. 工程本身已有媒体引用时，以工程引用为初始事实；拖入同名视频可以建议重新关联，不擅自替换媒体。
6. 候选未处理前不启动该任务。用户可先移除不想处理的候选，避免把同一组文件识别成两个付费任务。

### 3.3 按输入能力决定模块是否适用

| 输入/条件 | 波形 | ASR | 字幕整理与翻译 | OCR 去重 |
| --- | --- | --- | --- | --- |
| 仅音频/视频 | 有音轨时可生成 | 可按选择识别 | 需 ASR 先产生字幕 | 需视频与字幕，纯音频还需关联视频 |
| 工程 | 源媒体可用时补全/重建 | 源音频可用时允许重新识别 | 有字幕即可处理 | 需可用视频和字幕 |
| 仅字幕 | 未关联音频时不适用 | 未关联音频时不适用 | 可直接处理，也可包装为新工程 | 允许显式关联视频后处理 |
| 已确认的媒体 + 字幕 | 可生成 | 默认使用已有字幕；重识别须明确选择 | 直接使用关联字幕 | 视频与字幕均可用时处理 |

右侧仍选择本批需要的模块；预检为每个任务计算“执行 / 不适用 / 缺少条件”。“不适用”须显示原因；用户明确选择的处理步骤缺少必要输入时，不得静默跳过。

ASR 模块对已有字幕提供明确策略：“仅识别没有字幕的任务”（建议默认）与“重新识别”。重识别作用于新派生工程，保留原文件；不因为加入第二个文件而自动启动 ASR。

文稿匹配增加逐任务映射。单任务直接选择文稿；多任务在模块中列出“任务—文稿”紧凑映射表。可以提出同名候选，但需确认；不默认将一篇文稿套给所有媒体。缺文稿定位到对应任务，不再使用“批量统一跳过”的旧规则。

### 3.4 统一执行与持久化

- 建议引入带版本的队列方案：文件列表、确认后的关联、任务列表、模块参数、输出策略。任务保存稳定 ID、媒体/字幕/工程来源、音轨与文稿等局部参数。
- 单任务和多任务采用同一预检、执行事件和结果结构；保留现有 ASR、媒体建工程、后处理作为内部适配器，逐步收敛重复分支。
- 开始后冻结本次方案。处理中更改配置不能影响已开始或后续排队任务；本轮先锁定当前队列编辑，取消完成后可修改。
- 初期沿用顺序执行，任务失败与其他任务隔离；支持取消队列、重试失败项，已完成项不默认重新识别。
- 统一互斥控制，避免预制工程、波形工具与旧批处理线程同时写同一目标；任务事件必须带任务 ID，忽略旧任务迟到事件。
- 迁移旧单文件/批量草稿、模块启用值、提示词和输出偏好；旧模式只作为迁移输入，不再决定新执行分支。
- 文件数量增加只改变队列与进度展示，不改变处理意义、输出策略或文稿映射。

## 4. 模块卡片与配置完整性

### 4.1 通用规则

- 右栏为唯一启用入口。卡片头显示“折叠箭头 · 序号 · 模块名 · 参数摘要 · 状态”，移除卡片体重复的启用、需要配置和摘要行。
- 保留稳定模块 ID；界面排序、序号、处理摘要来自同一注册表。按输入、波形、ASR、文稿匹配、固定处理、校对、断句、OCR、翻译、输出、人工对齐、日志的当前逻辑顺序展示；日志始终最后。输出/日志/人工入口不伪装成自动字幕处理步骤。
- 输入默认展开，其余默认折叠。当前会话手动展开后不被重渲染收起；新会话采用新默认，不继续恢复旧版“全部展开”的折叠记录。保留各模块配置值。
- 开始前校验失败时，只展开并定位首个有问题的模块；卡头汇总其余错误。普通选中模块不强制滚动或跳转设置。
- 卡头摘要反映真实配置，例如“中文 · 副字幕 · DeepSeek”，不能用摘要截断来替代必需配置。
- 小控件在宽卡片中双列排列；路径、规则文本、提示词、任务映射与预览占整行。窄窗口自动单列，保持标签与控件一一对应。
- 删除旧启用 DOM 前，先把序列化和事件绑定改为读取方案状态；不能仅用 CSS 隐藏旧开关，让两个真源继续互相同步。

### 4.2 各模块保留与调整清单

| 模块 | 卡片内的调用/处理参数 | 放在更多设置的长期配置 |
| --- | --- | --- |
| 输入媒体/工程/字幕 | 拖入区、队列、任务关联、逐任务音轨和来源详情 | 默认文件位置等通用偏好 |
| 波形生成 | 频谱开关；优先复用有效缓存/重新生成；当前来源与音轨摘要 | 工具环境、缓存目录等 |
| 识别设置 | 服务、模型、语言、说话人区分及服务支持的调用参数；已有字幕策略 | API Key、地域、Workspace ID、服务地址等 |
| 文稿匹配 | 文稿/逐任务映射、换行来源、清理 Markdown、原文和拆分预览 | 断句与保留符号默认值 |
| 固定处理 | 替换规则、分隔符、自定义分隔符、空白处理、简繁转换、规则预览 | 通用默认值；不把实际本次规则藏入设置 |
| LLM 校对 | 供应商、当前模型、预设提示词、追加提示词 | 供应商连接、凭证与默认模型 |
| 重新断句 | 供应商、当前模型、预设提示词、追加提示词；时间处理说明 ⓘ | 供应商连接与长期默认值 |
| OCR 字幕去重 | 视频来源/逐任务绑定、模型、区域、阈值、报告输出 | OCR 运行环境、模型安装 |
| 翻译 | 供应商、当前模型、目标语言、译文写入方式、必要时双语行序、预设/追加提示词 | 供应商连接、凭证与默认模型 |
| 输出 | 工程或仅 SRT、原文/译文/必要时双语输出、位置、名称、产物预览 | 默认目录组织与命名偏好 |
| 人工口播对齐 | 对选定任务的入口与简短用途说明 | 原工具环境配置 |
| 处理日志 | 当前任务/整批运行日志、复制或导出诊断 | 默认诊断保留策略 |

“保留中间产物”迁移到更多设置的“缓存与诊断”，作为流程级偏好；失败和取消所需的恢复记录按既有规则保留。日志模块关闭只控制是否展示，不停止必要的状态收集和错误报告。

### 4.3 翻译与 LLM 参数

翻译卡片建议布局：

```text
供应商 [下拉]                  模型 [当前模型/可选项]
翻译目标 [中文/英文]           译文写入 [下拉]
双语行序 [译文在上/原文在上]    ← 仅合并双语时出现
预设提示词 [任务名称] [查看]
追加提示词 ⓘ
[可选文本输入，整行]
```

“译文写入”统一为互斥的三种模式，避免删掉 MSW 已有副字幕能力：

1. **生成副字幕**：保留原文主字幕，译文成为副字幕；建议作为默认，兼容现有两个复选框均关闭的含义。
2. **翻译回填**：译文替换对应主字幕文本，保留既有副轨、配音和其他工程数据。
3. **合并双语字幕**：在同一字幕条目内合并两种语言；此时才显示双语行序。这里的双语行序不同于编辑器主/副字幕列表的双列/双排显示。

已有副字幕遇到新翻译时，预检明确显示会更新哪部分；沿用工程副轨契约，保留非目标副轨及音频素材。新结果默认写派生工程。

校对、断句、翻译分别选择供应商；迁移时把原共用值复制为各模块初始值。更多设置中切换“正在配置的供应商”不应改变已保存的调用选择。模型优先读取对应供应商的已保存配置；如提供本次模型覆盖，必须显式写入该步骤请求，不能偷偷改全局默认模型。

“预设提示词”标题常驻，显示当前任务名；点击查看展开只读内容。“追加提示词”单独可编辑，标明可选。默认内容应与实际提交给后端的任务模板一致，目标语言变化时同步更新，不能只是旧 UI 文案的副本。

本轮保留已支持的中文/英文目标，不用无能力校验的任意语言输入扩大范围。后续若扩语言，应同时调整后端目标验证与提示词。

### 4.4 Markdown 与 OCR

- 补齐中文/英文翻译键，并检查同类缺失键；语言渲染缺键时保留有效兜底文案，开发校验中报告缺键，正式界面不显示键名。
- “自动清理 Markdown 符号”的 ⓘ 只描述实际支持的行内格式，如粗体、斜体、删除线、行内代码和高亮标记；不夸大为完整 Markdown 文档渲染。
- 预览使用与最终文稿匹配相同的清理函数，切换选项即时更新预览，不改源文稿。
- OCR 校验根据实际关联的视频与字幕判断，修复“字幕输入一律拒绝”与卡片说明相矛盾的逻辑；队列中每个任务有自己的视频来源。
- 检查迁移卡片的 HTML 分组层级、标签和错误定位，避免旧 `adv-group` 嵌套造成不一致缩进。

## 5. 输出模块

### 5.1 控件与命名

- “只生成 SRT 字幕”移入输出模块，统一作用于单任务和多任务，默认关闭；启用后不发布最终工程，不显示“打开刚生成的工程”。内部必要的临时工程不属于用户产物。
- 输出模块关闭时沿用已约定的默认输出策略，动作区以简短摘要显示预计产物；该模块内隐藏的自定义路径与开关草稿不进入本次执行。
- 移除原文 SRT 下面无标签输入框。改为“保存位置”及自动命名预览；“自定义 SRT 位置”按需展开，给出完整标签。
- 单任务允许指定完整 SRT 路径；多任务选择输出目录与命名规则，不能让多个任务共享一个 SRT 文件路径。
- 勾选仅 SRT 时，至少选择一种可产出的 SRT；不满足时就地校验。没有字幕来源且未启用 ASR，不能生成空的“成功”字幕文件。
- 只输出 SRT 时波形缓存不是必要步骤，应显示不适用原因，不额外生成无去处的缓存。取消该输出模式后恢复波形草稿，不清空用户配置。

### 5.2 区分原文、译文与双语成品

建议明确为：

| 输出项 | 文件内容 | 出现条件 |
| --- | --- | --- |
| 工程 | 完整工程，以翻译模块选定的方式写入字幕 | 未勾选仅 SRT |
| 原文 SRT | 文稿匹配、固定处理、校对、断句、OCR 后，翻译之前的字幕 | 有字幕来源；独立可选 |
| 译文 SRT | 对应目标语言的翻译内容 | 启用翻译；独立可选 |
| 双语 SRT | 按所选行序合并的原文与译文 | 翻译选择合并双语时按需导出；明确命名，不冒充原文 |

双语 SRT 是对现有合并结果的清晰归类，不是新增一套翻译流程。旧配置中勾选原文并使用双语合并的情况需迁移提示，避免升级后看似相同的选项悄悄改变成品含义。

发布层分别保留翻译前快照、独立译文与最终合并结果引用；不再通过一个 `current_srt` 推断所有文件。没有后处理、只有翻译、回填、合并双语、仅 SRT 与断点恢复均使用同一输出解析器。

发布前统一分配目标路径，处理输入同名、不同目录同名、原文/译文同名、已存在结果和并行写入冲突。默认生成新的派生文件，按稳定规则追加序号，不能覆盖输入工程/字幕。迁移工程位置时复用现有素材复制与相对路径逻辑。

## 6. 波形模块与独立工具

### 6.1 预制工程内

- 说明“波形”与“频谱颜色”的区别，长说明放到 ⓘ；生成算法/缓存数据与编辑器的波形配色方案分开，不在启动器重复建设主题设置。
- 基础波形沿用当前原生波形与 ReaPeaks 缓存生成链；频谱开关只决定是否额外计算并写入频谱颜色数据。
- 音轨来自任务输入；改变音轨后重新校验缓存，不误用其他音轨的峰值。
- 默认复用有效缓存；需要重建时显式选择。失效依据包括真实源媒体身份、音轨和缓存版本，不能只比文件名。

### 6.2 实用工具中的“生成波形”

右侧新增“工程辅助”分类和“生成波形”工具；左侧直接配置，不弹旧工具箱。

| 工具输入 | 操作 | 结果 |
| --- | --- | --- |
| 媒体 | 生成基础波形，可附加频谱 | 无字幕媒体工程，完成后可打开编辑器 |
| 已有工程 | 读取其媒体/音轨，补全或重建缓存 | 保留完整工程内容的派生工程；如提供原位更新，必须明确选中并采用原子写入 |
| 已有工程但媒体失联 | 选择重新关联媒体后生成 | 写入目标前验证媒体与音轨；未关联成功不能假报成功 |

工具自有输入、进度、取消和结果入口，不依赖预制工程队列中的“当前媒体”。与预制模块共享缓存服务，避免两个开关各自实现一套算法。

更新已有工程必须保留：主副字幕与颜色、事件码、音频贴片、素材库、TTS 配方、ASR 元信息、时间选区和其他扩展字段。只更改必要的缓存、关联媒体及缓存身份字段。生成失败不破坏已有有效缓存；改换来源时不能把旧缓存标成新来源。

单纯关闭“生成频谱”不应删除已有且仍有效的频谱；显式重建时按新来源处理。缓存生成完成但频谱失败要明确报告部分成功。

## 7. 语言、导航与说明收纳

### 7.1 更多设置

- 右上角移除界面语言切换；“更多设置 → 外观与语言”内增加“界面语言：简体中文 / English”，复用原保存与切换机制。
- 保留主题选择；将“显示相对小众的语言”明确标为“识别语言列表”，与界面语言区分。
- 切换语言不得重置模块、队列、调用服务、提示词或折叠状态；同步更新动态状态、提示图标内容与右栏分类。
- 设置页只保留一套供应商环境编辑器，供应商选择器用于编辑配置；当前任务供应商由模块自身选择。

### 7.2 统一视觉与双列布局

- 工具分类标题与选项建立层级：分类沿主基线，选项文字建议缩进一个 12px 层级；分类间距大于选项间距。设置分类采用相同规则。
- 保持与现有编辑器/启动器相同的字体、圆角、控件高度、描边和 SVG 图标；复用主题变量，不新增蓝色底板、表情符号或另一套卡片体系。
- 卡片内采用既有间距 token；建议字段间距 12–16px，组间距 16–24px。以实际字体、缩放和长中文标签验收，不为追求密度压缩点击区域。
- 双列只用于可并列理解的选择项；避免长路径、日志、提示词被硬挤成两列。
- 收展采用短过渡并尊重减少动态效果设置；不因运行状态更新不断改变卡片高度或滚动位置。

### 7.3 ⓘ 的使用范围

可收纳：输入格式详细规则、缓存说明、语言模型注意事项、替换分隔示例、OCR 算法说明、输出文件命名解释、工具参数长解释。

保持可见：必填项、无凭证/模型未安装、输入失联、覆盖影响、任务失败、当前保存位置和执行进度。复杂配置不是注释，不能收到提示里。

提示图标紧随名称，支持鼠标、点击和键盘聚焦；Esc/点击外部关闭，避免被卡片裁切。较长内容采用有宽度上限、可换行的浮层，而不是只用原生 `title`。可共享编辑器的交互规范，但启动器保持独立可加载。

## 9. 验收矩阵

### 9.1 输入与执行

1. 空队列禁用制作；单文件增加第二个文件自动出现批量进度，删回一个任务恢复简洁展示，配置不丢失。
2. 同名媒体+字幕只有确认后合并；分别处理、解除关联、多候选、重复拖入和大小写扩展名行为明确。
3. 同时输入媒体、工程、SRT、ASS，各按实际能力执行；损坏工程、未知 JSON、丢失媒体、无音轨视频有具体错误。
4. 已有字幕且 ASR 默认策略为“仅缺字幕”时不额外识别；选择重识别时清晰显示受影响任务。
5. 单/多任务文稿匹配使用各自文稿；添加文件不使步骤跳过，不把错误文稿批量套用。
6. 单任务失败、取消、重试、迟到事件、切换页面以及重新打开启动器后的草稿恢复一致。
7. 工程仅补波形、字幕仅包装工程、字幕显式关联视频后 OCR 均有有效处理路径。

### 9.2 输出与工程保真

1. 在原文/译文容易区分的夹具中验证副字幕、回填、双语两种行序；逐个检查 SRT 实际内容，不只检查文件存在。
2. 原文、译文分别勾选、都勾选、都不勾选、仅 SRT、无翻译、翻译失败、断点恢复均满足产物约束。
3. 输出模块关闭时不采用其隐藏自定义草稿；同名源文件批量输出不碰撞，不覆盖源文件。
4. 有字幕、着色、副轨、贴片、素材和 TTS 配方的工程补波形前后做字段比较；仅预期缓存字段变化。
5. 原生波形、ReaPeaks 波形层、频谱分别验证；非默认音轨、复用缓存、重建、取消与部分失败均报告准确。
6. 生成新工程后的登记、卡片排序、媒体封面、打开编辑器和素材路径解析继续通过已有回归。

### 9.3 界面与原生宿主

1. 中文/英文、亮色/暗色、1280×800 与 1440×900、窄窗抽屉、125%/150% 缩放；无横向溢出、裁切和悬浮层被遮挡。
2. 键盘能进入拖入框并唤起选择、操作候选、折叠卡片、访问 ⓘ、关闭浮层；状态不只依赖颜色。
3. 翻译选择非合并模式时不显示双语行序；切回合并模式保留先前行序；不同模块服务选择互不串改。
4. 提取音频、压制字幕、媒体重组、口播对齐及更多设置回归，输入区重构不能破坏它们的独立输入。
5. Windows 原生 pywebview 的多选/拖入、特殊字符路径、网络/不可读路径、窗口重新打开另行验证。浏览器演示页通过不等于原生桥接通过。

实现阶段按影响运行现有 Python 单元/契约测试、JS 检查和对应 Playwright 用例。修改 `web/` 后遵守仓库要求运行 `uv run python edit.py --blank` 并检查生成产物。所有带后端的测试隔离应用数据、工程索引、缓存和配置，不使用真实个人设置。
