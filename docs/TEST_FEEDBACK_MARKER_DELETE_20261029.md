## 原因与处理

- v4 保存校验会拒绝指向不存在标记头、自引用、标记名称不一致或同时含头和引用的数据。
- 普通编辑器仍使用操作视图中的 `headIdx`。主列删除维护了组关系，但联动删除另一列时直接 `splice`，未执行标记头晋升和引用下标平移；独立副列删除也存在同类路径。浏览器已复现确认，切分本身可保存，删除后校验失败。
- `web/editor.js` 两侧删除共用 `removeSegmentsWithGroupReferences`，只重新分配受删除影响的标记组；用旧下标到新下标的映射更新全部剩余引用，不再反复扫描删除下标。保留严格保存校验，不通过放宽校验掩盖问题。
- 专项覆盖从任一侧切分后删除前半段、独立副列标记头晋升及后续组下标平移、绑定与独立混合多选删除、绑定伙伴锁定保护、一次撤销重做、实际接口保存与重开。均使用合成工程，不修改用户工程。
