## 1. 结论、已确认决定与范围

目前横向布局、真实封面服务、黑紫配色和部分执行流程已有改善。这轮的重点是完成页面内配置迁移、建立完整工程目录、修复菜单及导航交互，并让预制选项真正贯穿执行和输出。上一轮的 HTML 层级错位等问题不直接照搬为当前故障。

## 3. 已复现的根因及新增检查结果

### 3.1 项目卡片右键为什么间歇失灵

位置：`web/launcher/project-home.js` 的 `openMenu()` / `closeMenu()`。

当前每次打开菜单都会延迟注册文档级 `click`、`contextmenu` 监听。关闭只删除菜单 DOM，没有移除旧监听或取消待注册的定时器。下次右键创建新菜单后，旧监听仍处理同一次冒泡事件，调用全局 `closeMenu()`，把新菜单一起关闭。

本轮真实点击结果：同一张卡连续六次右键，菜单数量为 **1、0、0、0、0、0**。因此不是只能“偶尔看到”的猜测。

另开全新页面检查 Esc：菜单打开前后数量均为 1，焦点仍在卡片。菜单自己的键盘监听没有接收到 Esc。

修正细节：

- 一个菜单实例维护自己的目标工程 ID、DOM、关闭监听、定时器和焦点来源；关闭时完整释放。
- 再次右键同卡或另一张卡，替换菜单并更新目标；旧事件不能关闭新实例。
- 使用稳定事件委托；封面、工程名、徽标、卡片空白处的右键行为一致。
- 菜单提供打开、固定/取消固定、所在文件夹、刷新封面、重新定位等适用操作；“从记录移除”和“移入回收站”按分组明确区分。
- 支持 Esc、方向键、Enter、Shift+F10；打开时正确转移焦点，关闭后返回原卡片。
- 空白点击、切页、滚动、窗口失焦及工程被移除时按统一规则关闭；页面刷新不得将菜单操作应用到另一工程。
- 菜单坐标兼容应用缩放、系统缩放和屏幕边缘；键盘唤起按卡片定位，不依赖鼠标坐标。

### 3.2 左导航偏移和动效问题

位置：`web/launcher/launcher.css` 的 `.nav-item-label`、`.nav-item`、`.app-nav-inner`。

文字只设置了 `opacity: 0`，仍占据 flex 布局；在 64px 栏内将图标挤向左边。悬浮展开时布局又切换到另一套对齐方式，图标从 x=8px 移到 x=20px，形成肉眼可见的跳动。

建议保留现有“紧凑导航＋悬浮展开”，但使用固定图标列，让展开仅影响文字和背景宽度。折叠态图标以 64px 栏中心为基准，展开后横坐标保持不变。活动背景、图标、提示点和页脚使用同一栅格。展开约 160～180ms，文字淡入更短；遵循系统减少动态效果偏好。

### 3.3 ASR 分支仍遗漏波形开关

位置：`web/launcher/launcher.js:startTranscription()` / `formPayload()`，`maw/gui_web.py` 的请求构造，`maw/gui_workflow.py:TranscriptionRequest`。

浏览器确认：开启 ASR、关闭波形后仍调用旧 `start_transcription` 载荷，其中没有波形开关；后端 `generate_waveform` 默认值仍为 true。无 ASR 的媒体制作分支已经传入该开关，不能因这一路通过便认为所有流程一致。

修正要求：单文件 ASR、无 ASR、已有工程再处理和批量必须消费同一个冻结方案。至少逐项验证波形开关、源音轨、频谱、后处理参数、输出路径和结果登记。不要只在前端增加一个同名字段而不检查后端是否读取。

## 4. 实用工具与更多设置：统一右侧分类模式

### 4.1 公共页面框架

这两页采用右侧选择、左侧配置，比“卡片 → 工具箱 → 工具标签”的多层路径更适合当前启动器。

```text
应用主导航 │ 左侧：所选工具/设置的标题、字段与结果 │ 右侧：分类列表
           │                                      │ 当前项高亮
           └──── 状态、必要的保存/执行操作 ─────────┘
```

- 工具与设置右栏是**单选导航**，使用活动描边/背景，不使用复选框。
- 预制右栏是**多选处理模块**，保留复选框；框架一致不等于交互语义相同。
- 右栏宽度、分组标题、行高、选中反馈与预制栏对齐；内容宽度不足时变成同款右侧抽屉。
- 切换只切可见面板，保留每个工具草稿；运行中的任务继续，状态在页脚显示，不能切换后丢失取消入口。
- 设置分组记忆上次访问位置；跨页配置跳转保留返回来源、滚动位置与字段草稿。
- 页头不堆解释。每个工具只保留一句目的说明，细节放在字段帮助或折叠高级选项。

### 4.2 工具内容

| 工具 | 左侧内容 | 操作与输出 |
| --- | --- | --- |
| 提取音频 | 输入文件、音轨列表、输出位置、现有支持的格式参数 | 提取、取消、打开输出文件/目录 |
| 压制字幕 | 视频、SRT/ASS、已有压制参数、输出文件 | 制作视频，保留源文件；不假装包含编辑器贴片混音 |
| 媒体重组 | FFconcat 清单、解析/输入摘要、输出文件 | 重组与结果；给出实际输入错误 |
| 口播对齐快捷入口 | 不再维护另一份输入或参数表单 | 定位到预制页的同一口播对齐模块，必要时带入工程引用 |

口播对齐会制作工程，主入口放在预制页更符合工具分类原则；若保留实用工具快捷项，必须直达同一页面卡片，不能再弹旧工具箱。波形生成、文稿匹配和字幕处理也只保留对应预制模块。

提取等工具默认保留各自输入；需要复用当前媒体时提供明确的“使用当前媒体”，避免随着预制页切换悄悄改变正在配置的工具对象。

### 4.3 设置分类

建议右栏分为：外观与语言、服务与连接、处理默认值、文件与输出、工具与运行环境、编辑器启动、缓存与诊断。

- 服务与连接保存地域、Workspace ID、API Key、Base URL 等低频配置。
- 模型、语言、提示词、断句参数等本次调用内容放在预制模块；设置中只保留其默认值。
- 更新默认值不覆盖当前方案；需要时提供明确“恢复默认”操作。
- 立即生效项显示简短保存反馈；需要保存的字段明确保存按钮和未保存状态，避免整页所有设置混用两种习惯却无提示。
- 环境探测异步、按需进行；进入设置不应因多个检测请求阻塞交互。
- 迁移期间复用处理逻辑和配置协议，完成后删去旧工具箱的页面与事件依赖，避免重复 ID、重复监听和两套参数。

## 5. 首页：最近工程、全部工程与文件删除

### 5.1 两个可折叠分组

采用“最近工程（数量）”和“全部工程（数量）”两个独立折叠区域，箭头/标题样式与模块卡一致。默认均展开；最近先显示约 6 条，全部分页或按需加载，避免最近区域将全部工程推得过远。折叠状态记忆，搜索范围为两个分组，可显示各自命中数。

- 最近工程：按实际打开时间排序，固定工程优先显示；制作完成但尚未打开不伪造打开时间。
- 全部工程：长期登记合集，按制作/登记或更新的时间降序；新制作的工程出现在前面。图钉在全部工程中表示同一固定状态，但不强制改变该区排序，避免与“新制作排前面”冲突。
- 同一工程可以同时出现在两个分组，使用同一个规范身份；选择、图钉、封面、移除状态保持同步。
- 折叠分组保留当前选择，在底部显示将打开的工程名；搜索将当前选择完全隐藏时清除选择，避免误开不可见目标。
- 顶部搜索可匹配工程名、媒体名、路径；计数区分工程总数与当前结果数。
- 图钉放在封面固定角落，使用与编辑器同风格 SVG。选中描边和固定图钉相互独立，不用同一个角标兼任。

### 5.2 长期工程索引

建议新增工程目录服务或在 `maw/launcher_projects.py` 中明确拆分最近视图与持久登记层，保存工程身份、规范路径、显示名、登记来源、登记/更新/打开时间、固定和失效状态。缓存图片不内嵌工程索引。

- 启动器制作成功且工程可读后登记，不能等用户先打开编辑器才出现。
- 手动打开/导入成功、编辑器保存/另存成功同样登记；制作失败、取消、临时包装工程及中间步骤不登记。
- 编辑器未通过启动器启动时也能登记；通过统一服务完成跨进程锁与原子更新，不能让两个进程各自覆盖同一 JSON。
- 从当前最近记录和启动器元数据迁移可知工程。已经从历史最近列表淘汰且未登记的文件不能凭空恢复，用户以后再次打开/导入时登记。
- Windows 路径大小写、相对路径、重定位别名规范化后去重；保留可读显示路径。
- 不因文件暂时离线就删索引；标记失效并允许重新定位。
- 大列表分页、封面按需加载、统计缓存；折叠区域不启动新的封面提取任务。

### 5.3 删除工程文件

全部工程右键菜单新增红色“删除工程文件…”并使用垃圾桶图标；实际行为是**将选中的 `.mosp` / 工程 JSON 文件移入回收站**。

- 操作前展示工程名、实际路径和删除范围，避免与“从记录移除”混淆。
- 默认只处理工程文件，不删除原始视频、音频、同目录文件或 `.assets`；这是用户指定的“项目文件”范围。
- 缺失文件提供清理记录，不尝试删除其他同名文件。
- 文件被活动会话编辑、存在未保存内容或运行中的任务将写入时，先处理会话/任务；不能删完又被后台自动写回。重新核对目标身份及文件版本。
- 回收站成功后再更新两组视图、选择和菜单；失败则保留索引和卡片，显示原因。
- 回收站不可用时不退化为静默永久删除，告知用户可打开所在目录处理。
- 从回收站恢复后再次打开可重新登记；若支持应用内撤销，应基于真实回收记录，不伪造恢复能力。

“从最近记录移除”仅影响最近视图；“从全部工程记录移除”仅移除登记，不删除文件；“删除工程文件…”才操作磁盘。三者文案和成功提示必须区分。

## 6. 预制页：每个模块成为独立配置卡

### 6.1 卡片和状态的共同规则

卡头顺序为：**左侧折叠箭头 → 两位序号 → 标题 → 参数摘要/状态**。轻量悬浮只改变箭头颜色或极淡背景，保留约 28～32px 命中区；键盘焦点仍有可见轮廓。点击标题空白区也可折叠，字段、帮助和按钮不触发折叠。

序号按可见卡片动态连续排列，稳定模块 ID 用于保存；输出位于处理模块后，日志若显示始终最后。不把编号当作后端处理器 ID。

勾选模块后直接显示可配置卡片；缺字段显示“待配置”，不取消勾选、不跳旧工具箱。折叠只控制显示，取消勾选才从本次方案移除；草稿保留，再勾选恢复。预检失败展开相应卡片、定位具体字段，不再展开一个笼统的“后处理步骤”。

将旧后处理总开关、内部重复的步骤复选框、额外配置弹窗和分散保存状态合并到模块状态模型。各卡字段生成统一方案，再由适配层调用现有处理器。UI 显示、摘要、校验、任务快照使用同一份参数。

### 6.2 独立配置内容

| 模块 | 卡片应直接提供的内容 | 依赖/提示 |
| --- | --- | --- |
| 选择媒体/工程 | 文件、输入模式、源音轨、批量清单；移走 SRT 输出字段 | 输入身份稳定，切换模式明确校验类型 |
| 波形生成 | 缓存策略、波形来源/兼容生成模式、频谱数据开关、缓存状态 | 详见下一节；源音轨从输入模块读取 |
| 识别设置（ASR） | 服务、模型、语言、模型支持的本次调用参数 | 连接配置来自更多设置，错误定位当前服务 |
| 文稿匹配 | 文稿文件、预览、换行/匹配方式、现有匹配参数 | 需要字幕来源，时间与文本改变范围明示 |
| 固定处理 | 已有规则/替换项、启用规则摘要、可编辑列表 | 复用现有规则含义，不混入校对模型配置 |
| LLM 校对 | 服务、模型、校对提示词与现有高级参数 | 环境连接与本次提示词分开，保留草稿 |
| 重新断句 | 现有断句方式、字数/标点等适用参数；依赖 LLM 时显示对应服务 | 区分改文本与改时间，维护主副字幕绑定 |
| OCR 字幕去重 | 视频来源、识别区域/已有阈值、处理范围、报告选项 | 名称与说明明确“去重”，不是抹除画面字幕 |
| 字幕翻译 | 服务、模型、目标语言、目标副轨、提示词；已有兼容选项收纳到高级 | 原文与译文分别输出；默认保留主字幕 |
| 口播对齐 | 工程/识别结果、文稿、媒体引用、人工工作台入口与结果状态 | 详见第 6.4 节，不作为无交互自动步骤 |
| 输出 | 工程位置、可选原文/译文 SRT、命名与冲突策略 | 可见性与是否生成工程分开 |
| 处理日志 | 筛选级别、复制、打开日志目录、滚动跟随 | 仅显示控制，默认不勾选；始终最后 |

不为已有处理器臆造尚未支持的参数。先迁移现有配置能力，新增参数须完成后端契约，不能出现“能选但没生效”的控件。

### 6.3 波形：生成数据与显示效果分开

当前真实能力：编辑器已有“原生波形 / REAPER 波形”来源选择及“频谱颜色”开关；`maw/media_cache.py:embed_media_caches()` 当前会生成基础波形，并尽力生成 `.ReaPeaks`。关闭频谱仍可生成 REAPER 的 wave 层。因此，“波形类型”不等同于“是否生成频谱”。

建议卡片提供：

1. **波形生成模式**：自动/兼容模式为默认，原生与 REAPER 为明确选项；使用现有支持的缓存作为基础。模式传到生成器，不只改变表单文字。若 REAPER 路径仍需要基础缓存作为兼容回退，明示这点，不宣称绝对只生成一种。
2. **生成频谱数据（用于频谱颜色）**：复用现有 `generateSpectral`，说明额外耗时；不把“生成了数据”误写成“强制所有编辑器开启显示”。
3. **缓存策略**：默认复用有效缓存，必要时重新生成；有效性包含媒体版本、源音轨和所需数据层。
4. **简短状态**：是否已有缓存、当前源音轨、生成/回退/失败原因；缺音轨或不可解码时提供可理解说明。

编辑器的“基础/多行波形”“显示窗口”“纯色/频谱着色”等属于显示偏好，不要求重新分析音频。首轮主要实现生成配置；若卡片提供初始显示偏好，则使用明确的工程/启动显示契约，不能偷偷改写用户全局编辑器设置。此处不新增任意色板编辑器。

### 6.4 口播对齐的含义与完整入口

现在名称里的省略号是写死文案，原意接近“还要进入交互界面”；它不是运行进度，也没有表达实际作用。建议去掉省略号，标题“口播对齐”，加小型“需人工确认”说明。

一句说明建议：**根据文稿整理口播素材，在对齐工作台中选择需要保留的录制片段，再导出对齐后的工程。** 它与简单替换字幕文字的“文稿匹配”是两个功能。

- 已有工程输入：直接带入工程引用，选择文稿，点击“打开对齐工作台”。
- 媒体＋ASR：制作基础工程后提供“继续口播对齐”，不能在字幕来源尚未生成时假装准备就绪。
- 完成人工选择后，明确“使用对齐结果继续处理/制作”，接回真实输出工程；如果现有工作台没有完成回调，先提供“选择对齐结果工程”，不要靠文件名猜结果。
- 对齐等待期间显示“等待人工处理”，基础工程已生成和最终工程已完成是不同状态。
- 批量首轮不自动启用人工对齐链；提供明确限制与逐工程入口，不能静默跳过。

### 6.5 日志显示

“处理日志”右侧为复选框，新环境默认不勾选。勾选后出现同款卡片，末尾编号、首次默认折叠；展开显示日志，不改变后台是否记录必要诊断信息。

制作进度、当前步骤、取消、失败摘要、完成产物放在独立任务区；关闭日志不会失去这些信息。普通执行不强制滚动或展开日志。用户主动点击“查看详情”可打开日志并定位，但不要由普通成功事件覆盖用户的显示选择。

日志长文本限制渲染量、保留复制/文件入口；用户向上查看时停止自动滚动，提供“回到最新”。所有日志与错误报告沿用脱敏规则。

## 7. 输出模块与制作完成后的闭环

### 7.1 “输出”复选框的含义

这是可选的**自定义输出配置区**，不是是否制作工程的总开关。建议默认不勾选，使用“更多设置 → 文件与输出”的默认策略；页脚始终显示简短的实际输出目标，可点击定位配置。

勾选后展示自定义参数并参与本次方案；取消勾选后恢复默认策略，同时保留自定义草稿供再次勾选使用。不要隐藏卡片后继续悄悄采用用户看不到的旧自定义路径。

输出卡至少包含：

- 工程输出目录、工程文件名、最终 `.mosp` 路径预览。
- “导出原文 SRT”开关及独立位置；默认不强制开启。
- 启用翻译时显示“导出译文 SRT”及位置，可与原文独立勾选。
- 批量命名规则及每个输入的输出预览；不能让一批文件共用同一个文件名。
- 碰撞策略默认自动编号，运行前重新检查；不得静默覆盖源工程或另一个输入。
- 保留中间产物作为高级选项，与最终 SRT 导出区分。

原文 SRT 指翻译前、已完成选中整理步骤的主字幕；译文 SRT 对应实际产出的目标副轨，不将双语文本误当作原文。源字幕为空则不可导出空壳冒充成功；无字幕的媒体工程仍是合法产物。

处理器若内部仍需要 SRT，应放在临时/运行目录并按生命周期管理，不代表用户选择了发布 SRT。工程输出、原文 SRT、译文 SRT 应各有独立字段，不能继续用一个 `srtPath` 推导所有用户结果。

### 7.2 制作按钮、结果与登记

底部左侧展示精简状态/输出摘要，右侧操作顺序为“制作工程”及完成后出现的“打开工程”；批量采用“批量制作工程”。运行时主操作切换为取消，并防止重复提交。

- 成功输出写入并可读后才出现打开按钮；按钮绑定该次任务返回的真实工程身份，不能使用随后被改动的媒体或路径输入框。
- 制作完成立即登记全部工程，并排到最新普通条目前；点击打开成功后再进入最近工程。
- 新任务运行中，旧成功产物可从结果区域访问，但不能被标为本轮输出；失败/取消不得显示“打开刚制作的工程”却打开上一次产物。
- 部分成功按实际步骤标记，保留可用工程与失败提示；翻译失败不能宣称译文 SRT 已完成。
- 批量结果提供每条工程的打开入口；底部“查看制作结果”展示成功/失败列表，不猜测用户要打开哪一个。
- 制作不会自动启动编辑器，保留用户点击“打开工程”的操作。

### 7.3 “就绪”移除后的反馈去向

目前“就绪”只代表某个前端状态设置为闲置，不保证 FFmpeg、全部 API Key、本地模型均已可用。因此不适合当作全局健康标识。

删除其空闲文本及占位宽度；运行/取消显示在任务区，校验错误在模块字段及错误摘要，保存成功在对应设置附近短暂反馈，正在运行的编辑器显示在首页会话区。后台状态仍需无障碍播报，不能简单删掉 DOM 后让现有 `setStatus()` 调用失效。

## 8. 风格、交互与动效补充

- 右栏三页统一宽度、边框、分组间距；工具/设置单选与预制多选保持区别。
- 折叠箭头、图钉、菜单、窗口、删除等图标统一 Lucide 风格/线宽，不再增加表情符号。
- 展开/折叠约 140～180ms，避免给大表单高度施加长时间弹性动画；长任务不反复折叠重排当前正在编辑的卡片。
- 切换工具/设置可短暂淡入，保留左侧内容定位，不加入卡片飞入、弹跳或强发光。
- 深色用中性黑层次及低调紫色；选中边框、鼠标悬浮、键盘焦点分开；图钉不是选中状态。
- 左侧紧凑导航悬浮展开不要推动正文，图标保持中心位置；能通过键盘访问与关闭，图标折叠态有提示。
- 错误定位到具体模块，展开对应卡片即可，不自动改变其他模块配置。
- 封面先显示占位再替换图像，固定尺寸避免列表跳动；项目目录增多后不一次性解码全部视频。
- 中英文长标签、125%/150% 系统缩放、应用缩放及窄窗口均检查；不将文字截断或偏移误当作“精简”。

## 9. 值得后续扩展的相关能力

以下只列强相关扩展，不作为本轮修正的前置依赖：

| 优先顺序 | 能力 | 价值与边界 |
| --- | --- | --- |
| 1 | 保存/复制预制方案 | 固定常用模块与参数；只存服务引用，不把密钥带入方案；命名方案与临时草稿分开 |

### S1：交互可靠性与基础视觉

状态：已完成（2026-09-16 实施批次 1，基线 8d0b656）。对应 4、5、10、11、12，及新增 Esc 问题。实施时逐项复核了 §3.1/§3.2 的根因指控，全部属实：

- 连续右键失效的机制确认为「旧菜单的 `{once:true}` dismiss 监听泄漏」：关闭只删 DOM 不摘监听、不取消待注册定时器；下一次右键的冒泡事件被旧监听处理（旧菜单已脱离 DOM，`contains` 恒假）→ 全局 `closeMenu()` 误杀新菜单。审计记录的 1、0、0、0、0、0 与源码推演完全一致。
- 导航偏移的机制确认为「隐藏文字仍占 flex 布局」：折叠态标签被压缩到 19px，行宽恰好填满 48px 内容区，图标左缘停在 x=8（中心 17.5px ≠ 栏中心 32px）；展开态切换 `flex-start + padding-left 12px` 后图标左缘跳到 x=20，形成 12px 跳动。

实施内容：

- 菜单重写为单一实例生命周期：document 捕获阶段常驻监听（contextmenu 先关旧菜单、网格处理器随后开新菜单——替换语义不再依赖定时器延迟注册）；click/Esc/Tab/方向键/Home/End、窗口失焦、任意滚动、切页、visibilitychange 统一关闭；网格重建（render）时菜单随之关闭，悬浮菜单不再指向已换位的列表。Esc 关闭并把焦点归还唤起卡片；Shift+F10/Menu 键唤起（按卡片定位，不依赖鼠标坐标）、聚焦首项、方向键循环导航；坐标在视口内收敛（clientX/Y 与 innerWidth 同为 CSS 像素，应用缩放/系统缩放下语义一致）。

## 11. 核心验收矩阵

| 场景 | 预期 |
| --- | --- |
| 右键 A → 右键 B → Esc → 再右键 | 始终打开正确菜单；Esc 关闭并恢复焦点 |
| 折叠导航 → 悬浮展开 → 移开 | 图标中心稳定，文字不占折叠态空间，页面不回流 |
| 最近与全部出现同一工程 | 选择/图钉一致；移除最近不删除文件或全部记录 |
| 删除工程文件失败/成功 | 失败保留索引；成功只回收指定工程文件，媒体和资源完整 |
| 媒体＋ASR，关闭波形 | 不生成波形/频谱；工程和字幕仍正确 |
| 波形模块开启，ASR 关闭 | 可直接设置波形/频谱并制作零字幕工程 |
| 选多个字幕整理模块 | 独立配置、编号和折叠；实际顺序与摘要一致 |
| 日志关闭时制作失败 | 错误摘要和失败模块可见，无须打开日志才知道失败 |
| 日志重新开启 | 最后一张卡、默认折叠，能查看当前任务已产生的信息 |
| 输出区关闭 | 使用清楚显示的默认位置；隐藏自定义草稿不生效 |
| 原文/译文 SRT 组合 | 导出内容与开关、语言、路径对应，不生成未选产物 |
| 制作完成后修改媒体输入 | 打开按钮仍对应已完成任务，下一次制作使用新输入 |
| 全部工程登记超过 50 项 | 老工程仍可搜索访问，封面/统计按需读取 |
| 口播对齐等待人工 | 不宣称最终完成，不自动跨过人工步骤；可继续接回结果 |
| 复杂工程再处理与另存 | 主副轨、素材批次、TTS 配方、贴片及资源路径不因 UI 重构丢失 |
