# 编辑器统一性能基线

第一阶段只提供可复现的测量和数据完整性检查，不改变编辑器操作逻辑。基线用于判断后续优化是否真正改善相同工作量，不能以某次操作较快就认定问题已修复。

## 运行

先安装项目 Python 环境、开发依赖、Playwright Chromium 和 FFmpeg。Windows 默认使用 `.venv/Scripts/python.exe`，其他环境使用 `uv run --frozen python`；可通过 `MSW_E2E_PYTHON` 指定解释器。FFmpeg 在 PATH 中，或通过 `MSW_E2E_FFMPEG` 指定。代理环境应让 `127.0.0.1,localhost` 直连。

```powershell
npm run test:perf-tools
npm run perf:editor -- --out output/performance/before
```

快速验证工具入口，不作为正式基线：

```powershell
npm run perf:editor -- --matrix bound:1000 --repeats 1 --warmup 0 --idle-ms 1000 --out output/performance/smoke
```

输出目录必须不存在，避免覆盖旧报告。每次运行串行测试所有场景；请关闭其他性能测试和视频导出，保持浏览器版本、电源模式、场景顺序及后台负载一致。不要在测量时同步运行单元测试。浏览器默认无界面，自动启动和停止此次测试自己的本机服务器。

若测试终端设置了优先级更高的 `MSW_ENV_FILE`，先移除该终端的环境变量，避免它覆盖工具指定的隔离 `MAW_ENV_FILE`。正式基线的测试终端没有这项覆盖。基线使用默认字体和隔离配置，不评估个人字体安装及个人设置的额外负载。

## 固定输入

| 场景 | 字幕数 | 用途 |
| --- | ---: | --- |
| `bound` | 1,000 / 6,000 / 10,000 / 15,000 | 同规模规则的主副绑定字幕、字词时间、5 名说话人及空白目标轨道 |
| `mixed` | 10,000 | 3 组主副轨道、注释、12 名说话人、外观覆盖、动画及 100 个音频贴片 |
| `migrated` | 10,000 | 旧主副结构经当前迁移代码生成的工程 |

所有场景固定两小时、640×360、2 fps 的合成视频，以及相同的确定性波形。这样字幕数量不会与媒体时长、源文件解码复杂度混淆。波动动画固定为 400 ms，避免小规模工程的长字幕触发既有片段上限。

`migrated` 检查迁移所得数据参与编辑后的性能，不代表直接打开所有历史工程的迁移耗时。`plain`、`long-note` 为额外模型夹具，不属于默认浏览器矩阵。浏览器工作量要求至少 1,000 条字幕；选择数量不足会明确失败。

夹具版本、内容摘要、工具摘要、环境、视口、预热次数及采样次数写入报告。改变工作量后须更新夹具版本；改变计时或校验语义须更新工具版本，并重新建立基线。

测试仅使用生成的数据、媒体和音频；每个场景隔离用户设置、恢复草稿和环境配置，浏览器禁止访问外部 HTTP 服务。不读取个人工程或 API Key，不调用识别、翻译、配音服务。素材、完整工程和原始报告留在 `output/`，不提交仓库。

## 操作和完整性

统一入口测量 27 类操作：选择、右键、跳转预览；复制／跨轨粘贴／撤销／重做各 1 组和 100 组；剪切、联动切分、合并；文字、单字幕／轨道／说话人样式预览；搜索；整组跨轨拖动、单组及 100 组端点调整；内容保存、仅播放头保存、无变化保存；恢复草稿与空闲后台活动。

一组指一对主副字幕。批量复制固定同一组物理轨道，目标为空白主副轨道；混合工程的其他轨道仍参与整体负载。准备选择、恢复前置状态及撤销清理在测量区间之外。

播放器保持暂停，跳转另行测量；边播放边编辑属于后续专项。为隔离保存操作，测试关闭工程自动保存，保留手动保存与恢复草稿的独立测量。空闲场景位于保存完成之后，代表已保存工程的后台活动，不代表持续输入且尚未保存时的负载。

拖动和端点调整使用真实鼠标事件；其余操作调用产品处理函数或派发实际控件事件。它们用于稳定对比相同路径，不等同于完整人工操作的端到端输入延迟。拖动检查只产生一个撤销记录、两侧时间变化一致；样式修改检查产生一个记录；粘贴、剪切、切分和合并检查内容确实变化。最终检查撤销后的字幕模型、绑定和说话人配置恢复，原始夹具未变化，保存和重新打开的字幕一致。失败和页面错误保留在报告中，不计为快速成功。

## 指标含义

| 指标 | 记录内容与边界 |
| --- | --- |
| `syncMs` | 操作处理函数占用主线程的时间；异步保存接近 0 不代表保存快 |
| `feedbackMs` | 操作开始到两个浏览器动画帧回调，作为界面反馈机会的近似值；不是屏幕像素呈现测量 |
| `settledMs` | 普通操作处理完成；预览操作额外等待新一版 ASS 完成；保存等待保存结果；空闲等待指定观察时间 |
| `longTasks` | 观察区间中浏览器报告的 ≥50 ms 主线程长任务；后台工作也可能计入 |
| `frameGaps` | 观察区间内动画帧回调间隔；包含自动化往返和调度影响，不直接称为 GPU 帧率 |
| `calls` | 关键产品函数调用次数、累计耗时；存在嵌套，不应相加当成总 CPU 时间 |
| `previewRequests` | 本地字幕预览请求次数、参与字幕数、ASS 字节数和耗时 |
| `startup` | 本地服务就绪、页面加载、编辑器就绪、ASS 就绪及保存重开时间 |
| `memory` | 加载、操作后、重开后的 JS 堆、CDP 报告的后备存储及 DOM 数；记录强制回收前后值，不代表整个进程或 GPU 内存 |

拖动的 `feedbackMs` / `settledMs` 包含 12 步鼠标移动的整个手势；单次移动与松手提交耗时分别查看 `calls.moveCueDrag.samples` 和 `calls.endCueDrag.samples`。不能把完整手势时间当作一次卡顿。

默认每项浏览器操作预热 1 次、正式采样 3 次，保留所有原始样本，报告中位数和最大值。少于 20 个有效样本时不报告 P95；发布验收可使用 `--repeats 20`，但不能与次数不同的报告直接判定回归。首次打开每个场景只测一次。

模型探针在所有浏览器场景结束后串行执行，独立记录 10,000 条下的 90 秒预览投影、完整工程转换、无锁／半数字幕锁定校验，以及长注释对预览范围的影响。它们不冒充浏览器输入延迟。

锁定探针使用同一份未修改对象，反映当前无改动校验路径的开销；它不代替编辑前后两个独立状态的锁定正确性测试。后续优化不能只靠增加同对象短路，就认定实际编辑中的锁定成本已经解决。

## 对比与后续门槛

```powershell
node scripts/benchmark_editor.mjs --compare output/performance/before/bound-10000/report.json output/performance/after/bound-10000/report.json
```

不同夹具、工具、浏览器、机器、字体清单或运行参数拒绝自动比较。产品提交号允许不同。有效样本至少 3 次、中位数同时增加超过 20% 和 50 ms 时标记回退候选；需要同条件复测确认原因，不根据一次运行下结论。退出码：0 可比较且无候选回退；1 报告不兼容、不完整、缺项或操作失败；2 有性能回退候选。

后续阶段以以下目标制定改动，第一阶段不宣称已经达标：

- 常规选择、右键和输入反馈尽量在 100 ms 内；连续拖动优先减少超过 50 ms 的主线程停顿。
- 小范围移动、粘贴、撤销的成本主要随修改量增长，避免随全工程字幕数增长。
- 局部样式预览优先更新当前可见字幕；保存、恢复和后台扫描不打断操作。
- 10,000 条混合工程必须通过锁定、冲突、绑定、引用、撤销与重做、保存重开、预览和导出的完整性回归。

本工具尚不覆盖长时间播放、数小时反复编辑泄漏、真实高分辨率视频解码、完整视频烧录速度、所有字体与全部历史工程。这些属于后续专项及第六阶段，不能由本次合成基线替代。

阶段结果及尚未解决的问题见 [第一阶段账本](TEST_FEEDBACK_PERFORMANCE_BASELINE_20261107.md)。
