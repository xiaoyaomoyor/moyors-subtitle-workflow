# 编辑器音量、ASR／翻译结果与文件菜单修正方案

日期：2026-09-24。基线：`91a96df`，保留当前工作区上一轮启动器修复。

本文最初记录原因核查与实施规划。2026-09-24 已按用户授权完成 A–F：A+B 验证与边界见 [A+B 实施记录](TEST_FEEDBACK_EDITOR_PROCESSING_20260924.md)，C+D 见 [候选结果与应用记录](TEST_FEEDBACK_EDITOR_PROCESSING_CD_20260924.md)，文件菜单及最终集成验收见 [E+F 实施记录](TEST_FEEDBACK_EDITOR_PROCESSING_EF_20260924.md)。此前误发的涂鸦需求不在范围内。

## 已确认的交互决策

- 时间选区截断原字幕、但缺少可靠字词时间码时：区外剩余片段保留原文，并标记“待校对”，由用户修正。
- 音频批量处理继续只调整选中贴片；名称使用“所选贴片音量”，不改成整个配音轨的总音量。
- 用户遇到音量无效的入口是媒体播放器／波形时间线原声，不是素材库音频试听。
- ASR／翻译生成结果后都不直接改时间线；修改候选结果后，由底部三个操作决定去向。

### 1. 源音量：已复现绑定错误

依据：

- `web/editor.js` 的 `player` 可以被替换；`resetLoadedMedia()` 会新建 audio，`loadMediaFile()` 在 audio/video 类型变化时新建播放器。
- `processing-host.player` 是动态 getter，但 `web/msw-audio.js` 调用 `MSWAudioTransport.create({ player: host.player })` 时只取了一次。
- `web/msw-audio-transport.js` 的媒体源节点、音量、事件、时间读取都保留该旧对象。

在隔离 Chromium 中加载现有便携编辑器，调用实际的播放器重置函数，再设置 +6 dB，得到：

```json
{"elementWasReplaced":true,"boundToCurrent":false,"boundToRemoved":true,"connected":false,"reportedGainDb":6}
```

这说明“数值改变”不足以证明正在播放的声音被放大。此前测试验证了 gain 值和波形高度，未覆盖更换播放器后的实际信号路径。该缺陷还能影响贴片播放的时间读取、事件订阅及总试听音量，修复应覆盖这些共同依赖。

实施时增加明确的播放器挂接／脱离操作，统一在替换、回滚和清空媒体时调用。保留每个媒体元素唯一的 MediaElementAudioSourceNode，避免对同一元素重复创建；更换元素时清理旧事件和调度，绑定当前播放器。真实换源仍按既有约定归零源试听增益；仅同一源媒体换播放代理时保留用户试听设置。暂停／恢复后保证 AudioContext 正常运行。

验收必须测量实际音频信号：低幅度测试音在 0 dB 与 +6 dB 时应约为 1:1.995 的振幅关系；分别覆盖首次导入视频、新建工程后导入、audio/video 切换、代理切换和加载失败回滚。另验证播放器总音量及静音没有被重复乘算。上述振幅测量属于实施验收，本轮没有把绑定诊断冒充音频测量。

### 2. 翻译：已复现内部编号泄漏

使用合成快照：一条中文 `main-chinese`、一条英文 `main-english`，目标中文；模型响应由本地测试桩提供，没有联网或计费。

实际 `translate_snapshot()` 返回：

```text
translations: main-chinese → 原中文；main-english → 中文译文
skipped_ids: ["c0001"]
```

`maw/postprocess.py` 内部使用 c0001、c0002 给模型编号；已经是目标语言的字幕跳过模型调用并保留原文。本意合理，但 `maw/msw/jobs.py` 未把跳过编号映射回工程 ID。`web/msw-translation-core.js` 找不到对应源字幕，因此抛出用户看到的错误。

修正：在编辑器后端适配边界建立显式的内部编号→原字幕 ID 映射，返回逐条保留原因。不要删除前端一致性检查，也不要靠正则猜测用户工程 ID。混合语言全文可正常完成；已是目标语言的内容显示“原文保留”。全部已是目标语言时也应返回清楚的无须调用说明和可检查结果，而不是把正常跳过渲染成失败。

兼容已有任务时，仅在能通过快照映射和原文校验的情况下恢复旧跳过记录；保留有效译文，不因这个适配错误要求用户重新支付整批翻译。确实缺项、重复 ID、无效响应和源字幕在处理期间被修改，仍需要明确处理，不能静默忽略。

## 统一的 ASR／翻译面板

### 配置与记录布局

保留紧凑双列表单，统一宽度、间距、关闭按钮、控件背景、主题色和键盘反馈。范围放第一项；服务、模型／目标语言等调用项留在面板；API Key、地域等环境配置继续留在全局设置。补充要求与高级项可折叠，长解释收进提示图标。

```text
识别记录
  ▾ 识别批次01                         ○ 选择结果
    识别001               [可编辑的识别文字……]
    00:10.000–00:12.300
    识别002               [可编辑的识别文字……]
    00:12.500–00:15.000

当前批次：识别批次01    [覆盖主字幕] [覆盖副字幕] [存入素材库]
```

翻译使用相同结构，名称为“翻译批次01”“翻译001”；每条左下展示源字幕原文，长原文可以展开查看，右边是可编辑译文。ASR 左下显示时间范围，必要时补来源贴片名。

规则：

1. 批次号按工程内、处理类型分别递增，01／02……；刷新、排序、折叠或筛选不能改变编号。超过两位、三位时自然延长，不截断。
2. 一次用户发起的多选区／多贴片 ASR 归为一个批次；底层多个服务任务不伪装成多个用户批次。连接测试不混入翻译记录。
3. 折叠箭头只负责展开；右侧单选点只负责选择；选择不应用结果。底部始终显示当前批次或“未选择”。
4. 尚无可用结果时不能选择和应用。部分任务失败时清楚标出完成／失败数量；用户可以使用已完成内容或重试失败范围，不把部分成功当成全部成功。
5. 长记录区固定最大高度并内部滚动；逐条懒渲染／虚拟化，所有结果仍可访问，不再硬性只读前 300 条。
6. 轮询只能更新状态，不重建正在编辑的输入框，不抢焦点、不丢光标、折叠状态或滚动位置。
7. ASR／翻译统一为“保存设置 → 开始处理”；开始翻译不再接受“译文写入”参数作为自动落地指令。

### 可编辑候选结果的数据规则

- 服务原始结果、来源快照保留；用户编辑存为候选修订，使用稳定的批次 ID／行 ID，不覆盖原始服务记录。
- 编辑后的候选用于三个去向，存入素材库也必须使用编辑后的文字。
- 结果修改与时间线修改是不同操作；候选自动暂存，刷新后恢复。应用时间线后一次撤销能恢复所有受影响内容。
- 编辑 ASR 文字会让旧字词时间码失效；没有重新对齐时清除失效字词映射，不制造精确时间码。
- 空内容在该行内提示，不默认解释为删除原字幕；删除字幕仍是明确的编辑操作。
- 把当前全局 `applied_results` 的一次性应用标记改为按批次修订＋目标去向记录。写入主字幕后仍可写副字幕或入库；同一修订重复点击同一目标不重复添加。
- 在处理期间或候选编辑之后，时间线已经变化的内容必须进行目标快照检查。不要为了“能覆盖”取消原有的工程、媒体版本与字幕冲突保护。

### 底部三个去向

| 操作 | 行为 |
| --- | --- |
| 覆盖主字幕 | ASR 替换识别范围对应主字幕；翻译按源字幕稳定 ID 更新主字幕，不改无关字幕 |
| 覆盖副字幕 | 写入当前目标副轨；没有副轨时建立副轨。正常情况建立／更新与主字幕的绑定，不能确定绑定时不强行建立错误绑定 |
| 存入素材库 | 一条候选一个字幕素材，同次操作归批次；保留来源、相对时间和手动修改后的文字 |

取消“译文写入”选项和成功后的自动应用路径。底部按钮在没有选中批次、目标不可用等情况下禁用并给出简短原因。应用后仍允许检查和修改候选；重新应用新修订时先检查上次应用后用户是否又修改了时间线。

## ASR 选区切穿字幕的处理

识别只验证选区处于有效媒体内、有可识别音轨等条件。选区不必包住整条字幕；“扩展到完整字幕边界”作为可选操作保留。前端、后端和应用层必须一起修改，不能只放开开始按钮。

出现跨边界冲突时，仅相应目标轨的覆盖按钮改为下拉菜单；不能点按钮主体就直接覆盖。建议菜单文字比“截断主字幕”更明确：

- 替换涉及的整条主字幕／副字幕。
- 仅替换选区内，保留区外部分。

示例：原字幕为 10–20 秒，识别选区 14–16 秒。

| 策略 | 结果 |
| --- | --- |
| 替换整条 | 移除原 10–20 秒字幕，插入实际识别得到的 14–16 秒内字幕；不把短音频识别结果擅自拉长到 10–20 秒 |
| 截断保留 | 保留 10–14 秒和 16–20 秒原字幕片段，14–16 秒使用识别结果 |

有可靠字词时间码时按边界保留对应文字；没有时按用户确认方案保留原文，标记区外片段“待校对”。因此一条字幕中间被切走时，两侧暂时可能带有同一句原文，不能将它们表示为已准确拆分。

多选区按各个区间分别计算，不能把最小起点至最大终点之间的空档一起删除。主／副轨分别判断交叉；主轨有边界冲突不应阻止写入空副轨。保留颜色／说话人等可继承信息，为拆出的片段分配稳定新 ID，清理或重建失效绑定，并把受影响的配音来源标记为需复核。所有修改为一个撤销事务，不删除音频贴片。

如果同批 ASR 自身产生相互重叠的候选，先说明内部冲突；不能把“替换／截断旧字幕”菜单当成候选彼此重叠的解决方案。仍允许入素材库后整理。

## 音量与波形显示

### 滑条方案

```text
所选贴片音量    ─────●────  100% · 0.0 dB  [复位]
选中贴片：3

源音频试听音量  ─────●────  100% · 0.0 dB  [复位]
```

- 保留现有 −60 至 +12 dB 的有效范围，用滑条实时试听，数值可精确输入，0 dB 为原始音量（100%）。低端不伪称完全静音；完全静音仍通过静音功能完成。
- 去掉设置为／增减下拉框和额外应用按钮。复位回 0 dB，不擅自解除用户单独设置的静音。
- 所选贴片当前值一致时显示实际值；不一致时显示“多个音量”，不假装它们都处于 100%。第一次拖动／输入时统一设置为所选值，行内短提示解释影响范围。
- 拖动期间使用临时试听状态，不每一像素写一条撤销和保存记录；松手提交一次，可一次撤销。Esc 取消此次拖动。
- 无选中贴片时禁用贴片滑条；无有效源音频时禁用源滑条。切换选中对象时重新读取实际值。
- 所选贴片音量仍是工程中的贴片增益，会按现有规则参与导出；源音频滑条是试听增益，导出是否采用继续由“同步试听音量”决定。说明收入提示图标，避免名称误导。
- 播放器总音量继续作为最终监听控制，不改变其现有入口，也不重复叠加。

### 右上角统一读数

- 就绪：`15:10.270 · 91,027 peaks · +3.0 dB`。
- 导入、读缓存、下载峰值或生成波形：统一显示加载图标＋“正在加载波形”，隐藏时长、peaks 和 dB 组合，不显示上一份媒体的数据。
- 未生成：显示“占位波形”；取消或失败：显示可理解的结束状态，不能永远停在加载。详细错误及重试入口放波形设置或消息区。
- dB 始终反映源试听增益；“波形跟随源试听增益”只决定绘制高度是否跟随，不再决定这个数值是否可见。
- 状态按当前媒体／音轨版本归属，迟到的旧任务回调不能覆盖新媒体状态。时长与峰值数应对应实际显示的波形来源。
- 波形随音量变化继续复用已生成峰值，只调整绘制振幅，不重新生成音频或峰值缓存。

## 文件菜单

### 保存反馈

移除菜单中“工程已保存 · 音频素材 0/0”常驻字段及所有重新显示它的调用。普通保存、另存为、新工程首次保存统一使用现有的“正在保存 → 保存成功”气泡；保存期间新增修改仍保留未保存状态。缺失素材、恢复记录写入失败等真实问题保留警告气泡和诊断入口，不能随常驻文案一起吞掉。

### 最近工程

以启动器当前“最近工程”最终列表为同一来源，沿用其上限 9 项、固定／移除／重定位语义，不把“全部工程”注册表塞进最近菜单。

增加经过本机服务鉴权的读取入口。编辑器打开菜单或窗口重新获得焦点时更新；成功打开、保存新工程、另存为后通知或刷新。启动器同样在回到首页／获得焦点时刷新。复用合并查询函数，不维护两套排序规则。

需要同时修正打开入口：当前编辑器只允许打开内存中的旧 recent_projects；启动器固定或重定位后的有效工程可能不在其中。新的打开操作仍必须验证其属于可信最近记录，不能因同步列表而扩展成任意路径打开接口。

同名文件保留目录提示；已失效路径标识并给出统一行为。独立 file:// 编辑器没有本机服务时如实禁用同步入口，不声称浏览器能读取启动器历史。并发保存设置时合并最新最近记录，避免旧进程用旧快照覆盖另一端刚更新的记录。
