## 1. 本次要交付的体验

用户直接打开 MSWE 编辑器，导入视频，即可播放、手动编辑字幕、翻译和配音；波形在后台生成。用户可以对整个源视频或在波形上划定的时间范围执行 ASR，再把结果应用到当前工程。不要求先在 Launcher 中转写、生成波形或生成工程文件。

完整功能仍由现有本机 Python 服务提供。Launcher、编辑器和 CLI 共用处理能力及本机配置；用户可以只启动编辑器及其后台服务。这里的“独立”指使用流程不再经过 Launcher 窗口，不要求把 Python、FFmpeg 或模型搬入浏览器。

必须覆盖的工作流：

1. **从纯视频开始**：打开编辑器 → 导入视频 → 立即得到有刻度的时间轴和占位波浪线 → 后台补齐真实波形 → 整段或片段 ASR → 编辑 → 按需翻译／TTS → 保存／导出。
2. **跳过 ASR**：导入视频 → 直接输入配音草稿或手动添加字幕 → TTS → 放置音频贴片 → 导出。波形生成关闭、失败或尚未结束，都不阻塞这条流程。
3. **重新转录**：打开已有工程 → 选择整段或时间范围 → 提交识别任务 → 查看替换影响 → 应用到当前工程 → 可以一次撤销。
4. **清空后继续**：删除所有字幕和／或所有贴片 → 工程仍可保存、重新打开、播放媒体、重新 ASR、重新添加字幕和配音。
5. **无视频纯 TTS**：沿用已有独立文本草稿能力；即使字幕、贴片、素材都为 0，也能开始输入、合成并放置第一条贴片。

## 3. 先确定的数据与交互规则

### 3.1 工程、媒体、波形和任务分别管理

| 对象 | 建议规则 |
| --- | --- |
| 字幕和贴片 | 主字幕、副字幕、音频贴片可以分别为 0；空数组合法，轨道设置与素材库不因删除最后一块自动消失 |
| 当前媒体 | 后端登记稳定 `media_id`，关联源文件、文件指纹、所选音轨、时长和本次登记版本；前端 blob URL 只承担播放用途 |
| 保存后的媒体引用 | 工程保留可重新定位的原媒体引用／收集后的相对路径；临时 `media_id` 和 blob URL 不作为唯一恢复依据 |
| 源媒体时长 | 来自媒体元数据；波形峰值数量不能决定视频是否存在、能否选区或能否执行 ASR |
| 编排内容时长 | 根据媒体、字幕、副字幕和音频贴片的末端计算；无源媒体也可编辑纯字幕／TTS |
| 空工程可视范围 | 无内容时先显示 20 秒编辑空间；这是视图范围，不是伪造的媒体或导出时长。放置内容后扩展 |
| 波形状态 | `未请求 / 排队 / 生成中 / 就绪 / 失败 / 已取消 / 无音轨`；状态独立于字幕数量、项目保存状态 |
| 占位波浪线 | 纯显示层，标明“占位波形”；不写成真实峰值，不参与静音检测或音量计算 |
| 时间选区 | 单个连续 `[start_ms, end_ms)` 源时间范围，独立于字幕块选择和音频贴片选择；本轮建议不持久化、不进入内容撤销栈 |
| ASR 任务 | 快照保存媒体身份、音轨、范围、设置、目标轨和受影响内容；返回候选字幕，不直接修改当前工程文件 |

继续使用上游整数毫秒契约。若新增持久化字段，优先置于可选的 `msw` 命名空间；确需扩充公共媒体元数据时，同时更新 JS／Python 校验和文档。不会仅为允许空数组就升级 schema。

### 3.2 时间选区与现有手势

用户已指定：**按住 Ctrl+Shift，再用鼠标左键拖动波形以选择片段；选中范围内的波形反色显示。**

建议细化为：

- 单次拖动创建／替换一个连续时间选区；反向拖动自动规范起止时间。
- 按下时确定手势模式，松开修饰键不会突然变成移动字幕；松开鼠标才提交选区。
- 在波形时间编辑区域内，即使起点落在字幕块或音频贴片上，也优先识别 Ctrl+Shift 时间选区手势；不误拖已有内容。按钮、输入框、轨道头和缩放手柄不作为选区起点。
- 超过最小拖动距离才创建选区，单击不提交零长度范围；取消拖动保留原选区。
- Esc 清除／取消时间选区；普通播放定位不立即清空选区；新建工程、切换源媒体时清除。
- 状态栏显示起点、终点、持续时长，并允许在 ASR 面板中精确输入时间。
- 支持单行和多行波形、跨行拖动、自动滚动、缩放、虚拟行重建、窗口改变和高 DPI。
- 反色只处理波形绘制层，包括占位波浪线；字幕文字、贴片热力图、播放头和边界标签保持可读。提供边界线，使灰色或接近中灰的主题下也能识别选区。
- 保留 Ctrl+Shift+滚轮调整行高；选区拖动过程中冻结会改变坐标映射的滚轮缩放／行高操作，避免端点跳动。
- 时间选区不触发 ASR；用户从“媒体 → ASR”或选区右键菜单提交任务。
- 删除／剪切仍作用于明确选中的字幕／贴片；只有时间选区时不把 Delete 解释为删除整段媒体或字幕。

第一版不增加多段不连续选择。ASR 始终选取真实源音频；占位时间轴超出视频末尾的区域不能用于源视频 ASR。纯 TTS 时可以使用完整编排范围定位贴片。

### 3.3 整段与片段 ASR 的时间含义

- “整个视频”明确指源媒体的完整音轨，包括当前被空隙跳过的部分，不隐式转录 TTS 混音或导出的压缩时间轴。
- “所选片段”默认严格取提交时展示的源时间范围。播放／导出的空隙映射不改变 ASR 的时间坐标。
- `audio_index` 与容器 `stream_index` 区分保存。ASR 面板清楚显示正在识别的音轨；源波形和试听尽量与该音轨一致。
- 片段可有少量用于上下文的前后音频，但实际送入范围与需返回范围分别记录。裁切前后的时间戳只做一次回映射。
- 例如源范围是 60–75 秒，截取后 2–3 秒的识别结果，回写应为 62–63 秒。若实际提取从 59.5 秒开始，则按 59.5 秒偏移，并过滤／裁剪目标范围之外的结果。
- 段级、字词级时间戳都要换算、排序、校验和限制范围；没有字词时间戳的引擎仍保留段级结果，不伪造字词精度。
- 帧模式下继续经过已有的帧／毫秒规范化逻辑，避免旧 `start_frame/end_frame` 覆盖新 ASR 时间。
- 无音轨是不能执行 ASR；有音轨但没有语音是合法的空结果。空结果不自动清空已有字幕。

### 3.4 ASR 应用规则

建议第一版以**当前主字幕轨**作为 ASR 目标。副轨继续承接现有翻译；直接识别到副轨可在后续扩展，避免本轮同时引入轨道管理重构。

| 场景 | 建议行为 |
| --- | --- |
| 原主轨为空，任务返回时相关状态未变 | 可自动加入识别结果，作为一次可撤销编辑 |
| 已有主字幕，整段重新识别 | 展示旧／新数量和影响范围，用户点击应用后替换主轨；不把旧工程其他字段整份覆盖 |
| 已有主字幕，片段重新识别 | 只替换工作范围内的主字幕，范围外保持原样 |
| 选区边界穿过已有字幕 | 提交前展示原选区和边界冲突；建议让用户选择扩展到完整字幕边界后再识别，或调整选区；不静默删除范围外文本。严格范围拆分作为 D3 的可选方案 |
| 返回零条字幕 | 显示“未识别到语音”，保留现有内容；如果要清空，走单独的字幕删除操作 |
| 任务期间修改了受影响字幕或目标范围内插入新字幕 | 标记结果待处理，阻止自动覆盖；比较整个目标范围，不能只核对提交时已有的 ID |
| 仅编辑其他范围 | 不锁整个工程；提交应用时重新校验受影响范围即可 |
| 换工程、换媒体、改音轨或文件被替换 | 拒绝自动应用到当前上下文，保留原任务结果和来源说明 |
| 任务结束时仍在输入文字／拖动 | 等手势或编辑提交后再复核；不在指针按住期间改时间轴结构 |
| 撤销后再次应用、刷新恢复或重复响应 | 使用结果 ID 和已有任务确认机制去重，明确区分“已应用”与“已撤销” |

ASR 不是一对一翻译：它会改变段数、边界和身份，不能直接套用翻译的文本替换算法。

主副字幕和 TTS 的建议规则：

- 新 ASR 段使用新稳定 ID，并记录任务／范围来源；范围外原段保留 ID。
- 重转录替换主字幕时，默认保留旧副字幕文本和位置，解除指向已删除主字幕的绑定，标识需要复查。不要按数组下标强行绑定新旧字幕。
- 已生成音频是独立素材；旧贴片继续播放并保留位置，来源缺失／内容过期状态可见，不自动重合成或删除。
- 普通字幕删除沿用用户现有的主副轨连锁规则；专门的“清空全部字幕”清空所有主副字幕，包括隐藏副轨，保留媒体、音频素材和贴片。
- 删除字幕、重转录替换和应用翻译之间要使用同一历史系统；一次应用的主字幕变化、绑定清理、来源状态和应用记录可以整体撤销／重做。

- [ ] 新建轻量媒体登记服务，支持已经由服务器打开的源媒体、编辑器本机文件选择、浏览器拖放三条入口。
- [ ] Server 的“导入媒体”优先通过本机选择器登记源文件，返回受控媒体 ID 和可播放地址，减少大视频额外拷贝。
- [ ] 浏览器拖放取不到真实绝对路径时，使用二进制分块传输到本机管理目录；设置大小／磁盘空间检查、进度、取消和失败重试，不把整个视频编码成 base64 JSON。
- [ ] 复用已有媒体探测、兼容播放和 FFmpeg 查找能力，读取时长、视频帧率、音轨列表；不因浏览器原生解码不了就直接判定源文件不能 ASR。
- [ ] 维护原媒体与播放代理的关系。转码代理不替代原素材身份，时间起点与音轨对应明确。
- [ ] 上传完成前可先用 blob 播放、占位时间轴编辑；后端媒体未就绪时显示对应处理状态，不能误用之前的媒体执行任务。
- [ ] 将“给已有工程重新关联媒体”与“导入另一个视频建立新工程”分开；避免导入视频时无意覆盖当前字幕，避免媒体改变后沿用旧波形。
- [ ] 新工程先有稳定身份，再提交后台任务；首次保存、另存为、媒体收集、恢复和多窗口绑定沿用现有持久化机制。
- [ ] 注册媒体接入 `source_scope` 和 `save_as`；保证同一工程的视频播放、ASR、波形、混音导出和媒体收集看到的是同一份源文件。
- [ ] 保存后可重建媒体登记；搬移工程支持相对路径／重新定位；临时导入副本在仍被工程或任务引用时不能被缓存清理。
- [ ] 新媒体导入失败／取消时保留旧工程和旧媒体；异步返回通过媒体代际校验，不能把 A 视频的元数据和波形挂到 B 视频。
- [ ] 本机接口延续现有令牌、会话和路径作用域校验；客户端提供的任意路径或 blob URL不能直接成为 FFmpeg 的文件读取入口。

**拟新增**：`maw/msw/media_service.py`、`web/msw-media.js`。
**主要修改**：`server-editor/serve.py`、`maw/msw/api.py`、`maw/msw/dialogs.py`、`maw/msw/persistence.py`、`maw/msw/recovery.py`、`maw/msw/audio_exports.py`、`web/editor.js`、`web/msw-persistence.js`。复用 `maw/media.py`，不另造视频格式识别系统。

**验收**：不经过 Launcher，从空白编辑器导入真实视频后可保存重开，且后端能提取该视频指定音轨的一小段音频；取消、换媒体、只读源目录、大文件和原生播放不兼容均有明确结果。

### P3：导入后后台生成波形（规模：中）

**主要修改**：`maw/waveform.py`（仅补必要通用参数）、`maw/msw/api.py`、`server-editor/serve.py`、`web/waveform.js`、`web/msw-media.js`。

## 5. 建议的执行批次与文件边界

| 批次 | 阶段 | 可单独验收的成果 |
| --- | --- | --- |
| 第一批 | P0 + P1 | 允许清空全部字幕／贴片；没有真实波形也有可用时间轴和纯 TTS 入口 |
| 第二批 | P2 + P3 | 直接导入视频、前后端媒体一致、后台生成波形，不再要求 Launcher 预处理 |
| 第三批 | P4 + P5 + P6 | Ctrl+Shift 范围选择、整段／局部 ASR、结果应用和撤销 |
| 第四批 | P7 | 完整独立入口、回归、打包兼容和文档 |

P4 的部分纯几何工作可以早于 P3，但整体按上表顺序执行，避免同一时间大幅修改 `editor.js` 和 `waveform.js`。新入口的方案在 P0 就确定，P7 负责完整发行包验收。

为长期吸收上游更新，建议：

- MSW 专有媒体登记、任务、选区和 ASR 应用尽量落在 `maw/msw/` 与 `web/msw-*.js`。
- 对 `editor.js`／`waveform.js` 做少量明确接口接线；时间轴不依赖峰值这一处确实需要触及底层，单独形成可审阅的改动，不用伪造缓存长期绕过。
- 共用 ASR／FFmpeg 代码保留现有默认行为，通过可选参数扩展。避免复制 `generate_subtitle_*` 或从 Launcher 复制一整份服务商表单。
- `main` 继续作为上游镜像；实际开发以 `my-feature` 为基线。大型改动可临时从它切出功能分支，阶段合回 `my-feature`，不向 `main` 写入 MSW 功能。
- 本轮不顺带升级上游。未来把“同步上游”和“编辑器独立工作流”分开验证；若只接收某个发行版，固定该版本引用，不直接把超前的 `main` 全合进来。
- 此次方案不包含提交、推送、发布或向上游提 PR；执行功能阶段不自动扩大为这些操作。
