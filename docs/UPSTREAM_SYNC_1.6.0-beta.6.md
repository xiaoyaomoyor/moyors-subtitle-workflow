## 5. 需要修改／新增的内容

### 5.1 工程兼容与 ASS 名称局部着色

主要文件：`maw/project_preview.py`、`web/editor-utils.js`、`web/editor.js`、模板／i18n、`JSON_SCHEMA.md`；MSW 独立链路涉及 `maw/msw/subtitle_style.py`、`maw/msw/subtitle_export.py`、`web/msw-subtitle-style.js`、`web/msw-audio-export.js`，按实际快照接口调整。

- 将 `preview.subtitle.ass_color_style` 的合法值扩为 `text`／`speaker`／`stroke`／`none`；后端校验、规范化、加载保存、自动备份、另存、便携 HTML 和压制快照保持一致。保留旧 CSS `shadow` 兼容，与 ASS 枚举区分。
- `speaker` 只着色由颜色映射实际生成的说话人名称及分隔符，正文恢复有效 ASS 基础色。不能用冒号正则切正文猜名称，避免原文自带冒号或名称误染色。未开名称、无颜色、空名称时正文不着色。
- 主轨与启用的叠加轨均使用本轨颜色组解析；副轨保持既有独立样式和名称规则，不能错误引用主轨索引。自定义调色板、分隔符、花括号／反斜杠、换行及动画标签需正确转义和恢复颜色。
- 保留 MSW 的名称相关导出选项、设置搜索和主题；提示链接定位到 MSW 实际控件，不复制上游不存在的控件 ID。名称只用于显示／导出，不能写回 `segments[*].text`，也不影响 ASR／翻译候选和 TTS 发音文本。
- Python `library_ass()` 目前直接写正文，不能只改前端 ASS 文件导出就宣称 MP4 同步支持。显式新方案需从冻结的导出任务接收名称开关、映射和分隔符；主／叠加名称局部着色与 libass 帧预览／MP4 一致。后台不读取正在变化的浏览器偏好或共享样式库。
- 旧 `preview.burn_subtitles` 不自动切换；用户仅打开 ASS 预览也不自动开启 `preview.ass_library_exports`。不同机器缺样式库时沿用已有回退，不宣称像素级完全一致。
- D2 若采纳保护已有选择，需要能区分“默认值”与“用户显式选择”。在现有设置规范化及持久化处记录，不用读取旧工程时全局改偏好。已有明确 `false` 必须有效；设置联动与撤销的实际作用范围需有测试。

### 5.2 拆分并保留原文

主要文件：`web/editor.js` 的 `buildSplitPair()` 与四类提交入口，模板／i18n；复核 MSW 素材来源检查、结果应用冲突校验和历史记录。

- 拆分面板增加独立按钮，普通“拆分”、Enter／B、自动提交继续保持原行为，避免默认把全文复制两次。
- 主轨、副轨、叠加轨、绑定主副字幕均覆盖。即使只有一个字或一个不可按空格分开的单词，也应能在时间允许时打开面板并用新操作；普通拆分仍要求合法文本断点。
- 两侧保留相同文本，使用既有合法时间切点和帧模式约束，保留最小时长保护；清除不再匹配全文的 `items`。普通拆分的词间静音与强制切点行为不得被这项改动替换。
- 为新段分配不冲突的稳定 ID；修正颜色／表情包组的 `headIdx`，保留禁用状态、说话人和可继承扩展字段。联动拆分必须重新建立有效的同轨绑定，无法合法切开时给出明确提示／沿用已批准的主轨降级规则。
- 按 D3 处理已有 TTS 贴片及素材来源。不要因为文本相同就把一个音频文件复制到两个片段，或把本来由旧段生成的音频宣称已对应新段。一次撤销恢复字幕、绑定和相关来源状态。
- 保留近期结果候选的“应用后目标变化”检测：拆分后重用旧 ASR／翻译候选仍应提示冲突，不得按旧 ID 静默覆盖。ASR 区外片段无可靠字词时间时的 `review_required` 规则保持；用户主动保留全文的手工操作不伪装成准确字词拆分。

### 5.3 点击暂停与中缝回归

主要文件：`web/editor.js`、`web/editor-utils.js`、`web/waveform.js`、模板／i18n；按需扩展 `web/msw-audio-transport.js`、`web/msw-audio.js`。

- 新偏好 `pauseOnMouseClick` 默认 `false`，加入现有 MSW 设置与搜索，读取旧配置不改变播放体验。
- 仅在播放中、由普通鼠标点击导致 seek 时执行暂停；只选择、多选、Ctrl+Shift 范围、边界拖动、键盘跳转、内部去空隙跳转不得误触发。原先暂停且设置“点击自动播放”的情况仍可开始播放。
- 覆盖列表主／副／叠加字幕、波形字幕、空白与空隙。先记下点击前播放状态，seek 后暂停，避免后续自动播放分支立即恢复。
- MSW `seekFromWaveform()` 会被配音虚拟时钟提前接管；暂停必须停止虚拟播放和已调度音频，并覆盖 JKL 倒放。播放器替换后使用新实例，保留近期源增益修复。
- `transport.seek()` 从虚拟播放返回真实媒体时可能安排微任务 `player.play()`；媒体未就绪时还会排队 `pendingMediaSeek`。要传递本次鼠标暂停意图并取消迟到恢复，不能出现“刚暂停又自动播放”。
- 中缝不增加上游独立 DOM／CSS；在主副同屏、叠加与三层音频同屏、单／多行波形、不同缩放及换行边界测试实际指针命中。只联动同轨精确相接的两段，Alt 单侧、撤销、最小时长、帧模式保持。发现真实回归再修复现有实现。

### 5.4 文稿匹配的两个修复

主要文件：`maw/postprocess_match.py`、`scripts/mosp_match_text.py`，相关后端测试与 MSW 派生工程／素材保真测试。

- 合并明确闭合符号集合及断句后连续闭合符号的保留逻辑，覆盖 `？」`、`？”`、`？》`、全角括号和嵌套结束符。不把对称 ASCII 引号一概视为右侧符号，避免破坏引号开头和英文撇号。
- 有字词时间码：利用对齐报告识别整段均为 ASR 多录内容的来源段，按原时间回插；原段 ID、元数据、items 保留。合并禁用段后仍满足排序、非重叠及正时长约束。
- 无字词时间码：在文稿边界区分前一句结束和后一句起点，保留边界处多录的完整段或可明确分离的片段；只在确实切片时分配新 ID、清除不可信 items。
- 上游实现有边界：位于同一句文稿内部且与该句时间重叠的额外文字，不能无歧义作为独立非重叠字幕保留。不可宣传“所有多录内容绝不丢失”；保留原始快照和告警，测试同句插话／重复文稿／低匹配／首尾额外段／零时长等情况。
- 重分段可能更换主字幕 ID；MSW 多副轨、叠加轨、音频文件、贴片位置及候选／应用记录不能丢。解除无法保持的旧绑定并明确来源待复核，不伪造一一对应关系。要检验保留段与新建段 ID 不撞号、颜色引用不悬空。
- 沿用现有 Launcher／CLI 匹配入口，不借此次修复新增一套编辑器文稿处理系统。编辑器现有 ASR／翻译候选显式应用机制保持。
