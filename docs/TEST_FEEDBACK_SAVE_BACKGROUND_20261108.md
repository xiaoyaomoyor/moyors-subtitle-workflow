## 实施与验证记录

- 版本接口在短互斥区内验证绑定、磁盘版本、工程归属和媒体，随后写入已捕获的独立快照。期间保存或切换工程不改变该快照的来源。素材校验、原子发布、跨服务 SQLite 去重及保留上限保持不变。
- 无变化保存不接受客户端哈希作为内容：仅确认服务器已有的验证快照，重新核对绑定与实际磁盘字节。快照不可复用时要求完整上传，音频素材继续走完整校验。新接口通过响应能力字段启用，旧服务仍走原保存路径。
- 字幕指纹保留精确内容比较，避免用遗漏变更的版本号代替保存正确性；重复比较不再生成包含所有词时间码的大字符串。保存请求直接嵌入已编码 JSON，避免一次完整解析及重复编码。播放头改变复用已规范化的字幕，保留其他 editor_state 字段。
- 页面初始化不再仅为草稿定时器构建完整工程。后台依据编辑版本和输入／内容变更事件判断是否需检查；显式保存／草稿仍精确比较。自动保存在输入结束后约 1.6 秒执行，定时保存也避开活跃输入；静默保存与后台保存分别处理，显式调用不因隐藏提示而被跳过。
- 首轮浏览器 8 项通过，包含万条字幕无变化保存小请求、只移动播放头免重复规范化、保存中继续编辑、外部磁盘冲突、草稿并发与空闲扫描、元数据保存和重开。随后检查补齐了手动版本按钮不受点击防抖拦截、草稿记录规范化后的版本，以及静默／后台保存的区别，需以最终追加套件为准。

## 专项测量中的追加调整

- 第一轮万条专项已测到无变化保存和空闲活动改善，但完整保存反馈仍偏慢。请求统计发现直接嵌入带缩进 JSON 令普通场景上传约从 7.9 MB 增至 15.9 MB；需要在持久化入口直接产生紧凑 JSON，避免为了省一次编码反而增加上传和解析成本。保留此次原始报告，不把它作为追加调整后源码的最终结果。
- 新增备份期间切换工程的隔离回归，检查捕获的版本保留原工程身份和目录，新工程的数据与备份目录不被触碰；最终 Python 四套合计 106 项通过（44.4 秒）。最终前端 801 项通过，语法检查通过，`edit.py --blank` 已重新生成产物。
- 已在 `buildSavedProjectJson` 使用紧凑输出，普通 `buildJson` 导出仍保留缩进；避免先生成大文本后再解析压缩。相同四个浏览器套件在此修改后再次运行，最终 27 项通过（5 分钟），新增紧凑格式断言通过。
- 测量后审查补充了不提供指纹的旧宿主回退：必须完整上传，并用相同紧凑格式比较；没有指纹不能进入无变化确认。四个标准保存场景再次通过。兼容测试起初尝试改写冻结注册表，没有真正切换宿主；改为页面内注入旧接口并明确断言缺少指纹后，单项实际复测通过（28.7 秒）。合计覆盖 28 个独立浏览器场景，不累加重复执行次数。便携产物已再次生成。

两侧均使用同一当前后端，不冒充历史后端的完整对照。两小时 640×360、2 fps 合成视频，每个工程 10,000 条；各操作预热一次、正式三次，最终对照共 72 个正式样本，全部成功。所有场景无页面错误，原始夹具摘要未变；保存重开后字幕模型、绑定、说话人、音频贴片和播放头一致。前端源码测量前后摘要一致。

- 加载记录用于观察；初始字体等存在缓存波动且只采样一次，没有据此宣称整体启动加速百分比。加载优化的正确性由服务器、媒体缓存及保存重开测试覆盖。
