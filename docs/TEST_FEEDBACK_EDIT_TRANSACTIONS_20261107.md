# 第二阶段：统一编辑事务与数据索引

目标：以第一阶段的固定夹具和性能脚本为基线，减少编辑过程中的重复全量工作；提交、失败回滚和撤销必须保持字幕、绑定、标记及选择一致。

| 项目 | 状态 | 范围与验收 |
| --- | --- | --- |
| 共享数据索引 | 已修复 | 提供字幕身份、轨道归属、绑定与标记引用索引，接入拖动、外观与锁定检查；锁定检查不再逐条扫描所有绑定；提交/撤销/重做/切换工程使缓存失效，拖动期间复用同一索引 |
| 编辑事务与历史 | 已修复 | 合并提交、校验和检查点更新；结构编辑使用差量历史；失败与无变化操作不产生撤销项 |
| 操作接通 | 已修复 | 剪切粘贴、切分合并、移动缩放、文字和外观共用检查点规则；保留旧入口的安全回退 |
| 回归与性能复测 | 已修复 | 三类 10,000 条矩阵完整通过；失败选区回滚复验通过，性能回退指标与既有失败如实保留 |
| 产物与文档 | 已修复 | 已更新生成页面、变更记录与性能摘要；实测源码和收尾回滚修正分别记录 |

## 事实基线

- 起点：`70d783ed`，第一阶段报告见 `docs/PERFORMANCE_BASELINE.md` 和 `docs/performance/BASELINE_20261107.json`。
- 现有普通编辑在 `pushUndo → fixedBeginEdit → fixedAcceptEdit` 中重复复制/序列化全部字幕；部分已验证事务仍再次走相同检查。
- `assertLocks` 对每条锁定字幕过滤两份完整绑定列表，存在随字幕和绑定数量乘积增长的开销。
- 已有文字、外观、移动及插入的轻量历史需要保留，并统一检查点规则；旧输入和少用操作仍须经过完整校验。
- 本阶段不提前改造第三阶段的列表渲染或后续预览、保存体系，避免无法区分性能收益来源。

## 验证记录

用户工程和第一阶段原始报告保持不变；测试仅使用隔离夹具。

- 已新增共享索引与差量事务模块，接通结构编辑历史；文字、标记、外观、移动、粘贴统一检查点更新，移除这些更新中的全量 JSON 指纹。
- 新建/切分/合并仍先完整校验；成功后将待定历史收敛为一条差量记录，无变化和失败恢复原历史栈。
- 回归中发现规范化发生在提交之后，会造成差量撤销冲突：已把操作视图默认值及切分的帧时间同步放到差量封存之前。未以放松冲突校验解决。
- 第一轮单元测试：`test_edit_transaction.mjs`、`test_subtitle_tracks.mjs` 共 46 项通过。结构编辑浏览器回归进行中，正式性能复测尚未开始。

## 实现与保护边界

- `msw-edit-transaction.js` 保存变化的字段及增删/排序关系。未变字幕沿用原对象，历史值单独复制；应用前检查变更目标，出现冲突不部分写入。
- 新建、切分、合并在旧操作入口保留一次待提交记录，经过时间排序、帧时间同步、引用/重叠/绑定/锁定校验后封存为差量。剪切及纯字幕的规范工程操作直接生成差量。粘贴、时间、文字、外观、标记原有轻量历史保留，统一更新检查点，不再每次生成全文 JSON 指纹。
- 涉及素材库或其他非字幕数据的宽范围事务仍使用完整快照；旧数据输入及未明确经过验证的入口保留完整校验。没有用对象地址或不完整版本号跳过旧入口检查。
- 共享索引提供身份、来源数组、物理轨道、时间顺序、双向绑定和标记依赖。拖动只检查涉及的轨道与绑定，完整模型仍在松手时校验。锁定验证为线性索引查询，并阻止向锁定轨道插入或移入字幕。
- 事务提供变化字幕集合，复用已有的按身份刷新能力；没有提前改造列表虚拟化、ASS 生成、保存格式或后台保存机制。

- 最后调整后 797 项单元检查及 27 项相关浏览器回归通过（完整 108 项在该轮调整前通过）。正式全矩阵原始结果写入 `output/perf-transactions-20261107-final`，第一阶段原始报告及脚本未修改。
- 正式矩阵的 1,000 / 6,000 / 10,000 条场景已完成完整性检查。10,000 条的一组粘贴同步中位数从基线 668 ms 降至 352 ms，但 100 组粘贴为 2,984 ms，高于基线 1,182 ms；未改动的界面刷新函数同样明显变慢，且有恢复草稿调用混入。暂不将原因归结为环境，也不只选择诊断轮的较快结果；完成矩阵后补做原版代码对照，并保留所有回退指标。

- 审查拖动检查点时复现了本轮新比较器的边界问题：`_dirty: undefined` 与没有 `_dirty` 字段在保存数据和差量中等价，但相等检查返回不等，可能反复触发完整校验。已补回归用例；待当前旧测量结束再修正产品源码，避免同轮报告混用源码版本。之后需以新版本再做目标场景验证。

## 收尾修正与复验

- 上述可选字段比较已修正，与保存 JSON 及差量语义一致；同时补齐说话人引用变化后的依赖索引失效。798 项单元检查、27 项相关浏览器回归，以及包含两项新边界检查的 7 项事务浏览器测试通过。
- 停止 `perf-transactions-20261107-final` 旧轮次，保留已完成与失败记录，不把它作为最终源码的完整矩阵。最终测量使用 `perf-transactions-20261107-release`，覆盖普通、混合、迁移三类 10,000 条目标工程；原版 `70d783ed` 的 10,000 条对照在它之前串行运行，避免同时争用资源。
- 独立 15,000 条保存诊断：4 次改字保存、4 次播放头保存、备份完成后保存和重开通过，字幕内容、时间及绑定恢复一致。主动让版本备份与保存重叠时，保存返回 HTTP 409：`另一个工程保存操作正在进行`；备份结束后保存成功，无页面错误。
- 保存并发冲突位于本轮未修改的 `server-editor/serve.py`、`maw/msw/versions.py`、`web/msw-persistence.js` 路径：版本创建持有保存锁，前台保存最多等待 1 秒。列入第五阶段的后台保存调度；本轮不放松锁或吞掉失败。早期 15,000 条测量没有响应正文，无法确证那一次失败也由同一原因导致，仍保留原失败状态。
- 原版同期补测的编辑及保存采样完成，但 `recovery-draft` 预热在约 39 ms 内返回 `false`，无页面异常。`captureDraft` 在后台草稿忙碌时直接返回 false，而原工具的就绪条件未等待该状态；表现符合这条竞态路径。该原版轮次保留失败状态，仅使用双方各有 3 个成功样本的操作作补充对照，不称为完整通过的基线；第一阶段正式报告仍是原始完整基线。
- 最终源码的普通 10,000 条场景已完成 27 类操作采样，恢复草稿成功。剪切采样中的 `fixedContentKey` 从原版中位 5 次降至 0 次，`fixedContent` 从 3 次降至 0 次，`snapshotSegments` 从 1 次降至 0 次；这比受运行时波动影响的总耗时更直接地证明了重复全量工作的减少。完整性重开及另外两类工程仍待本轮结束统一汇总。
- 三类 10,000 条最终矩阵均完整通过。矩阵结束后的错误注入回归发现：失败结构编辑虽恢复数据和历史，但没有恢复操作前选区。已补齐失败分支的选区及编辑对象恢复；新增用例修复前失败，修复后与切分相关的 62 项浏览器测试全部通过，798 项单元测试再次通过。该修改只作用于校验失败路径；性能摘要保留实测源码摘要，并单独标注这项测量后修正，不将原数据冒充修正后的重新测量。

## 后续界面阶段的具体入口

- 联动切分调用 `markMultiSubtitleDirty()`，把整条副轨的 `_dirty` 设为真。卡片以 `dirty` 类显示此状态，因此本轮差量必须保留这些变化；当前刷新仍会重建涉及的卡片。第三阶段应区分内容变化和仅修改状态变化，用原位类名更新替代重建，不能直接忽略 `_dirty` 导致显示或保存状态不一致。
- `renderAll()` 即使复用字幕节点，仍遍历全部显示行并重新应用显示设置。下一阶段继续缩小刷新范围及 DOM 数量；本轮未把这些剩余成本描述为已解决。

## 完整矩阵结果与解释

三类 10,000 条工程（普通绑定、混合轨道、旧结构迁移）各完成 27 类操作，每项 1 次预热、3 次正式采样；原夹具不变、撤销恢复模型及说话人配置、保存重开一致性全部通过，页面错误均为空。原始数据在 `output/perf-transactions-20261107-release`，可提交摘要为 [TRANSACTIONS_20261107.json](performance/TRANSACTIONS_20261107.json)。

| 普通 10,000 条操作，同步中位数 | 第一阶段正式基线 | 本次原版同期补测 | 第二阶段 |
| --- | ---: | ---: | ---: |
| 粘贴 1 组 | 668 ms | 1,814 ms | 1,257 ms |
| 粘贴 100 组 | 1,182 ms | 3,644 ms | 3,283 ms |
| 剪切 1 组 | 2,815 ms | 6,907 ms | 2,365 ms |
| 联动切分 | 2,115 ms | 6,263 ms | 5,328 ms |
| 合并 | 2,163 ms | 6,775 ms | 2,978 ms |

这些数字不能解释为所有操作均已提速：与第一阶段正式基线相比，普通、混合、迁移场景分别有 66、68、8 个指标触发回退提示（包括同一操作的不同指标，非操作数量）。原版同期也明显变慢，说明时间上存在波动；未采集完整系统负载、电源或温度信息，不能确证其原因。同期原版草稿操作失败，因此该列只比较双方各有 3 次成功的操作，不能替代完整基线。全部回退提示保存在摘要中。

更明确的阶段收益：

- 剪切 1 组不再调用全量 `fixedContentKey`（原中位 5 次）、`fixedContent`（3 次）和 `snapshotSegments`（1 次）。
- 10,000 条、半数字幕轨道锁定的独立模型检查中位数由 782 ms 降至 121 ms；无锁检查保持不变。该探针使用同一输入作前后模型，另有不同对象副本及真实改动的正确性测试。
- 普通工程强制回收后的 JavaScript 堆：加载约 174 → 157 MiB，操作后约 204 → 181 MiB。DOM 数量仍约 15.3 万，尚未改造虚拟列表；不是整个进程内存指标。
- 迁移工程的粘贴、剪切、切分、合并同步中位数均低于第一阶段；仍不能据此宣称所有用户工程流畅。

剩余工作：第三阶段缩小列表/波形刷新与 DOM 范围；预览阶段处理 ASS 更新等待；保存阶段处理版本备份互斥及后台任务调度。旧波形套件的 8 项失败及基线草稿忙碌竞态继续保留为专项核查项，没有计入本阶段已解决问题。
