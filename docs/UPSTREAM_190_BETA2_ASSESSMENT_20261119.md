## A. 建议优先实施的两组修复

### A1. 工程媒体关联与保存路径

值得吸收，且 MSW 已确认实际缺口。应检查重新关联后保存、重新打开和下载副本的整条路径，不能只修一个表达式。

当前证据：

1. `maw/media.py:469` 的 `_path_from_value` 在显式相对路径分支返回工作目录，遗漏文件名。在媒体所在目录传入 `-m clip.wav`，实际解析成目录并报告缺失；隔离诊断已复现。
2. `maw/project_io.py:186` 的 `write_mosp` 使用 `media_path` 补元数据，但不重写 `media`。合成工程存入 `_msw/clip.mosp`，即使传入准确媒体路径，仍保存 `clip.wav`，重开无法找到父目录媒体；已复现。这不代表所有识别输出失败，当前多个生成入口已写绝对路径。
3. `resolve_project_media` 只有工程同目录的有限匹配，未覆盖旧 `_msw` / `_maw` 子目录的上述情形。
4. Launcher `start_server` 在同一工程已打开时直接复用会话（`maw/gui_web.py:2289`），没有比较本次显式选择的媒体是否不同；这是静态确认的分支缺口。
5. Launcher 没有 `rememberMedia` / `--remember-media` 通路，显式选择主要用于本次启动。之后编辑器保存可以落盘，但不等于重新关联成功即记住。
6. 服务器失联下载和“仅下载工程”直接序列化当前引用（`web/editor.js:18399`、`:24226`）。原引用为相对路径且下载目录改变时，原基准可能丢失；本轮为静态结论，未模拟文件选择器切换下载目录。

建议实现边界：

- 明确路径基准：显式相对路径基于工作目录，工程引用基于源工程目录；已知保存目标时按目标目录计算，同盘优先相对路径、跨盘保留绝对路径。
- 对旧 `_msw` / `_maw` 工程只检查受支持输出目录上一层的明确文件名，不向任意祖先扫描或猜测媒体。
- 提供默认开启的“记住此媒体关联”，允许“仅本次使用”。加载成功后仅更新关联，复用 MSW 原子写入、备份及并发保护，不顺带写入加载缓存、迁移状态或未提交正文。
- 同工程但不同媒体走 MSW 现有冲突处理或安全重关联流程，避免返回成功却仍播放旧媒体，不影响其他会话。
- 下载兜底仅在工程和媒体身份匹配时使用可信原始媒体路径；浏览器替换的媒体没有原生路径时不能使用旧工程路径。依托 MSW 的媒体登记和恢复信息，不复制上游全局变量方案。
- 区分原媒体与浏览器转码缓存，持久化正确的源身份。

已有能力必须保留：`maw/msw/persistence.py:190` 的另存为／恢复已有媒体收集、源目录锚定及绝对路径保护；`maw/msw/recovery.py` 单独记录来源和媒体；`maw/postprocess_io.py:201` 的 `write_derived_project` 已锚定相对媒体并保留音频资产。不能称为所有另存为、恢复或派生工程都损坏，也不能将 v4、资产和多会话系统替换成上游实现。

来源：[媒体关联与记忆](https://github.com/Moyf/moys-asr-workflow/commit/fbe76fe3)、[生成链接与恢复下载](https://github.com/Moyf/moys-asr-workflow/commit/99ff4573)。其中已退役便携 HTML 的媒体 URL 修复不列入本轮。

### A2. 剩余后台媒体调用隐藏命令行窗口

建议补齐，但只修改 MSW 尚未覆盖的调用：

| 调用 | 当前位置 | 实施边界 |
| --- | --- | --- |
| 媒体时长探测 | `maw/ffmpeg.py:316` | 复用跨平台进程参数。 |
| 帧率／尺寸、音轨探测、浏览器转码 | `maw/media.py:150`、`:227`、`:436` | 保留超时、错误反馈和转码回退。 |
| quapeaks 流式解码 | `maw/quapeaks.py:1056` | 保留流式处理及错误输出读取。 |
| 本地 Qwen 音频切片 | `maw/local_asr.py:878` | 补隐藏窗口，不增加识别／运行时系统。 |

基础波形 `maw/waveform.py:313` 和时间对齐 `maw/timestamp_alignment.py:684` 已通过 `process_group_kwargs()` 间接设置隐藏窗口。仅搜索 `creationflags` 会漏掉它们。MSW 导出、进程树终止与取消机制继续沿用，不改回上游简单同步调用。

`MSW.spec:168` 已将 `project_io.py` 放入 `local-runtime`；`ocr-runtime` 当前没有该文件，但 MSW 的 OCR → `postprocess_io` 路径不依赖它，不能将“本地识别已包含”误当成“OCR 已包含”。上游的补丁针对其自己的项目 I/O 依赖。本轮不机械补文件；实施 A1 时若把媒体引用处理放进 `project_io` 并让 OCR 调用，必须同时补 OCR 源码及依赖检查。也不为对齐上游调用名单而引入视频画面带或恢复便携 HTML。

证据边界：实际调用参数及共享帮助函数已核对；本轮没有重建 Windows 包观察闪窗，结论是缺少防闪窗设置，而非每个调用都已实测弹窗。

来源：[隐藏后台媒体窗口](https://github.com/Moyf/moys-asr-workflow/commit/19ce4164)、[OCR 运行时依赖补全](https://github.com/Moyf/moys-asr-workflow/commit/8838de35)。

## B. 建议随后吸收的一项性能优化

### B1. 单行波形滚动复用画布

MSW 已有多行虚拟化、滚轮事件合并和画布尺寸缓存，但 `web/waveform.js:4657` 的 `renderBasic` 仍执行 `replaceChildren`，重建行与 Canvas。在真实本机编辑器中推进合成工程的单行视窗再执行刷新，两者均未复用；确认了实现差异，本轮未测 FPS 或耗时，不承诺提升比例。

建议保留单行画布和基础事件节点，只更新视窗、字幕覆盖层及标记，并合并尺寸读取。必须适配 MSW 字幕轨道头、配音层、顶部复核标记、选中虚线、悬停预览和拖动取消，不能照搬上游选择器删除覆盖层。本项不包含 Q 字词模式、字词编辑轨道或视频画面带。

来源：[波形滚动优化](https://github.com/Moyf/moys-asr-workflow/commit/1dbda3ff)。
