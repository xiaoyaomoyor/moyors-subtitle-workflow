## 建议纳入的内容

### 1. 优先修复：波形指针与实际时间边界统一坐标

上游提交 [`c7ca4a9c`](https://github.com/Moyf/moys-asr-workflow/commit/c7ca4a9c) 将指针时间映射改为排除行边框的坐标。当前 MSW 的 `web/waveform.css` 给 `.waveform-row` 设置 1px 边框，但 `web/waveform.js` 的 `captureRowGeometry()`、`timeFromPointer()`、`timeFromPointerUnbounded()` 和时间转指针位置仍使用包含边框的矩形。波形画布和字幕覆盖层使用的可用宽度与此不同。

v1.6.1 已让拖动指示线跟随实际生效字幕边界，但没有修复指针到时间这一层的计算；两项工作有关联，却不是重复修复。

只读诊断提取当前 MSW 和固定上游版本的实际方法，在相同合成行上运行。行左侧位置为 100px，左右边框各 1px，可用宽度 1,000px，起始时间 0ms：

| 每行时长 | 指针位于内容左端时，MSW 计算结果 | 指针位于内容右端时，MSW 计算结果 | 上游修复结果 |
| --- | --- | --- | --- |
| 10 秒 | 9.980ms | 9,990.020ms | 0ms / 10,000ms |
| 60 秒 | 59.880ms | 59,940.120ms | 0ms / 60,000ms |

缓存几何和即时计算都复现此差异；中点相同，越靠近两端偏差越明显。越界拖动的时间比例也不同。这里是计算层证据，不将其冒充完整浏览器拖动验收；实际界面还会受到吸附与帧取整影响。

适配时统一正反向坐标、拖动缓存和测试指针定位，保留 MSW 平级轨道、绑定字幕、跨行拖动、间隙及音频贴片系统。后续检查普通／多行波形、轨道头宽度、浏览器缩放、帧／毫秒时基、跨行及吸附后的反馈，不能整份替换上游 `waveform.js`。

### 2. 主要功能：适配 MSW 的识别预设库

上游 [`87f6db5c`](https://github.com/Moyf/moys-asr-workflow/commit/87f6db5c) 新增带名称和描述的 ASR 参数库，支持搜索、预览、加载、另存、更新、复制和删除。这适合重复处理同类视频，例如同一节目持续复用角色名、专有名词、背景说明和断句参数。

MSW 现状：

- `web/launcher/launcher.js` 的 `saveSegmentation()` 已记忆断句参数。
- `maw/msw/asr_config.py` 的 `catalog()` / 参数保存逻辑已保留编辑器上次 ASR 选项，且与启动器复用供应商目录和凭据。
- [配置管理](CONFIGURATION_MANAGEMENT.md) 已支持两端共享的 `.mswconfig` 分类导入、变更预览及冲突检查，也已有字幕样式、说话人和部分配音命名预设。
- 上述能力不等于可在多个识别场景间切换的 ASR 命名预设库；也没有理由再建立一套独立于 MSW 的配置迁移系统。

建议首版范围：

1. 启动器和编辑器内 ASR 共用同一预设库，复用当前本机配置存储和界面规范；纳入 `.mswconfig` 的可选分类导入／导出。
2. 管理入口提供搜索、名称／描述、参数摘要、加载、另存、更新、复制、重命名和可恢复删除。选中列表项只预览，明确加载后才改表单；加载不自动执行识别，不默认切换供应商或模型。
3. 保存语言、断句、背景文本、热词和适用的非敏感识别选项；按模型能力应用。不保存 API Key、账号业务空间、服务地址、媒体／输出路径、机器专属模型或热词文件路径；外部资源按 MSW 现有规则在本机重新关联。
4. 清楚区分“修改当前参数”和“更新已保存预设”，避免在编辑普通表单时静默覆盖预设。另存和复制后可直接改名；未保存变化应可见。
5. 加载时对不支持的参数给出简短说明，保留各供应商热词结构、语言限制、OpenAI 时间戳／说话人能力判断及 Qwen 3.1 方言选项。参数必须进入任务提交快照，不改变已经启动的任务。

不直接搬入上游 `maw/asr_presets.py` 和 Launcher 弹窗：上游是单独目录内的一组 JSON 文件，字段命名与 MSW 已有差异，例如 `qwenAudioKeepDialect` 与 `qwenKeepDialect`，还包含 MSW 配置包不应搬运的热词文件路径。其文件校验、原子写入、损坏项提示和同名冲突处理值得借鉴。首版不必添加库目录迁移和自动扫描 MAW 历史目录；单独文件交换或 MAW 预设兼容可后续按实际需要增加。

### 3. 随预设库一起做：共享背景提示词，保留专用内容

当前 MSW 的 Qwen `qwenAudioContext`、OpenAI `openaiPrompt` 和 Soniox `sonioxContextText` 各自保存。上游将三个输入实时同步为 `promptContext`，旧值则去重后拼接。这能减少重复输入，但 MSW 已有的不同供应商文本不一定相同，也不一定适合直接拼接。

建议采用“通用背景文本 + 可选供应商专用覆盖”：

- 普通使用只编辑一份通用背景文本，切换兼容供应商时复用；高级项允许保留专用内容。
- 不自动合并或覆盖旧的不同文本；一致的旧值可迁为通用值，不同值保留为对应供应商覆盖。
- Qwen 热词、OpenAI Keywords、Soniox General / Terms / Translation Terms 继续独立，不把结构化信息当作普通提示词同步。
- 不支持提示词的模型不发送该字段；长度、语言、说话人模式等约束沿用各供应商能力检查。

这与预设库属于同一组功能，适合一起实施和回归，不建议先给三个输入框加无条件双向同步。

### 4. 小范围维护：FFmpeg 路径与跨平台测试隔离

上游 [`0663def2`](https://github.com/Moyf/moys-asr-workflow/commit/0663def2) 虽然标题是 macOS 单元测试修复，也修改了生产代码：

- `maw/gui_workflow.py::_prepend_ffmpeg_path()` 把已存在的选定目录移到最前并去重。当前 MSW 每次直接前置；处理同目录的 ffmpeg / ffprobe 时仍会反复插入。
- `maw/gui_web.py::_check_ffmpeg()` 显式传递同一份 macOS 候选目录，避免检测搜索路径和工具解析器使用不同来源，便于隔离真实 Homebrew 环境。
- 测试用临时目录代替真实 Homebrew 候选；真实 ASS 滤镜测试先检查 FFmpeg 是否包含 `subtitles` 滤镜。

只读 AST 诊断执行两个版本的实际 `_child_environment()` 和 `_prepend_ffmpeg_path()`，其余依赖使用合成工具路径和空配置。初始 PATH 为“其他目录、选定目录、选定目录”，ffmpeg / ffprobe 位于同一选定目录：当前 MSW 最终出现 **4 次**，上游为 **1 次**；两者都已把选定目录放在最前。因此确认的是重复与一致性维护，不能夸大为当前总会选错 FFmpeg。

建议跟进上述小改动及针对性测试。当前 MSW v1.6.1 的三平台发行回归已经通过，见[发行记录](TEST_FEEDBACK_RELEASE_161_20261114.md)；这不是“macOS 版本不可用”的证据。开发机缺少 libass 时可以明确跳过相关环境测试，但正式标准包依然必须验证字幕烧录能力，不能靠跳过掩盖随包依赖缺失。

上游另修正 `scripts/verify_sha256.sh` 在 C locale 下的变量边界；MSW 当前没有该脚本，并有自己的发行校验流程，故不新增此脚本。
